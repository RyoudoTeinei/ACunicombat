# 开发日志写入接口

本目录是“太空机甲战斗开发资料库”的唯一日志数据源。任何人或 AI 在新增、移动、重命名或修改日志前，先遵守本文件约定。

## 自动发现规则

- 日志根目录：`E:\UnityDev\ACunicombat\太空机甲战斗开发日志`
- 网页地址：`http://127.0.0.1:5187/`
- 网页递归发现根目录下所有扩展名为 `.md` 的文件。
- 不需要维护数据库、清单或网页代码。
- 文件写入后，已打开的网页会在 3 秒内自动更新目录树。
- 以 `.` 开头的目录属于内部目录，不会显示。
- `.csv`、`.json` 和图片不会作为日志条目显示；图片可以由 Markdown 引用。

## 文件格式

1. 使用 UTF-8 编码。
2. 文件扩展名必须是 `.md`。
3. 第一处一级标题作为网页显示标题，推荐放在第一行：`# 文档标题`。
4. 文件名应简短明确，使用中文或 ASCII；禁止 Windows 非法字符：`< > : " / \\ | ? *`。
5. 内容使用标准 Markdown：标题、列表、表格、代码块、引用和图片。
6. 图片优先使用相对于当前 Markdown 文件的路径，例如 `![雷达界面](./图片/雷达界面.png)`。

最小模板：

```markdown
# 文档标题

## 目的

说明这份文档解决什么问题。

## 当前结论

- 结论一
- 结论二

## 待确认

- [ ] 尚未解决的问题
```

## 目录归属

| 目录 | 内容 |
| --- | --- |
| `01_待开发事项/` | 尚未实现的功能、问题和优先级 |
| `02_已开发内容/` | 已完成实现、验证结果和变更记录 |
| `03_设计文档/` | 玩法、系统、数值、交互和世界观设计 |
| `04_研究与参考/` | 外部资料、技术研究和数据来源 |
| `05_决策记录/` | 已确定的方向、理由和取舍 |
| `06_测试与试玩记录/` | 测试步骤、试玩反馈、问题复现和平衡结果 |

无法确定归属时，先写入最接近的现有目录，不要随意增加顶层编号目录。

## 安全写入

- 新建文档时，先写完整内容，再以 `.md` 文件名落盘。
- 程序批量生成时，先写同目录临时文件，完成后原子重命名为 `.md`，避免网页读到半份内容。
- 不要覆盖名称包含“抓取原始备份”的文件。
- `AC6零件AI可读资料.md` 由零件编辑器生成，不要直接修改。
- 修改现有设计前先读取原文，保留仍然有效的结论，不要用空模板覆盖。

## HTTP 接口

也可以通过本地网页服务写入：

### 新建文档

`POST /api/logs/document`

```json
{
  "path": "03_设计文档/雷达信号传播设计.md",
  "content": "# 雷达信号传播设计\n\n正文"
}
```

### 更新文档

`PUT /api/logs/{经过 URL 编码的相对路径}`

```json
{
  "content": "# 更新后的完整文档\n\n正文"
}
```

### 新建目录

`POST /api/logs/folder`

```json
{
  "path": "06_测试与试玩记录/雷达测试"
}
```

### 移动或重命名

`POST /api/logs/move`

```json
{
  "sourcePath": "03_设计文档/旧名称.md",
  "targetPath": "03_设计文档/新名称.md"
}
```

所有路径都必须相对于日志根目录，禁止使用 `..` 逃离目录。
