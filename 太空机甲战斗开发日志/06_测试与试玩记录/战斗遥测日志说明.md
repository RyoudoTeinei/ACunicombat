# 战斗遥测日志

## 目的

战斗遥测用于复现雷达鬼影、敌我识别错误、导弹意图误判、光电关联错误、激光测距拒绝和数据链异常。它和 Unity Console 不同：每条记录都是独立 JSON，带统一序号、UTC 时间、仿真时间、来源机体、系统和事件类型。

## 位置

- Unity 编辑器：`Logs/CombatTelemetry/combat_时间_场景.jsonl`
- 构建版：`Application.persistentDataPath/CombatTelemetry`
- 单文件默认上限：256 MB，超过后自动生成 `_part001` 等续卷。

同一次 Play 中的多个 `SimulationDriver` 共用一个文件，通过 `source` 区分玩家、AI 和导弹传感器来源。停止 Play 后文件会刷新并关闭。

## 默认记录范围

- 会话：Unity 版本、产品版本、场景、平台、Git 提交。
- 雷达配置：能力、距离、波形、功率、检测门限、波束、量测精度和分辨率。
- 雷达执行：全部驻留调度、发射事件和检测量测。
- 航迹管理：常规关联、机动关联、新建航迹、容量拒绝、生命周期变化和释放原因。
- 航迹状态：默认每 0.2 秒记录位置、速度、完整 6x6 协方差、置信度、分类和生命周期。
- 光电：接收机配置和全部方位观测。
- 激光：配置、脉冲、回波、NIS 和是否成功注入航迹。
- ESM/MAW：接收机配置、全部接触和相关后的威胁状态。
- 数据链：终端配置、排队报文、收到的报文和链路辐射。
- 导弹融合：敌我属性、火控质量、来袭状态、任务角色、目标意图、CPA 和估计运动学。
- 其他系统：现有 Unity 日志会同步写入 `application/log` 事件。

连续航迹状态限制为 5 Hz，但量测、关联和状态转换等离散事件不采样、不省略。

## 雷达鬼影关键字段

关注 `system=radar_tracking`：

- `event=TrackAllocated`：没有任何现有航迹通过关联门限，因此新建了 TrackId。
- `event=AssociationAccepted`：常规门限关联成功。
- `event=ManeuverAssociationAccepted`：常规门限失败，但机动补偿门限关联成功。
- `normalizedDistanceSquared` 与 `gateSquared`：前者大于后者即被门限拒绝。
- `staleRejected`、`classRejected`、`gateRejected`：各类候选拒绝数量。
- `measurementPosition` 与 `trackPosition`：判断是否是同一目标被拆轨。
- `LifecycleChanged`、`TrackReleased`：旧鬼影滑行和消失过程。

## 快速摘要

在项目根目录运行：

```powershell
.\Tools\SummarizeCombatTelemetry.ps1
```

脚本默认读取最新日志，输出事件计数、疑似一秒内重复建轨和最新导弹意图。也可以指定文件：

```powershell
.\Tools\SummarizeCombatTelemetry.ps1 -Path .\Logs\CombatTelemetry\combat_xxx.jsonl
```

## 开关

`SimulationDriver` Inspector 中提供：

- `Enable Combat Telemetry`：总开关，默认开启。
- `Telemetry Track Snapshot Interval Seconds`：连续航迹快照间隔，默认 0.2 秒。
- `Telemetry Maximum File Size Megabytes`：单卷大小，默认 256 MB。

记录器写入失败时会停止记录，不会让传感器或航迹算法抛错或改变仿真结果。
