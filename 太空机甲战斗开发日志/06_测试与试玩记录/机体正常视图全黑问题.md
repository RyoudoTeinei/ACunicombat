# 机体正常视图全黑问题

## 状态

- **已定位（2026-07-25，另一台机器诊断）：问题不在项目资产/材质/Shader，
  在复现环境的 Unity 版本与项目不一致。见文末"诊断结论"。**
- 发生于普通可见光视图，热成像状态为 `OFF`。
- 玩家机体与使用同类零件生成的靶机都会接近纯黑。
- 平台、标杆、天空盒和阴影仍能正常显示。

## 复现环境

- Unity：`6000.0.52f1`
- 渲染管线：URP
- 场景：`AC6PlayerControl`
- 进入播放模式后即可观察到。

## 现象

- 机体仅有推进器等少量自发光区域可见。
- 机体仍会在地面投射清晰阴影，说明主方向光存在并参与渲染。
- 地面能够响应主光和补光，机体表面基本不响应。
- 玩家机体和两个机器人靶机表现一致，问题更可能位于共用材质或 Shader 路径。

## 已确认

- `Key Light` 存在且启用。
- 运行时已成功创建 `Gameplay Fill Light`。
- `Gameplay Fill Light` 为无阴影方向光，强度 `0.9`。
- 环境光已提高：
  - Sky：`(0.16, 0.19, 0.24)`
  - Equator：`(0.085, 0.10, 0.13)`
  - Ground：`(0.035, 0.04, 0.055)`
  - Intensity：`0.85`
- `AC6ThermalObjects` 和 `AC6ThermalScreen` Renderer Feature 在热成像关闭时均为 inactive。
- `MechThermalSignature` 已停止向普通机体 Renderer 写入热量 MaterialPropertyBlock，并会在启动时清除旧覆盖。
- 增加补光和环境光后问题依旧存在，因此“场景完全没有光源”不是根因。

## 已尝试修改

- 在场景构建器中增加 `Gameplay Fill Light`。
- 增加 `MechGameplayLightingBootstrap`，在旧场景缺少补光时于运行时自动创建。
- 提高深空场景环境光。
- 禁止热特征组件向普通渲染路径写入 `_ThermalTemp`。
- 清除机体 Renderer 上遗留的 MaterialPropertyBlock。

## 优先排查

- [ ] 运行时逐个记录机体 Renderer 的 `sharedMaterials`、Shader 名称、`renderingLayerMask` 和启用状态。
- [ ] 检查导入 AC6 材质的基础色、主贴图、金属度、光滑度与法线贴图是否仍正确绑定。
- [ ] 检查材质 Shader 是否兼容当前 URP 版本，以及是否缺少 `UniversalForward` 或正确的光照 Pass。
- [ ] 检查机体 Renderer 与方向光的 Rendering Layer Mask 是否相交。
- [ ] 临时把一个机体 Renderer 替换为标准 `URP/Lit` 材质；若能正常受光，可确认问题位于原材质或 Shader。
- [ ] 检查热成像安装修改 `PC_Renderer.asset` 后是否改变了正常 Forward Renderer 的绘制路径。
- [ ] 对比问题出现前后的材质、Renderer Asset 和导入设置 Git 差异。

## 交接结论

当前证据指向机体共用的材质、Shader 或渲染层配置，而不是天空盒、相机曝光或单纯缺少灯光。最有效的下一步是使用标准 `URP/Lit` 临时材质做单个 Renderer 的 A/B 测试，再沿材质导入链或自定义 Shader 继续定位。

## 诊断结论（2026-07-25，6000.5.2f1 机器）

把上面"优先排查"的 1/2/5 条做成了自动化工具
`Tools > ACunicombat > AC6 > Diagnose Black Mech`
（批处理：`-executeMethod AC6BlackMechDiagnostic.RunBatch`，需要 GPU，勿加
`-nographics`），在 6000.5.2f1 + 同一份 git 资产（含被重序列化的
`PC_Renderer.asset` 和两个 inactive 热成像 feature）上实测：

```text
render[original]: centerLuminance=0.4111   ← AC6PartsApprox 原材质
render[urplit]:   centerLuminance=0.5035   ← 全部换白色 URP/Lit
DIAG_RESULT verdict=MECH_RENDERS_LIT_HERE
```

**机体在 6000.5.2f1 下受光完全正常。** 材质纹理绑定、Zone 颜色、renderingLayerMask、
MPB 状态逐项转储均无异常。问题只出现在你的环境，根因链：

1. 本日志"复现环境"写的是 **Unity 6000.0.52f1**，而 `ProjectVersion.txt`
   是 **6000.5.2f1**——版本不一致。
2. `PC_Renderer.asset` 在 ebccdab 里被按**新 schema 重序列化**
   （`m_AssetVersion: 2→3`、新增 `m_PrepassLayerMask` 等字段、删除
   `m_UseNativeRenderPass`、SSAO feature 丢失 `m_BlueNoise256Textures`），
   说明那台机器上至少有一次是用比 6000.0 新的编辑器打开的（Hub 多版本
   切换很容易发生）。
3. 旧编辑器读新 schema 的 renderer 资产 = 未知字段丢弃 + 缺失字段取默认，
   叠加 URP 17.0 与 17.5 的 shader 库差异——正是"自定义 lit shader 全黑、
   内置 URP/Lit 正常、阴影照常投射"这一类症状的经典来源。

**修复步骤**：
1. Unity Hub 里把项目固定用 **6000.5.2f1** 打开（与 `ProjectVersion.txt` 一致），
   不要再用 6000.0.x 打开本项目；
2. 删除本机 `Library/` 全量重导入；
3. 打开 `AC6PlayerControl` 场景验证，或直接跑 Diagnose Black Mech 看
   `DIAG_RESULT`。

另：新版 `AC6PlayableSceneBuilder` 现在硬依赖本地生成的
`Raw/NativeEquipment/WP_*_NATIVE.glb`（gitignore 素材）。这台机器上因缺这批
文件 BuildAllBatch 会失败——与全黑问题无关，但两台机器的本地素材生成
步骤需要在文档里对齐一下。
