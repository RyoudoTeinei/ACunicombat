# 雷达中远距可靠性深度排查

## 问题

试玩中雷达在约 `5-6 km` 已表现出目标框抖动、航迹丢失或重新编号，和设计中的 `50-100 km` 作战包线不符。

## 结论

- 当前问题不是雷达回波功率不足。
- 主要故障是场景桥接层生成错误速度，导致多普勒测量出现尖峰，航迹预测随后偏离真实目标并关联失败。
- 同一个物理目标会被反复分配成新航迹。运行日志中只有一台敌机注册，但导弹火控先后使用了 `Track#4`、`Track#14`、`Track#28`。
- 搜索光栅对角覆盖余量过小、全局驻留预算不足会进一步放大漏扫和延迟。

## 射频包线核对

生产主雷达参数：

| 参数 | 当前值 |
| --- | ---: |
| 最大距离 | `100 km` |
| 目标雷达截面 | `18 m²` |
| 常数项 | `215 dB` |
| 积累增益 | `6 dB` |
| 检测门限 | `3-10 dB` |

无干扰、波束对准时：

| 距离 | SNR | 探测概率 |
| ---: | ---: | ---: |
| `5 km` | `85.59 dB` | `100%` |
| `20 km` | `61.51 dB` | `100%` |
| `50 km` | `45.59 dB` | `100%` |
| `80 km` | `37.42 dB` | `100%` |
| `100 km` | `33.55 dB` | `100%` |

当前射频模型实际上偏强，`100 km` 是硬上限而不是信号门限。后续需要按“`10 m²` 目标在 `50 km` 接近发现门限”重新标定常数项，并让积累增益由驻留时间决定；本次不下调功率，以免掩盖航迹故障。

## 根因

### 速度采样跨时钟

- `MechPlayerRig` 和 AI 机甲在 `Update` 中推进飞行。
- 雷达桥接曾在 `FixedUpdate` 中用位置差除以 `fixedDeltaTime` 计算速度。
- `Update` 与 `FixedUpdate` 频率和相位不同，采样结果会在零值、正常值和尖峰之间跳变。
- 雷达把该速度写入多普勒测量，航迹滤波器因此获得错误速度。

### 高信噪比过度自信

- 旧多普勒标准差按 `1 / sqrt(SNR)` 无限缩小。
- 近距离高 SNR 下方差接近零，滤波器几乎完全相信错误速度尖峰。
- 下一次量测落到关联门外，系统建立新航迹，旧航迹继续滑行，最终占满 `32` 条容量。

### 搜索光栅余量

- 旧 `12°` 波束、约 `9°` 网格的最差对角覆盖余量只有约 `0.025°`。
- 摄像机、机体或目标在一帧扫描期间发生轻微角运动时可能穿过波束缝隙。

### 全局驻留预算

- 旧预算是全场每传感器 Tick `16` 个驻留。
- 母机雷达、敌机雷达和独立导弹导引头共用调度器；导弹末制导优先级高于广域搜索，交战时可能推迟载机搜索驻留。
- 设计基线的多平台和导引头负载本身已超过 `16`。

## 已修复

- 本机和机甲目标改用 `MechFlightMotionController.Velocity` 权威速度。
- 只有没有飞行组件的旧测试目标才保留位置差分后备路径。
- 多普勒标准差增加为速度分辨率 `10%` 的下限。
- 搜索网格改为 `14 × 9`，请求间距 `8°`。
- 每 `40 ms` 搜索驻留从 `4` 增至 `5`，完整搜索恢复到约 `1.01 s`。
- 全场驻留计算预算从 `16` 增至 `64`，不改变单雷达天线时序语义。

## 回归验证

- 新增生产参数 `5/20/50/80/100 km` 对准波束探测测试。
- 新增高 SNR 多普勒精度下限测试。
- 新增 `5 km` 与 `50 km` 双运动平台连续跟踪测试：本机 `250 m/s`、目标横向 `180 m/s`、持续 `10 s`，要求始终只有一条确认航迹。
- 新增搜索光栅最差对角覆盖余量测试。
- Unity 编译响应文件验证通过，无 C# 编译错误。
- 射频门限、多普勒精度下限和搜索光栅覆盖测试已在 Unity 自带 Mono 环境中执行通过。
- 使用 `NativeList` 的传感器/航迹跨层测试必须在 Unity Test Runner 内执行；脱离编辑器时 Unity 原生容器内部调用不可用。
