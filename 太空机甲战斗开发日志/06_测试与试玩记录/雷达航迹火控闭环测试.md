# 雷达航迹火控闭环测试

日期：2026-07-23

## 自动测试结果

Unity 原生运行时自测通过 5/5：

- `Radar_TargetInsideBeam`：波束内 1 千米目标产生一次发射记录和一次有效量测。
- `Tracking_FirstHitTentative`：第一次量测只建立一条暂定航迹，不会被重复计数。
- `Tracking_ThreeHitsConfirmed`：满足 3/5 逻辑后航迹转为已确认。
- `FireSolution_ConfirmedTrack`：新鲜的已确认航迹可以生成拦截点并获得开火许可。
- `FireSolution_StaleTrack`：过期航迹不会获得开火许可。

完整解决方案编译通过，结果为 0 个错误。编译输出仍有 114 个既存警告，本次没有把这些历史警告计为雷达实现失败。

由于 Unity 编辑器当时正在打开工程，命令行 BatchMode 测试被工程锁拒绝。随后在已打开的 Unity 编辑器内执行同一组原生自测，以上五项全部通过；涉及 `NativeArray` 和 `NativeList` 的雷达、航迹测试没有使用脱离 Unity 的替代运行时。

## 场景验收步骤

1. 重新构建或打开可游玩测试场景并进入 Play。
2. 将模拟敌人保持在机体雷达波束和准星附近。
3. 观察 HUD 航迹由暂定状态转为确认状态。
4. 使用枪炮开火，确认有效航迹和火控解存在时才按解算方向射击。
5. 发射导弹，确认导弹绑定的是 `TrackId`，而不是直接追踪目标 `Transform`。
6. 让目标短时离开波束，确认导弹使用航迹外推；超过航迹生命周期后应停止获得有效更新。

## 后续测试重点

- 高速交会、横穿目标和极端相对速度下的拦截质量。
- 遮挡、杂波、干扰和欺骗条件下的虚警与漏警。
- 多枚导弹同时发射时的制导通道占用和释放。
