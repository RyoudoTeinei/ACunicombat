# 画面与渲染升级计划

## 目的

达成三个观感目标：真空强反射与炫目高光、金属表面波光粼粼、太空深邃辽阔；并为液体/气尖/固体三类发动机的真空羽焰与被点亮的废气云建立框架。

本计划的排序**不按视觉收益，按引擎层依赖**。原因见下节：当前存在一个 shader 关键字缺口，导致机体根本收不到附加光源和部分 IBL 路径，在修好它之前所有打光和材质调参都是在错误的显示链路上盲调。

## 核实过的现状（含证据）

环境：Unity `6000.5.2f1`，URP `17.5.0`，`PC_RPAsset`（HDR 已开），`PC_Renderer`。

### 一、渲染路径是 Forward+，不是 Deferred

`PC_Renderer.asset:114` `m_RenderingMode: 2`。URP `UniversalRenderer.cs` 的枚举实测为：

```
Forward = 0,  Deferred = 1,  ForwardPlus = 2,  DeferredPlus = 3
```

所以 `2` = **ForwardPlus**。不要改成 `0`——那是降级，且会破坏羽焰多光源方案。

### 二、`AC6PartsApprox.shader` 缺少 URP 17 的一整批关键字（根因）

现有声明（`:56-65`）只有：

```
_MAIN_LIGHT_SHADOWS / _CASCADE / _SCREEN
_ADDITIONAL_LIGHTS_VERTEX / _ADDITIONAL_LIGHTS
_ADDITIONAL_LIGHT_SHADOWS
_SHADOWS_SOFT
multi_compile_fog
```

对比 URP 17.5 官方 `Lit.shader` 的 ForwardLit pass，**缺失**：

| 缺失关键字 | 后果 |
| --- | --- |
| `_CLUSTER_LIGHT_LOOP` | **机体收不到任何附加光源**（详见下） |
| `_REFLECTION_PROBE_ATLAS` | Forward+ 的反射探针图集路径不生效，局部探针无效 |
| `_REFLECTION_PROBE_BLENDING` / `_BOX_PROJECTION` | 探针混合与盒投影不生效 |
| `_SCREEN_SPACE_OCCLUSION` | **SSAO feature 在 `PC_Renderer` 里是启用的，但机体读不到** |
| `_SHADOWS_SOFT_LOW/MEDIUM/HIGH` | URP 17 把软阴影拆成质量档，旧的单一 `_SHADOWS_SOFT` 拿不到分档 |
| `EVALUATE_SH_MIXED` / `EVALUATE_SH_VERTEX` | SH 环境光求值路径 |
| `_LIGHT_COOKIES` / `_LIGHT_LAYERS` / `REFLECTION_PROBE_ROTATION` | 对应功能静默失效 |

`_CLUSTER_LIGHT_LOOP` 的链路是闭合可证的：

1. `ShaderLibrary/Core.hlsl:13-16` —— `USE_CLUSTER_LIGHT_LOOP` **只由 `_CLUSTER_LIGHT_LOOP` 关键字决定**。shader 不声明该 pragma，关键字永远无法置位，`USE_CLUSTER_LIGHT_LOOP` 恒为 `0`。
2. `ShaderLibrary/RealtimeLights.hlsl` —— `GetAdditionalLightsCount()` 在 `USE_CLUSTER_LIGHT_LOOP == 0` 时走 `#else` 分支，返回 `min(_AdditionalLightsCount.x, unity_LightData.y)`，即**经典逐物体光索引路径**。
3. `Runtime/ForwardLights.cs:744-745` —— 
   ```csharp
   if (lightData.additionalLightsCount == 0 || m_UseForwardPlus)
       return lightData.additionalLightsCount;   // 提前返回
   ```
   Forward+ 下 URP **根本不建立逐物体光索引**（集群方案的设计目的就是取消这个上限）。

结论：shader 编译出的是经典循环，管线送来的是集群数据，两者对不上 → **机体只收到主光 + 环境/IBL，所有点光/聚光被静默丢弃。**

### 三、上一条的直接证据：场景里那盏 Rim Light 一直没生效

`AC6PlayerControl.unity`（`AC6PlayableSceneBuilder.cs:27-28` 的 `PlayableScenePath`）里只有两盏灯：

- `Key Light`
- `Rim Light` —— `:12885`，enabled，**`m_Type: 2` = Point**，intensity 5，色 `(0.48, 0.62, 0.85)`

它是点光源，所以在上述缺口下**对机体完全无作用**。这解释了一个矛盾：对象确实存在，但画面上看不到任何轮廓光效果。

builder `:940-946` 只改它的 color 和 intensity，**没有设 `type`**，所以它会一直是点光源。

> 注意：修好关键字后这盏灯会突然开始工作，画面会变。这是预期行为，不是回归。

### 四、色彩管线是 LDR 的，ACES 装上去也没用

| 项 | 当前值 | 含义 |
| --- | --- | --- |
| `m_ColorGradingMode` | `0` | **LDR**。LUT 覆盖 `[0,1]`，颜色在查表前被 clamp，ACES 拿到的已经是压过的值，高光滚降无从发生 |
| `m_ColorGradingLutSize` | `32` | 高对比太空场景的暗部容易色带 |
| `m_HDRColorBufferPrecision` | `0` | `R11G11B10_UFloat`：无 alpha、无符号、尾数仅 5 bit，高量级处量化步长很大 |
| `m_MSAA` | `1` | 关闭（`Disabled = 1`） |
| Tonemapping | mode `0` = **None** | 不是 Neutral。当前连范围重映射都没有 |
| Bloom | intensity `0` | 实际关闭 |

后处理没有场景 Volume：builder 不创建 Volume，也不配相机后处理，生效的是 URP 出厂 `DefaultVolumeProfile.asset`。

### 五、天空盒是 8-bit LDR，同时卡住了两件事

`AC6PlayableSceneBuilder.cs:964` `Color32[]` → `:1029` `TextureFormat.RGBA32` → `:1036` `EncodeToPNG()`。太阳盘亮度封顶 `1.0`。版本号 `2-distant-sun`。

后果**有两条**，不只一条：

1. Bloom 阈值 ≥ 1.0 时，太阳**永远无法触发泛光**。
2. 更关键：天空盒反射探针的最亮值也被封在 `1.0`。**金属几乎没有漫反射，全部外观来自 IBL** —— 所以在探针变成 HDR 之前提高 metallic，机体会**变暗而不是变亮**，看起来像倒退。

环境光是 `AmbientMode.Trilight`（三色常量，`:886-890`），**不从天空盒推导**，所以把全景图改成 HDR 不会连带炸掉环境光。`reflectionIntensity = 0.32`（`:891`）缩放的是天空盒探针贡献。

### 六、热成像管线的两个注入点

| Feature | 类型 | 参数 | 含义 |
| --- | --- | --- | --- |
| `AC6ThermalObjects` | `RenderObjects` | `Event: 400`、`RenderQueueType: 0` | AfterRenderingSkybox，**仅不透明队列** |
| `AC6ThermalScreen` | `FullScreenPass` | `injectionPoint: 550`、`fetchColorBuffer: 1`、`requirements: 1`(Depth) | BeforeRenderingPostProcessing |

两个后果：

- **所有后处理都叠在热像上**，不只是 Bloom。ACES 的 S 曲线、`postExposure`、饱和度都会重映射 7-30 刚标定好的灰阶关系（天空底噪 `0.025` vs 机体灰度）。
- **透明队列不被热像覆盖**。透明物在 450–500 绘制，晚于 400 的覆盖 pass，所以它们带着可见光外观进入缓冲，然后在 550 被当作温度编码重映射 → 结果是垃圾。羽焰若走透明队列会踩这个坑。

### 七、AGC 与热源注册

`MechThermalVisionController.cs:264`：

```
agcMeteringSamples.Add(Radiance(emitter.TemperatureK));
```

AGC 窗口从场景内全部热源测光。`MechThermalPointEmitter.SetTemperature(K)`（`:378-386`）是注册接口。任何新增高温源都会拉动窗口——与 7-30 那个 bug 同源，`agcMaxWindowRadianceRatio`（32:1）是现有兜底。

## 实施阶段

### 阶段 0：基线与度量

- 提交当前工作区（热成像 AGC 修复 + 未 add 的音频层）作为基线，之后每阶段单独提交。
- 固定一组度量机位：向阳面、背光面、逆光对日、热像白热/黑热各一张，同机位同帧号。每阶段结束出对比图。
- 度量工具：Frame Debugger 看 pass 顺序与 draw；shader Inspector 的已编译变体列表确认关键字置位；记录变体数与编译耗时基线。

### 阶段 1：管线正确性（不碰任何美术数值）

这一阶段的目标不是好看，是**让引擎能把光和 IBL 正确送到机体上**。

**1a — 补齐 `AC6PartsApprox.shader` 的 ForwardLit 关键字**

按 URP 17.5 官方 `Lit.shader` 对齐，至少加入：

```
#pragma multi_compile _ _CLUSTER_LIGHT_LOOP
#pragma multi_compile _ EVALUATE_SH_MIXED EVALUATE_SH_VERTEX
#pragma multi_compile_fragment _ _REFLECTION_PROBE_ATLAS
#pragma multi_compile_fragment _ _REFLECTION_PROBE_BLENDING
#pragma multi_compile_fragment _ _REFLECTION_PROBE_BOX_PROJECTION
#pragma multi_compile_fragment _ _SCREEN_SPACE_OCCLUSION
#pragma multi_compile_fragment _ _SHADOWS_SOFT _SHADOWS_SOFT_LOW _SHADOWS_SOFT_MEDIUM _SHADOWS_SOFT_HIGH
#pragma multi_compile_fragment _ _LIGHT_COOKIES
#pragma multi_compile _ _LIGHT_LAYERS
```

注意：
- 现有的单一 `#pragma multi_compile _ _SHADOWS_SOFT` 要替换成分档版本，不是叠加。
- `_FORWARD_PLUS` 是旧名，URP 17 会带警告兼容，**用 `_CLUSTER_LIGHT_LOOP`**。
- 关键字数量直接乘变体数。逐个加、逐个测，必要时用 `#pragma skip_variants` 砍掉确定不用的组合（如光照贴图相关）。把变体数与编译耗时和阶段 0 基线对比。
- `AC6ZoomDottedGhost` / 热像两个 shader 若也参与光照，同样检查。

**验证**：在机体旁放一盏点光源，Play 确认现在能照亮机体（修复前应完全无效）。Frame Debugger 确认走集群路径。开关 SSAO 确认机体明暗有响应。

**1b — 色彩管线切 HDR**

- `PC_RPAsset.asset` `m_ColorGradingMode: 0 → 1`（HDR）。这一步是 ACES 生效的前提：LDR 模式下颜色在 LUT 查表前被 clamp 到 `[0,1]`，色调映射拿不到 >1 的输入。
- `m_ColorGradingLutSize: 32 → 48`。
- `m_HDRColorBufferPrecision` 先保持 `0`。若后续太阳泛光光环出现色带，**这里才是旋钮**（→ `_64Bits` = `R16G16B16A16_SFloat`），不要去调 Bloom 参数。
- MSAA **暂不动**。原因：热像 pass 声明了 Depth 需求，MSAA 深度解析只取单一样本，物体边缘会出现 1px 热像伪影。等阶段 3 热像验证完再考虑提到 4x，并专门检查边缘。

**验证**：ACES 在 1b 之后才有意义，这里先只确认画面没有整体偏色或变暗，不做观感评价。

### 阶段 2：光源与环境（解锁金属外观）

**2a — 全景图升级为 HDR**

`GetOrCreateDeepSpacePanorama()` 改造：

- 像素缓冲 `Color32[]` → `Color[]`，纹理格式 `RGBA32` → `RGBAHalf`，落盘 `EncodeToPNG()` → `EncodeToEXR()`。
- 太阳盘写线性 `50–500` 量级，日冕做幂次衰减；星野保持 `0.02–0.8`。
- 版本号 `2-distant-sun` → `3-hdr-sun`，确保旧图不会存活。
- 导入设置必须显式指定浮点格式并关闭 sRGB，否则 Unity 可能压回 LDR。迭代期用 `RGBAHalf`，定稿后可换 `BC6H`（HDR 块压缩，无 alpha）。

**2b — 反射与探针**

- Lighting 设置里的默认反射分辨率提到 `256` 或 `512`。低分辨率探针在高 smoothness 下反射会糊，而高 smoothness 正是"波光粼粼"要用的。
- `reflectionIntensity` `0.32 → 0.7`（在探针变 HDR 之后才有意义）。
- **局部探针先不做**。场景近乎真空，局部探针只多提供机体自反射；先靠 HDR 天空盒探针，确认确实缺自反射再加。若要加：探针 parent 到机体，`Realtime` + `ViaScripting` 刷新，`timeSlicingMode = IndividualFaces` 分摊到 9 帧，`boxProjection` 关闭。

**2c — 打光重排（`AC6PlayableSceneBuilder.cs:885-946`）**

- **Key Light 保持中等：`2.35 → 8~12`，不要推到 50。** 理由：URP 的 ACES 近似把中灰 `0.18` 映到约 `0.1` 显示值，肩部在 `4~6` 以上压缩很快。0.5 反射率表面在 intensity 10 下进入 HDR 缓冲约 `5`，正好落在肩部起点；intensity 50 会把整个机体推到肩部深处，**对比度反而丢失**。
  **炫目应该来自天空盒太阳盘的 HDR 值（50–500）+ Bloom，不是来自平行光强度。** 这两个角色要分开。
- 环境光 Trilight intensity `0.85 → 0.4~0.5`，三色同步压暗。
- Fill Light（脚下行星反光）`0.9 → 0.5`，保持冷蓝。
- **Rim Light**：处理那盏点光源。两条路——改成 directional（简单，全局一致），或 parent 到机体并保留点光（局部更可控，阶段 1 之后才有效）。
- 色温：真空中直射日光约 5778K，几乎中性白。当前 `(1, 0.965, 0.9)` 偏暖，可略微中性化。
- **阴影改硬边**：真空无大气散射，明暗界线应当锐利、暗面近黑。`LightShadows.Soft` 在物理上是错的，硬阴影既更准也更省。若锯齿不可接受，退回软阴影但用小半径 + 更高阴影分辨率。

### 阶段 3：后处理与观瞄视图分离

**3a — 战斗视图 Volume**

新建 `Assets/_Project/Rendering/AC6SpaceCombatVolume.asset`，**不动**模板 `DefaultVolumeProfile.asset`。由 builder 在场景根幂等创建 global Volume 引用它。

- Tonemapping = **ACES**
- Bloom：threshold、intensity、scatter、highQualityFiltering 开
- ColorAdjustments：postExposure、saturation 微调

引擎层注意：
- `VolumeManager` 的基础层来自 URP Global Settings 的默认 profile，所以**所有要用的值都在场景 Volume 里显式覆盖**，不要依赖默认 profile 的隐含值。
- Bloom 在色调映射**之前**作用于 HDR 缓冲，所以 threshold 的单位是**线性场景参考值**，不是显示值。threshold `1.0` ≈ "比主光下的漫反射白更亮"。
- `skipIterations`（默认 1）使泛光半径随分辨率变化 —— 太阳光斑在 1080p 和 4K 下大小不同。这是机制而非 bug，记录下来免得误判。

**3b — 观瞄模式独立 Volume（关键）**

热像 pass 在 550，所有后处理都会重映射它。方案：

- 两个 global Volume 放在**不同 Layer** 上，切换热像时改 `UniversalAdditionalCameraData.volumeLayerMask`。比替换 `VolumeProfile` 便宜（后者强制重解析），也是引擎设计意图内的做法。
- 热像 Volume：Tonemapping = None，Bloom 极弱或关，不做曝光/饱和度调整 —— 保持仪表读数的线性可读性，AGC 标定不受影响。

**副产品**：战斗视图从此**不受 `threshold ≥ 1.0` 的人为约束**，Bloom 可以放开调。

**3c — 让热像里的高温源真的能"烧"起来**

AGC 把饱和源钳到纯白 `1.0`，而 threshold `1.0` 意味着它产生的泛光≈零。若要羽焰在白热模式下过曝溢出，应让热像 shader 对**超窗辐射输出 >1.0 的 HDR 值**而不是 clamp 到 1.0 —— 这是 `agcMaxWindowRadianceRatio` 钳位可以顺手带出的一行改动。

### 阶段 4：材质表现

**4a — 逐 zone metallic / smoothness**

**硬依赖阶段 2**。metallic 高 = 漫反射趋零 = 外观全部来自 IBL；在 HDR 探针到位前做这一步只会让机体变暗，容易被误判为回归而回退。

- zone mask 链已存在（`:197-203`），照抄一份插值顺序做 `BuildAc6ZoneMetallicSmoothness(mask)`。
- `_ZoneMode` 开时由 zone 决定，关时回退 `_Metallic` / `_Smoothness`（`:256-257`）。
- 新属性走 shader 默认值，147 个现有材质无需重导。但导入器会写材质覆盖，需决定逐 zone 值是留在 shader 默认里还是进导入器 —— 倾向前者 + 少量精选覆盖。
- 起点语义：主装甲（涂装）低金属中光滑；深色 zone（裸金属关节/框架）高金属中高光滑；Dust/标记零金属低光滑。

**为什么这样就"粼粼"**：`smoothness` 经 `PerceptualRoughnessToMipmapLevel` 直接选择 IBL 的 mip 层级，所以逐 zone smoothness 就是逐 zone 的反射锐度。机体转动时不同 zone 在不同角度先后"抓"到太阳。

**4b — 各向异性高光（精修，可延后）**

URP 的 `BRDFData` 不含各向异性，`UniversalFragmentPBR`（`:271`）表达不了。可行做法是在 PBR 结果之上**额外叠一个各向异性 GGX 高光叶**，用 `GetMainLight()` + 集群光循环手写。

前提：网格必须有切线（FBX 导入 `Import Tangents`）。机加工金属的拉丝方向一般不等于 UV 切线方向，实际折中是逐 zone 各向异性强度 + UV 推导切线。

### 阶段 5：引擎尾焰与废气云

前置：阶段 1（否则羽焰的点光源会和 Rim Light 一样被静默丢弃）、阶段 3（泛光是"泛开"观感的本体）。

**5a — 热像透明队列缺口（开工前必须定）**

`AC6ThermalObjects` 只覆盖不透明队列。羽焰若走透明队列，在热像里不是"看不见"，而是**带着可见光外观被当成温度编码重映射**。两条路：

- 增加第二个 `RenderObjects` pass，`RenderQueueType: 1`（Transparent）+ 热像覆盖材质；
- 或羽焰完全不进主透明队列，走专门的热像通道。

玩法上这条不能省：太空里羽焰是红外特征最强的东西，"烧固体的人会被看见"整条设计依赖它。

**5b — AGC 重标定**

大面积高温羽焰/废气云会拉动 `agcMeteringSamples`。`agcMaxWindowRadianceRatio`（32:1）几乎肯定要重标，并可能需要把点源测光升级为**面积加权**测光。这项与 5a 一起做，不要留到收尾。

**5c — 真空羽焰的物理形态**

- **液体机**：出口压 >> 环境压（真空为 0），欠膨胀自由膨胀，扩张角可接近甚至超过 90°。视觉 = **极短极亮的核心 + 极宽极暗的泛光罩**。羽流几何应是渐扩的旋成体，不是直锥。
- **真空里没有马赫环。** 激波菱形来自流场被环境压再压缩，硬真空无环境压、无再压缩，因此不存在。马赫环属于大气场景，不要放进太空羽焰。
- **固体机**：铝掺杂推进剂产生氧化铝凝相颗粒 → 明亮、致密、不透明的白橙羽焰 + 大量烟。废气云在真空中弹道式膨胀且**不消散**（无风、无扩散介质，只持续变稀），并被发动机自身从内部照亮。
- **气尖机**：高度补偿在全真空场景里**看不见**，只剩环状/塞锥包络的形状差异。要让它有存在感，必须给一个非几何优势（比冲更高 → 推进剂或 EN 消耗更低），挂到既有资源系统上。

**5d — 实现路径**

- 装 `com.unity.visualeffectgraph`。持续膨胀的废气云粒子量内置 Shuriken 撑不住，需要 GPU 粒子。
- 废气云内部照明：**Forward+ 的集群光循环取消了逐物体光源上限**，所以每个喷口挂一盏真实点光源 + 受光粒子输出是可行且最直观的。用自定义 shader 解析算 `1/d²` 是一种**优化选项**（更省、美术控制更强），不是必需的绕路。
- 羽流长度/张角由 `MechFlightMotionController` 的节流/QB/AB 信号驱动；挂点 `_dmy_800` 现成。
- 温度信号接 `MechThermalSignature` 推进器通道 + `MechThermalPointEmitter`。
- 发动机类型进 `MechPartDefinition`，让红外特征成为换装权衡：固体 = 高推力 / 巨大红外特征 / 不可节流；液体 = 可节流 / 中等特征；气尖 = 高效率。
- **美术边界决定**：现有火焰是 AC6 原生 FXR（为大气环境制作）。与真空物理羽焰混用会不统一，需明确划界（建议 FXR 留给武器/装备特效，推进器全部走新系统）。

## 风险与注意

- **阶段 1 会改变画面**：休眠的点光源（Rim Light）会开始生效，SSAO 会开始作用于机体。这是修复而非回归，但必须与阶段 0 的基线图对照记录，否则后续无法归因。
- **变体爆炸**：新增约 9 组关键字会显著抬升变体数与编译时间。逐个加、逐个量，必要时 `skip_variants`。
- **MSAA 与热像**：MSAA 深度解析取单一样本，会在物体边缘产生 1px 热像伪影。MSAA 放到阶段 3 之后，且必须专项检查边缘。
- **HDR 缓冲精度**：`R11G11B10_UFloat` 尾数 5 bit，太阳泛光光环可能色带。先别动，出现了再换 `_64Bits`。
- 所有光照/后处理数值均为起点，需 Play 迭代。每阶段一次提交、一组同机位对比图、一次 Frame Debugger 抓帧。
