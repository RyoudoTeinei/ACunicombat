# 模块化战斗架构重构方案

日期：2026-10-13。状态：实施提案，尚未实施。面向现有 Unity 工程的渐进重构。

核心目标是索敌、对抗、防空和自由拼装；架构必须支持不同插槽布局、多种武备、友敌共用机体运行时，以及随成员、装备和态势变化调整任务的协同 AI。保留现有驾驶、动画、雷达和导弹算法，先纠正状态归属和接入边界，再扩展玩法。

## 一 设计约束

1. 每个状态只有一个权威写入者。显示、AI 和效果读取快照或消费事件，不另建一份实际状态。
2. 玩家、友军、敌军共用机体、装备、感知、火控和伤害实现；输入来源、阵营关系、任务和策略可以不同。
3. 每台机体独立拥有感知知识。战场世界知道真实状态，但战术 AI、火控、HUD 不得直接遍历敌方真实 Transform。
4. 新增同类部件、插槽和角色主要改数据；新增真正不同的机制允许增加一个明确的能力模块和算法，不承诺所有功能零代码。
5. 多机联动指战场内协作，不等同于网络多人。预留稳定身份和命令边界，本轮不引入网络同步或完整 ECS 重写。
6. 小步替换，一次只改变一个权威路径。同一场景中不可让新旧实现同时驱动物理、扣除资源或生成弹体。
7. 保持三维导航参考面、俯仰飞行、辅助滚转约束和现有推进包线。重构阶段不顺便调整手感或引入完整轨道力学。

## 二 当前问题与处理决定

| 当前实现 | 决定 | 迁移边界 |
| --- | --- | --- |
| Sim/Core、World、Kinematics | 保留基础算法 | 增加唯一实体注册入口和生命周期；运动仍由现有运动组件负责，避免双重积分 |
| Sensors、Tracking、FireControl | 保留职责分层 | 感知和跟踪按平台隔离；火控算法复用；不合并为一个万能战斗类 |
| DataLink、ElectronicWarfare | 保留 | 数据链只运送消息，电子战改变信号；编队决策不塞入通信层 |
| SimulationDriver | 收窄 | 管理时钟和系统执行顺序，移除唯一 ownship 与唯一主航迹来源假设 |
| MechRadarController | 分阶段拆迁，最后删除兼容外壳 | 场景实体桥、主动雷达控制、目标指派、交战许可、导引头注册、制导上行分别归属正确模块 |
| MechLoadoutDefinition、MechPartDefinition | 保留资产入口并版本化迁移 | 固定槽位枚举转为稳定槽位身份与兼容规则；静态定义和运行时状态分离 |
| MechAssembler、Validator、StatsCalculator | 保留并扩展 | 装配拓扑、挂点解析、依赖检查、标量汇总；不承担 AI 或武器执行 |
| MechFlightMotionController | 首轮保留算法 | 后续抽出导航参考、推力分配与姿态算法，共用明确运动状态；不按文件长度机械拆分 |
| MechPlayerRig | 收窄 | 玩家输入映射和本地视角编排；武器状态、动作兼容策略、装配、热状态迁出 |
| MechWeaponArmLayer、肩部发射状态 | 统一装备生命周期，保留不同表现适配器 | 装备实例负责可用状态与发射时机；手臂和肩部动画各自适配 |
| MechBodyActionPlayer、EquipmentAnimationPlayer、SynchronizedAnimationPlayer | 保留播放能力 | 播放器不裁决是否允许攻击；动作选择统一由表现策略提供 |
| MechTestWeaponSystem、MechTestProjectile | 提取正式运行时 | 拆成装备控制、弹体、制导、引信、命中效果；旧名称保留短期适配 |
| MechThermalSignature、ThermalPointEmitter | 统一热源状态契约 | 动态与恒温模型都可实现热源；热像和红外探测消费同源数据 |
| RadarHud、ThreatWarning、ThermalVision、Camera | 保留表现层 | 只读观察者快照，不自动创建作战能力或注册目标 |
| AC6CombatShowcaseController | 隔离为演示 | 公共装配迁入 PlatformFactory；正式运行不依赖演示 Start |
| AC6PlayerMechController、旧场景生成器 | 迁移后退役 | 先确认场景引用，迁移并验收，再归档旧入口；不直接删除序列化脚本 |
| MechAiTargetController、CombatTestTarget | 分拆用途 | AI 迁入共享决策框架；健康、信号、阵营迁入实体组件；靶机往复运动留在测试设施 |

当前可核对入口：`Assets/_Project/Scripts/Mech/Runtime/MechRadarController.cs` 的 EnsureInitialized、`Sim/Driver/SimulationDriver.cs` 的 RegisterRadarSensor、`MechPlayerRig.cs` 的肩部状态与全身动作覆盖、`MechTestWeaponSystem.cs` 的 CommandFireMissile、`MechThermalVisionController.cs` 的 AutoTagUntaggedHeatSources。当前配装校验以 MechPartSlot 为字典键并拒绝重复，是八武器槽扩展的直接障碍。

## 三 目标职责结构

| 领域 | 权威状态和职责 | 明确禁止 |
| --- | --- | --- |
| 战场与身份 | EntityRegistry、关系表、生成销毁、世界真实状态、遮挡 | 向 AI 提供敌人全知列表 |
| 平台与装配 | PlatformRuntime、槽位拓扑、设备实例、能力目录 | 根据玩家或敌人身份选择另一套物理 |
| 运动 | 机体姿态、速度、导航参考和推力执行 | 动画或 AI 直接写 Transform |
| 资源与信号 | 弹药、电力、热、推进剂、辐射签名 | UI 创建热量；同一次开火多处扣费 |
| 感知 | 雷达、被动侦收、红外量测及质量 | 凭目标实体身份自动获得距离或敌我结论 |
| 本地态势 | 航迹、威胁、身份置信度、来源、时效 | 把友军转发航迹直接当无误差真值 |
| 交战 | 目标分配、武器可行性、火控解、制导资源预留 | 绕过武器运行时直接生成弹体 |
| 装备执行 | 装备状态、发射许可执行、弹药和冷却、能力动作 | 固定左手必为炮、固定两路背部武器 |
| 弹体与结算 | 飞行、导引头、制导、引信、碰撞和伤害管线 | 弹体必须依赖发射机的雷达控制脚本存活 |
| 防御 | 主动拦截请求、干扰与诱饵请求、装甲响应 | 另建一套通用枪炮或通用导弹实现 |
| AI 与协同 | 任务选择、角色偏好、编队分工、战术意图 | 直接扣血、瞬移、修改装备冷却 |
| 表现 | 动画、喷焰、声音、镜头、HUD、热像 | 成为武器状态与战斗温度的唯一持有者 |

这些是职责边界，不要求一项对应一个独立程序集或一个 MonoBehaviour。先在现有程序集内建立清楚接口，依赖稳定后再设置编译边界，避免为每个小功能增加框架。

## 四 机体和插槽的数据模型

建议引入以下明确类型，名称可随实现调整，职责不变。

- PlatformDefinition：机体类型与基础布局；描述必要骨架接口、基础槽位与资源总线，不硬编码人形四武器限制。
- SlotDefinition：稳定 SlotId、挂载类别、标签约束、尺寸与载重、供电与散热接口、安装位置和射界限制。槽位身份与左右手等显示名称分离。
- PartDefinition：部件静态定义，组合 Weapon、Sensor、Propulsion、Armor、Countermeasure 等有类型的模块配置。标签用于兼容筛选，核心行为不依赖任意字符串反射。
- EquipmentInstance：运行时实例身份、所占槽位、耐久、弹药、冷却与模块状态。共享 ScriptableObject 不存运行时弹药和温度。
- MountBinding：模型挂点与骨骼适配。一个逻辑推进器可以对应多个喷口，但只计一次部件质量和成本。
- CapabilitySnapshot：从当前设备与状态派生的可用能力，例如拦截目标类型、射界、射程、通道、反应时间、余弹、传感器质量。供 AI 与交战层读取。

示例：标准机体定义 4 个 weapon 槽；重型机定义 8 个独立 SlotId，仍使用同一配装列表和装备执行器。新增 defense.utility 槽可装主动防御设备；新增 armor.panel 槽关联一个受击区域并可装反应装甲。UI 根据槽位列表生成，输入映射到武器组或装备实例，不要求八把武器绑定八套脚本。

可扩展挂架允许部件提供子槽位。子槽位身份由父设备安装路径与定义内局部 ID 组成，禁止依赖数组顺序；装配图必须无环。卸下父挂架时先列出依赖子装备，编辑器拒绝隐式丢弃；战斗中父部件损毁使子设备失效并释放任务、制导和资源预留。第一版只实现有界层级，避免无限递归拼装。

兼容迁移保留旧 MechPartSlot 数字值和旧资产字段，通过映射生成稳定 SlotId。新格式为唯一运行时输入，旧格式仅加载时转换，不长期双向同步。资产转换提供只读预览、错误报告和版本号；保持 .meta GUID、现有引用和原始资产，先转换样例副本。数据缺失报明确错误，不能静默绑定到第一个武器槽。

整机质量、可加总装甲等可聚合；传感器、发射器和火控通道必须保留实例能力。两个雷达不能简单把距离相加，八个挂架也不自动意味着八个并行制导通道。

## 五 世界身份和每台机体的知识

EntityId 由战场统一分配并带代际；每个对象仅注册一次。机甲、导弹、无人机、诱饵、残骸可具备不同组件，但都走同一生命周期。SensorId、LinkTerminalId、EquipmentId 由对应注册表分配，移除固定 0、1、8 等平台私有编号区段假设。

每台机体建立 PlatformCombatContext，持有本地航迹库、威胁库、目标指派和交战资源。共享仿真驱动调度各上下文，不共享一份玩家航迹库。导弹作为独立实体持有自己的导引头状态和通信订阅；发射机销毁时，上行消息停止，但有条件的自主末制导仍继续。

TrackRef 至少包含观察者身份、航迹 ID 和代际。跨机消息携带来源、时间戳、误差、身份置信度和来源链；不同机体的 track 7 不等于同一目标。收到友军报告后先按时空门限和不确定性关联，不用真实 EntityId 偷做完美匹配。同一报告循环转发不得重复提高置信度。

真实阵营用于伤害和世界规则；感知阵营是未知、友、敌或不确定及其置信度。交战规则显式处理未知接触。仅有被动方位告警时可触发规避，不自动生成精准拦截解。

统一调度顺序：消费上一决策命令、运动与弹体更新、提交世界快照、信号与通信、量测与本地融合、AI 决策与交战请求、发布结果供表现读取。分频沿用现有基线并明确时间戳；早期迁移先复刻旧执行顺序，不在迁移身份时同时重排战斗时序。

## 六 统一命令和交战执行

建议的最小契约：

| 契约 | 用途 |
| --- | --- |
| PlatformCommand | 来源、序号、期望运动、目标指派、传感器模式和装备请求 |
| EquipmentActionRequest | 设备实例、动作类型、TrackRef 或方向、有效期与请求原因 |
| EngagementProposal | 目标、武器实例、预测拦截时间、解算质量、资源要求和不可行原因 |
| ActionResult | 接受或拒绝及理由；不得用播放动画代替实际执行结果 |
| CombatEvent | 发射、耗弹、命中、部件失效、任务取消等已发生事实 |
| CapabilitySnapshot | 当前可用设备能力与资源余量 |

执行链：玩家输入或 AI 意图 → 指派与交战评估 → 装备状态及资源预留 → 到达发射时机时重新校验 → 一次性扣费并生成弹体 → 发布 WeaponFired → 动画、声音和热源响应。

部署、开盖、蓄力、发射、冷却等状态归装备实例所有。动画标记可提供一次带请求序号的释放信号，但不能自行授权；无动画或纯模拟 AI 使用同一动作时序配置。取消、失效、丢锁、过期请求会释放预留。玩家和 AI 均经过这条路径，手动射击是否允许无航迹由武器与模式规则决定，不能隐式回退读取敌人真值。

现有导弹 PN、引信、推进和火控公式先原样迁移。步枪、炮和导弹共用发射生命周期，各保留弹道、制导和弹头机制。武器性能由设备定义提供，旧固定数值作为 LegacyProfile 保持样例手感。

## 七 防空和被动防护

防空是交战目标、任务优先级和装备能力的组合。近防炮与进攻炮使用同一枪炮执行模块；可拦截导弹与攻击导弹共用弹体基础，不要求相同导引头、射界或引信。

主动防御模块读取本地威胁和受保护对象的授权信息，按预计到达时间、威胁程度、航迹质量、射界、最小反应时间和可用弹药产生拦截请求，走统一交战链。它有局部自动防御策略，平台 AI 决定允许范围和资源预算。具备导弹告警不等于必然具有满足拦截精度的跟踪雷达。

反应装甲属于伤害响应，挂接受击区域、方向、剩余单元和适用威胁条件，不经过目标选择 AI。统一结算顺序为命中及引信成立、获取受击区域、评估主动/被动防护结果、装甲消耗与剩余伤害、结构及组件损坏、能力失效事件。主动拦截发生在命中前；不能在命中结算时凭空抹掉已经没有拦截机会的弹体。

损坏结果影响现有能力，例如炮塔卡死缩小射界、雷达失效降低态势质量、供电受损减少可用预算。热模型同时给热像、IR 探测和未来过热惩罚供数，禁止各自维护燃烧状态。

## 八 可复用的机体和编队 AI

每台 AI 机体需要自己的决策上下文和记忆，但不需要每种机体一份 AI 代码。采用共享决策实现，输入为本地态势、可用能力、任务意图、角色配置和交战规则。

决策分三层：

1. 编队层处理搜索区域、护卫对象、攻击或拦截任务与资源分配，只使用授权收到的信息。
2. 平台层生成搜索、跟踪、攻击、拦截、护航、规避、撤离等候选行为；先检验能力与交战可行性，再用角色权重排序。
3. 执行层将选定行为转换为运动、传感器和装备命令，使用玩家共用执行器。

角色是策略配置，可设主角色与次角色：侦察偏重覆盖和隐蔽，防空偏重友军威胁与拦截时限，进攻偏重打击价值和攻击窗口。选择还考虑手上装备、余弹、射界、解算质量、预计用时和生存风险。切换防空配置不会让没有拦截能力的机体获得虚构能力；它可以搜索、告警、诱导或规避。

行为采用效用评分选择任务，配小型状态机执行持续动作。首轮不同时引入 GOAP、复杂行为树和学习策略。角色权重、感知质量、反应延迟、风险偏好、交战规则和协同纪律构成敌我差异，不给敌机全知路径。

队伍适应通过成员上线/失联/销毁、能力改变、任务完成、威胁出现和信息过期触发重评估，辅以低频刷新。任务分配器根据可行性和能力报价进行稳定分配，使用承诺时窗、切换收益门槛和冷却避免反复换目标。紧急自保可以抢占普通任务。

拦截任务带截止时间和租约，声明预留武器、通道与预计效果；默认减少重复拦截，高威胁或低把握时允许明确的冗余射击。多个射手不会仅凭目标编号相同就认为已协同，必须完成跨机航迹关联。

编队协调器是逻辑任务分配服务，状态属于指定指挥节点；初版先实现一个节点及消息边界。任务、能力报价和成员心跳通过通信送达。断链时各机保持有时限的已知任务并自主防御；恢复后按消息版本和租约对账。指挥节点毁伤时先使用局部自主降级，后续再实现带任期和租约的确定性接替；不在分区时假定全队即时一致。

具体适应例：防空僚机阵亡后，其他机体只有在收到失联/任务超时并具备拦截能力时接管；无合适装备时转为告警与规避。新增队友收到同步后报价分担；敌机增加只扩大已感知候选集，不由敌方真实总数触发全知调度。

## 辐射管制与不确定信息决策

辐射管制是核心玩法，贯穿感知、交战、通信和编队分工。AI 不仅选择打谁，还要决定何时获取更多信息、谁承担暴露风险、已有信息是否足以行动。以下为游戏模型设计，不把物理探测简化成开机即全图公开。

### 探测 身份和暴露分别建模

主动雷达可探测静默机体的回波；被动侦收接收雷达、数据链等辐射。开机显著增加被侦收风险，但对方是否接收到、是否定位、是否识别、是否形成武器解算是不同阶段。静默机体仍可能被主动雷达、热传感器或其他手段发现。波形识别可推测设备类型或平台用途，不能仅凭辐射就无条件判敌；明确敌方专用波形也应受知识库与识别置信度约束。

本机态势保留彼此独立的状态：接触存在、位置与速度不确定性、设备/平台分类、阵营身份置信度、行为与威胁判断。疑似民用、第三方、中立、未知、敌对必须通过任务规则与观测证据处理。实体实际 TeamId 不能直接流入敌我识别 UI 或 AI。

增加 ExposureAssessment：对方可能已发现我、已定位我、已分类或识别我、已形成交战条件四类估计及其证据、时效与不确定性。输入仅限本机发射历史、已知接收威胁、敌方可观测活动、友军报告和明确任务先验；禁止查询敌方内部航迹库。没有告警不代表没有暴露，关闭雷达也不清除对方可能持有的航迹记忆。机动、时间和遮挡改变估计，不直接宣告隐身成功。

### 辐射策略和执行权限

每台机体持有 EmissionPolicy，由角色默认值、编队命令与本机自保权限共同确定。可选策略是严格静默、被动接收、短时定向搜索、周期更新、持续预警、交战支持和紧急自保；这些是配置组合，不是写死的全队统一状态机。

策略分别限制搜索、跟踪、IFF 问询、数据链发送、制导上行和干扰设备。雷达静默不等于无线电静默；加密不等于不可被探测。允许接收友军信息而暂不发送，定向/低占空通信减少风险但不自动免于侦收。首轮只实现设备实际支持的开关、扫描范围和发射周期，功率、频段和波形调整须有对应设备能力。

AI 提交 EmissionRequest，包含设备、用途、方向或目标、允许持续时间、优先级与中止条件。策略检查与设备资源调度通过后才执行；通道冲突返回原因。持续制导任务会声明所需发射窗口，关机请求必须显式选择维持任务、移交或中止，不能悄悄破坏已有承诺。启动、稳定、重捕获和模式切换时间计入行动代价，设置最短保持时间与切换门槛，避免每帧开关。

紧急自保权限采用任务配置：达到预设紧迫性条件可本机打破静默，无须等待断链指挥机同意；严格任务也可禁止自动越权。人工玩家可选择授权自动自保或手动决定。例外必须记录触发依据，不能作为 AI 获得隐藏信息的后门。

### 预警机和发射任务分工

用户设想的初始态势作为场景配置：前出机体默认主动雷达关闭，一到两台后方预警平台承担搜索并通过链路报告。开机机数量属于任务与编队策略，不作为所有场景固定规则；接收端默认静默时，不要求持续心跳回传，成员失效需要承诺窗口和超时推断。

预警职责按传感器覆盖、装备能力、位置、链路和暴露代价分配，可由专用机体或兼任机体承担。友军只有在已知覆盖不足、报告过期或任务失败后，才按权限接替。轮换需要交接与时间窗，不能无通信地瞬间同步。发射任务与扫描调度共用资源分配，主动防空与搜索预警可争夺同一雷达。

评估候选行动时先检查资源、时限和权限，再比较信息价值、防护/任务收益、暴露风险、资源成本和切换代价。首版用可解释的分级风险与证据规则，加效用排序；未经校准的分数不标成精确概率。信息价值至少关联实际需求，例如能否将未知接触分类，或将模糊告警提高到可拦截精度；不以探测数越多越好作为唯一目标。

### 来袭导弹目标推断

目标推断由 ThreatIntentEstimator 维护，输入为观测到的导弹航迹与误差、本机及已知友机运动、导引头辐射特征和经链路到达的报告。禁止读取弹体内部 GuidanceTrackId、目标实体、阵营真值或发射端真实锁定对象。

输出包括可能威胁的自身、已知友机、受保护对象及未知对象，附带接近时间区间、潜在危险范围、信息质量与竞争假设。具备位置速度估计时可使用最近接近几何和若干可行运动预测，考虑导弹继续机动；仅有方位告警时保留宽泛假设，不伪造精确距离和命中倒计时。

接近某架机不等于锁定它，导引头开机也不等于照射者已被锁定。连续观测到与某机机动相关的转向可增加相应假设权重，但共同航路、编队密集和中途变更目标都可能造成歧义。AI 可以主动机动获取区分信息，但该动作不是必然有效的锁定检测器。

是否开机由反事实候选比较决定：保持静默并规避、请求友军观测/拦截、短时定向搜索、自主跟踪拦截、干扰/诱饵、撤离。每项都包含执行时间和能力条件；迫近威胁且外援来不及时可触发紧急自保，尚不紧迫且本机疑似未暴露时可保持静默。AI 不必等到确定被瞄准才防御，也不能因一次告警自动全队开机。

### 新增模块边界

| 模块 | 归属 | 输出 |
| --- | --- | --- |
| IdentityAssessment | 本地态势 | 平台类别、身份假设、置信度、证据 |
| ExposureAssessment | 本地态势与决策支持 | 自身可能被发现、定位、识别、交战的风险估计 |
| ThreatIntentEstimator | 威胁评估 | 导弹可能攻击对象、时间范围、歧义 |
| EmissionPolicy | 指挥意图与平台策略 | 各设备用途权限、持续时间、自保例外 |
| EmissionArbiter | 设备与任务资源调度 | 发射请求的批准、拒绝、抢占与中止结果 |

这些可先作为明确的数据与纯函数模块，并入既有领域实现。它们不各自创建时钟、世界、目标库或装备执行器，不强制增加五个独立系统。

### 阶段增补和验收

P0 加入静默接敌基线，并把新 EMCON 玩法作为独立场景配置；不直接修改旧样例默认行为。P1 的本地态势契约必须支持身份、证据来源和未知状态。P3 的交战执行加入发射权限、持续支持要求和取消反馈。P4 接通信号事件与可观测告警，P5 实现单机身份/暴露/导弹意图评估和自保选择，P6 实现预警任务交接与静默编队协调。

必须新增下列验收：

- 一至两机预警、其余静默，信息共享有时延和误差；敌方不自动获得全编队名单。
- 静默敌机可被主动雷达探测但保持身份未知；民用或第三方辐射不会自动判敌。
- 自机开关雷达不直接知道敌方是否收到，也不清除对方航迹；缺少 RWR 告警仍可保留暴露风险。
- 同一枚导弹在本机观测相同的条件下，隐藏目标字段改变不能直接改变 AI 决策；只有后续可观测行为变化才影响估计。
- 方位告警、粗略友军报告与精确本机航迹触发不同可行行动；近距离紧急自保可按授权打破静默。
- 数据链发送与雷达发射都留下可侦收事件；静默接收不产生虚构辐射；无持续心跳时不凭真值提前判定友军阵亡。
- 预警机失联后按已知信息与超时接替，禁止全队同时无条件开机；带通信延迟时仍避免无限任务抖动。
- 决策日志可解释保持静默、请求支援或开机拦截的依据；玩家界面与 AI 使用相同信息边界，真值仅供隔离的调试视图。

## 呼叫应答与多源身份识别

呼叫是主动获取身份信息的行动，发送者承担位置暴露代价，接收者可以选择应答、延迟、保持沉默或作出许可范围内的虚假声明。身份判断由收到的证据、机体特征数据库和任务情报共同建立，不由单次应答或真实阵营字段直接确定。以下认证与伪装规则为游戏设定，不承诺现实密码学实现。

### 呼叫和回复的完整链路

执行流程为呼叫意图、辐射权限检查、呼叫发射、传播与接收、接收方策略决策、回复发射、回复传播、发送方接收与核验、身份估计更新。呼叫与回复是两次独立传输，各有自己的距离、方向、发射条件、接收质量、干扰影响和超时；呼叫成功不保证回复成功。

按玩法要求，呼叫与应答都产生可泄露发送位置的发射事件。位置泄露范围通过统一信号模型约束：成功截获者获得配置精度的位置线索或定位结果，再通过通信传给其他观察者；不向未截获者全图公开。普通公开呼叫默认采用强位置暴露配置，使由已主动开机的预警平台发起呼叫成为有意义的选择。消息自报坐标与侦收定位证据分开，伪报坐标不能修改发射源的物理事件。

接收方只在实际收到可处理呼叫时执行应答策略。发送方看不到对方的接收结果、随机选择或内部理由：未收到回复可能是对方未听见、设备故障、主动拒绝、回复被干扰、协议不兼容或超时。没有有效回复不能自动标成敌军；任务可将其作为有限的警戒依据，但不能伪装成确认身份。

每轮询问包含会话 ID、消息序号、有效期、协议类型及认证质询关联。重复包去重；同一会话的应答概率只采样一次并维持决策，重试使用原关联，禁止通过连续呼叫反复掷骰快速逼出必然回复。新会话设置冷却、重试预算及累计暴露代价。随机决策采用可重放种子；不同实例可用性格参数提供持续差异。

### 场景和角色可配置的应答策略

ResponsePolicy 是独立数据资产，供玩家自动应答设置、AI 角色与关卡实体引用。编队可以分发临时策略；优先级与到期时间显式记录。处理顺序为设备/协议能力可行性、关卡硬约束、有效指挥与辐射限制、角色规则，再由效用或配置概率选择；允许打破静默的身份回复必须获得明确策略权限。

| 可配置项 | 用途 |
| --- | --- |
| 呼叫方的已知身份与认证状态 | 对可信友军、未知呼叫者、已知敌方采用不同规则；不能读取呼叫者真实 TeamId |
| 接收方角色与行为背景 | 友军、第三方军队、民用、伪装、潜伏等预设；真实所属仅用于配置自身身份与持有凭据 |
| 响应方式 | 总是、从不、条件响应、一次概率采样、交由玩家手动选择 |
| 响应概率和延迟 | 按警戒、任务、暴露、自保或通信状态配置；接收概率与主动应答概率分开 |
| 声明内容 | 呼号、登记号、声称阵营、用途；可真实、有限披露或配置伪装身份 |
| 认证能力 | 支持协议、凭据权限、有效期、应答设备是否可用 |
| 自保与隐蔽条件 | 是否允许为避免误击应答、是否禁止暴露潜伏单位 |
| 超时和重试 | 窗口、重试上限、冷却、撤销时机 |

预设仅作为可编辑起点：友军对有效友军质询高概率认证回复，第三方武装可只声明身份或拒绝认证，民用可按空域规则回复，敌方可沉默或伪装民用。任何阵营都不固定绑定某种行为；场景制作者能覆盖个体与群组策略。角色策略也可随任务阶段变化，变化原因不得泄露给未获知的观察者。

### 身份证据的分层记录

识别按多个轴记录，不压成一条从未知到敌人的进度条：平台类别、型号候选、具体个体候选、声称身份、验证身份、阵营假设、敌意行为及交战许可。确认是军用型号应提高警戒，但不自动确认是敌军，更不自动授予开火许可。

| 证据 | 可以支持什么 | 必须保留的限制 |
| --- | --- | --- |
| 普通自报身份 | 某来源声称自己是谁 | 可以伪装，默认只是声明，不写成已验证友方或民用 |
| 民用应答机制 | 登记与民用身份线索 | 游戏默认较容易模仿；可与外观、航路、数据库冲突 |
| 有效友军认证 | 对特定凭据/权限的高可信验证 | 必须验证当前质询、时效、权限与关联；默认不能靠民用伪装获得 |
| 雷达特征匹配 | 型号、尺寸类别或军用平台候选 | 依赖观测质量、姿态和数据库覆盖；同型可有多个使用方 |
| 电磁特征匹配 | 发射设备、模式与平台用途候选 | 多机可能共享设备，不天然证明唯一机体或阵营 |
| 光电识别 | 外形、装备、涂装、标识等高可信型号或个体识别 | 取决于分辨率、遮挡和可辨特征；同型同涂装仍可能有歧义 |
| 任务情报 | 区域、时间、单位、型号、标识及敌方部署先验 | 记录可信度、有效期和排他性；可能不完整或过期 |
| 可观测敌意行为 | 威胁与交战依据 | 与型号身份分开，按任务交战规则解释 |

友军认证在默认游戏规则中为高可信且难伪造；只有关卡明确赋予的凭据泄露、受控设备等特殊能力才可能通过，不把它设计成普通欺骗概率掷骰。旧回复不能通过重放满足新质询。认证验证成功、认证无效、无法解码、未收到回复必须使用不同结果。

回复还必须与空间接触关联。会话匹配证明有人在响应，不天然证明就是框选的那架机体；借助方位/位置门限、时间与轨迹一致性关联。关联不充分则保留独立无线电接触，不能把第三方插话或转发的合法回复套在未知敌机上。

### 资料库和任务情报匹配

每个阵营或任务装载明确的 RecognitionCatalog，包含设备特征模板、机体外形模板、型号与可能使用方关系，以及获授权的识别资料。玩家和 AI 使用各自实际获得的版本；没有模板时保留未知或宽泛类别，禁止以 prefab 名称、资产 ID 或隐藏型号做完美匹配。新增条目或情报后可以重评估保存的观测。

MissionIntel 是另一个来源：记录情报区域、时段、预计敌方单位、型号、可辨标识、可靠程度与“该型号在此区域是否敌方独占”。特征库回答像什么，任务情报回答这里出现它意味着什么。

用户举例落地：若任务情报明确说明该区域存在敌方 XXX，且可辨标识或可信的排他性条件足够，光电确认 XXX 后可按规则确认敌方；若只知道敌方也使用 XXX，而第三方同样装备，则先成为高警戒的疑似敌方，需要继续核验。关卡作者能配置这两种情况，不能靠型号名称全局绑定阵营。

证据记录来源、时间、质量、来源链和相互依赖。友军转发相同识别报告不增加独立证据数量；同一张光电图像匹配出的外形与涂装不简单当成两次独立确认。证据冲突时保留原因并重新评估，不让最新一条自报声明覆盖全部高质量观测。

### AI 的信息获取选择

IdentityAssessment 输出当前候选、已验证内容、冲突证据和仍需的证据。AI 比较保持观察、公开呼叫、认证质询、请求预警机代询、短时雷达扫描、接近光电识别、请求友军确认等行动的信息收益、时限与暴露成本。

典型流程：预警机发现身份不明接触，前出静默机请求代询；目标声明民用，但电磁特征指向军用设备，则提高警戒并寻求光电证据；光电识别与本区敌方独占的任务情报一致后确认敌方。若问答链路受干扰，则保持未知/疑似并换手段，而非直接归敌。接近光电确认本身的时间与危险也参与决策。

玩家界面应展示“自称民用”“友军认证通过”“型号已识别，阵营未明”“依据任务情报确认敌方”“应答未收到”等语义，并能查看关键证据。身份状态与攻击许可分别显示；调试视图可以对照真值，但不能将真值混入正常界面或 AI。

### 集成位置与阶段验收

询问应答协议挂在已有通信消息通道上，接收与发射服从 DataLink 和 EmissionArbiter；ResponsePolicy 由角色/任务数据驱动。会话状态由平台拥有的 IdentificationService 管理；证据归本地态势的 IdentityAssessment；RecognitionCatalog 与 MissionIntel 为数据资产。无需建立第二套通信、目标库或实体注册系统。

P1 为本地态势补齐声明、验证身份、来源与关联字段；P2 增加询问/应答设备能力；P3 接入辐射许可与协议会话；P4 验证干扰下双向投递及特征量测；P5 实现响应策略和信息获取决策；P6 接入代询、协同识别与报告来源去重。基础呼叫和认证可先于完整光电实现，光电能力未完成时必须明确标注不可用，不用目标真值填充占位结果。

验收包括：友军/第三方/民用/敌方策略可由同一套数据配置；呼叫成功但回复丢失；呼叫本身未送达；伪装民用不能得到友军认证；截获旧回复无法满足新会话；重复呼叫不无限重掷概率；无模板不能准确识别；第三方同型号不自动归敌；可信排他情报加有效识别可以确认敌方；无关机体回复不错误绑定；同一报告多次转发不重复加信；正常界面不能显示对方实际拒绝理由。

## 行为扩展 状态所有权与冲突裁决

采用明确状态、事件触发的重评估、可组合的行为候选、统一资源裁决和小型执行状态机。条件分支仍可用于局部规则，但不得在各系统 Update 中直接触发互相竞争的世界动作。先用少量类型和显式注册实现，不以通用脚本语言或任意事件总线替代边界。

### 状态与触发的职责

| 内容 | 存放位置和写入者 | 使用方式 |
| --- | --- | --- |
| 观测与身份、暴露、威胁估计 | 各自评估模块写入本机态势 | AI 读取带版本与时效的只读快照 |
| 弹药、温度、冷却、工作模式 | 设备或资源运行时唯一写入 | 行为只查询和申请，不直接改字段 |
| 任务、角色、辐射授权 | 有来源、版本和有效期的策略/任务状态 | 作为行动约束与评分参数 |
| 正在执行的行为 | BehaviorInstance 的生命周期状态 | 记录阶段、承诺、取消原因与超时 |
| 呼叫决策、目标偏好等记忆 | 归属明确的行为记忆 | 限定作用域、目标代际、有效期及重置条件 |
| 新威胁、报告到达、装备失效 | 有序事件队列中的已发生事实 | 标记相关决策需要重算，不在订阅回调中直接开火 |

不引入任何组件都能改的全局 bool 黑板，例如 isEnemy、shouldFire、radarMustOn。衍生结论由其唯一评估器维护；若缓存，必须绑定来源版本并有明确失效条件。关卡设定是另一类有来源的先验或约束，不能直接覆盖观测记录。

普通态势变化按相关依赖触发重评估，并有低频周期兜底。紧急威胁或装备失效进入更短的有界处理通道，在统一命令阶段裁决，不由任意回调立即改世界。最大反应延迟必须低于对应设备的反应预算，并通过场景测试测量。每帧不为全部目标重算全部行为；目标规模和候选数设可观测预算。

### 行为定义与注册

每种行为提供稳定 BehaviorId、参数配置及以下契约：读取哪些上下文；何时可生成候选；需要哪些能力；估计收益、风险和最晚完成时间；申请哪些资源；怎样开始、更新、取消或完成；可被打断的阶段与恢复规则；执行反馈和调试理由。

候选生成和可行性/评分计算只读快照，不发射、不扣弹、不切雷达、不修改身份。通过筛选的候选形成 ActionProposal，携带来源、上下文版本、目标引用、授权等级、时限、资源需求、替代方案及稳定排序键。真正执行只能发生在裁决通过后。

新增同类行为变体只增加参数资产；新增行为机制增加实现并显式注册到对应能力/行为目录，不修改 AI 主循环中的型号 switch。注册表支持校验重复 ID、缺失能力、无退出条件、无界重试和非法资源申请。通用大枚举不承担插件机制，能力仍使用有类型的契约。

示例“请求预警机代询”：读取未知接触、通信可用性、已有询问会话和自身暴露；申请发送窗口；发送后等待相关报告；超时提供有限重试或本机观察候选。加入此行为不要求修改近防炮、导弹和其他身份识别行为。

### 统一优先级和资源裁决

先硬约束、再策略授权、再紧迫性分层、最后同层效用比较。硬约束包括设备损毁、物理不可行、失效引用、资源不足和不可违反的交战规则，任何高分都不能突破。自保打破静默属于预先配置的策略例外，不是突破物理或认证规则。

建议的默认排序层为：设备安全停机/取消失效执行由运行时保障；获授权的紧急自保与紧急护卫；需要维持的有时限任务承诺（例如在飞弹制导）；当前主要任务；机会行动与维护。层级可由场景政策明确调整；进攻/防空角色通常调整同层效用与资源保留，而不能任意把行为自报成最高优先级。

层级内比较剩余时间、任务收益、威胁/暴露风险、信息价值、资源成本和切换代价，采用有界归一化评分，输出分项理由。同分按既定承诺、截止时间和稳定 ID 裁决，不能依赖 MonoBehaviour 更新顺序或集合遍历顺序。关键任务必须有超时、容量或抢占规则，不能永久占用资源；老化加分仅用于非紧急同层任务，不能让普通扫描熬成高于自保。

平台 ActionArbiter 是命令接纳与资源预留的唯一提交入口。EmissionArbiter 作为其中的辐射策略/时隙检查模块，EngagementPlanner 提供可行性和火控评估，设备控制器提供能力检查；它们不各自最终下命令。编队分配器只提供带来源的任务，不能越过本机裁决器直接操纵设备。

资源按实例与用途建模：运动控制权、机体朝向/瞄准约束、每件设备的执行槽、雷达驻留预算、天线时间窗、数据链发射窗口、FCS 通道、弹药与电力预算、必要的表现通道。允许互不冲突的行为并行；共享资源按容量分配。先提供简单可解释的有序选择与全量资源包检查，不求解通用最优化问题。

复合行动申请所需资源包，一次通过或拒绝，禁止占着一半资源无限等待另一半；支持明确的分阶段短期预留和租约。提交时重新检查状态版本及前置条件，过期方案撤销重算。执行器拥有实际状态，收到有效命令时再次核验关键条件；资源预留与扣费不得被分别当成两次消耗。

### 并行 冲突与打断示例

| 同时发生的行为 | 裁决 |
| --- | --- |
| 被动侦收、飞行、接收友军消息 | 资源允许时并行，不因一个主要任务停掉所有能力 |
| 广域搜索和精确跟踪 | 同一雷达按预算调度；能力不足则降频、暂停或拒绝低优先级请求 |
| 维持静默和主动拦截 | 先检验自保/护卫授权；可越权则在辐射预算中明确占用，否则寻找被动防御等替代 |
| 原有导弹支持和紧急自保 | 比较任务层级与时间；抢占必须取消/移交原支持承诺，并把真实断链反馈给在飞弹 |
| 规避机动和炮塔/机体瞄准 | 检查射界及姿态兼容；可兼容则并行，不可兼容则暂停射击或选择其他装备 |
| AI 机动和玩家手动操控 | 普通 AI 不争夺玩家控制权；辅助或紧急接管只在玩家明确配置允许时生效 |
| 两行为请求同一武器 | 武器实例只有一个有效执行租约；其他请求排队、换装备或被拒绝 |
| 多个观察者建议不同身份 | 保留来源证据，由身份评估器更新结论；事件到达顺序不直接覆盖身份 |

行为生命周期统一为 Proposed、Reserved、Running、Cancelling 以及 Succeeded/Failed/Cancelled/Expired 终态。执行阶段可标记可立即取消、需安全点取消或当前原子动作不可逆。紧急机动不必等待不相干的长动画结束；不可中断区间仅包围真正不可逆的提交动作。

取消是一等接口：释放设备与通道、撤销未提交资源、解除任务租约、停止后续重试、报告原因。已经发射的弹体不因发射行为取消而消失，已花费资源不回滚；后续支持是否继续由显式规则决定。暂停后恢复须重新确认航迹、射界、资源和授权，不能恢复旧快照后直接发射。

防抖包括进入/退出阈值分离、最短保持时间、切换收益门槛、冷却和失败退避。紧急事件可绕过普通保持时间，但不能反复重启同一不可行方案；新证据或能力变化才解除相应失败抑制。

### 可扩展规则与事件反应

新增判定条件通过有类型的条件/评分项组合，如“信息过期”“有远程指示能力”“暴露风险较高”。条件树只读，不允许回调随意改世界；序列化规则不直接调用任意对象方法。核心可行性、身份认证和命中结算保持类型明确的代码，编辑器开放阈值、策略和组合。

新增反应应监听事实并生成候选。例如 WeaponFired 后热模块更新热状态，表现播放特效；ThreatUpdated 后 AI 重评估自保；PartDisabled 后能力目录更新并取消依赖行动。热源等事实消费者按明确系统阶段运行，可更新自己拥有的状态，不得递归触发另一串直接开火调用。

事件包含实例代际、命令/会话关联、序号、仿真时间和来源。语义要求单次生效的消费者去重；动画发射标记同样去重。每个阶段消费稳定队列快照，新生成事件在规定的后续阶段或下一 Tick 处理；限制重入与事件环。紧急响应的允许延迟显式定义，不能用随意递归派发解决。

规则解释器只处理已注册的有限节点；不为每个新增部件复制状态机，也不把所有行为塞进一个无限增长的全局状态机。装备生命周期、平台行为和编队任务各有自己的状态范围，通过命令和反馈协作。

### 现有行为图的定位

AC6 导入行为图用于动作语义和表现兼容，不成为战术决策器。统一动作选择器消费已接受的运动/装备状态，裁决全身与局部层播放。现有 PlayerRig 中补丁覆盖策略先原样收进该选择器，再逐个替换，避免图状态、玩家脚本、动画播放器同时争夺全身动作。

### 验收与落地约束

P1 定义状态所有权、命令来源、时间与版本约定；P2 定义设备能力和资源描述；P3 必须交付共同裁决入口、动作生命周期、预留/取消/幂等反馈以及辐射检查插件；P5 才在该执行基础上增加候选生成和效用选择；P6 的编队任务不另建执行路径。

调试器对一次决策展示候选、被拒原因、分项评分、冲突资源、胜出行为、抢占对象、执行结果及所用证据版本。参数作者可以验证策略覆盖来源，不能只能看到一个最终 priority 数字。

必须验证：调换行为注册顺序不改变同输入结果；同 Tick 多发射请求不重复扣弹；旧动画事件不能触发新一轮发射；资源包竞争不死锁；暂停恢复前重新校验；高优先级仍不能突破物理与硬规则；不冲突动作并行；断链/毁伤取消释放全部相关租约；威胁阈值附近不反复开关机；不存在通过回调绕过裁决器的世界动作。

扩展演练要求新增“预警机代询”行为、“节制发射”评分项和一种八槽机角色配置，均不修改 AI 主循环或已有行为内部逻辑；新增真正设备机制允许增加对应执行模块，但同样遵守统一裁决与生命周期。

## 九 渐进实施顺序

每阶段以可独立回退的变更集交付。阶段验收失败时停止扩大迁移范围；不要把旧模式静默回退藏在正式执行路径中。

| 阶段 | 具体交付 | 通过条件 | 保护与回退 |
| --- | --- | --- | --- |
| P0 建立基线 | 确认可用玩家场景、冻结样例配装和数值、记录输入/种子/发射事件；列出脚本与序列化引用 | Unity 编译、现有 EditMode 测试结果明确；驾驶、雷达、枪炮、导弹、告警、热像、动画人工基线可复现 | 不改玩法；发现已有失败先登记，不能声称重构前全绿 |
| P1 生命周期和多机身份 | PlatformFactory、EntityRegistry、各平台 CombatContext；替换固定传感器/终端身份；抽出演示装配 | 两台相同配装同时扫描互不覆盖；生成销毁重生不复用旧句柄；导弹脱离发射机生命周期 | 旧控制器作为薄适配器；独立新验证场景，保留基线场景 |
| P2 可变插槽和能力 | 数据模型、旧资产转换、装配校验、按槽位列表生成 UI、能力快照 | 4 槽和 8 槽共用装配执行；左右互换可兼容武器；追加防御槽；父挂架依赖有效 | 转换副本先验收；不批量重写全部现有资产 |
| P3 统一装备执行 | 武器实例状态机、统一行动裁决、辐射权限检查、资源预留、取消与幂等反馈；迁出 PlayerRig 肩部逻辑；弹体和导引头解耦 | 相同输入下玩家/AI 发射事件一致；开盖/取消/拒绝不多扣弹；8 槽并行受实际资源约束 | 保持原始数值与动画时序；逐一迁移步枪、炮、导弹 |
| P4 信号与防御 | 统一热源、伤害区域与响应管线；一个主动拦截模块、一个反应装甲模块 | 导弹燃尽在热像与 IR 同源变化；近防能拦截可解算威胁；反应装甲按区域消耗一次 | 现有整机 HP 模式作为明确配置保留；新增防御不改变旧配装 |
| P5 共享平台 AI | 只读候选生成、角色配置、身份/暴露/意图评估、分层优先级与效用选择、标准命令输出 | 同一机体切换进攻/防空；换武备后自动调整；未知目标不凭真值追踪；友敌共用执行 | 先使用静态任务单机验证，再接协同；旧靶机留为测试夹具 |
| P6 编队适应 | 跨机航迹关联、消息式任务分配、租约、成员心跳、重分配与断链降级 | 增减友敌、毁伤防空机、耗尽弹药、断链和恢复；可解释的接管或降级，无无限抢任务 | 先两机再扩规模；指挥节点接替作为独立子阶段验收 |
| P7 收尾与扩展演练 | 统一动作策略；删除迁移完的旧权威路径；收窄 UI、数据桥；依赖检查与性能预算 | 新增八槽变体和既有机制武器主要改数据；无演示依赖；完整回归与稳定性能 | 删除前检查场景 GUID 引用；按阶段基线回退，不恢复双写 |

P1 是多机基础，P2 是装备扩展基础，P3 是防空和 AI 的共同执行基础。P4 与 P5 可在 P3 稳定后分别开发，但集成必须分别验收；本提案不要求并行代理开发。P6 必须建立在本地感知隔离和共享 AI 已可用之上。

## 十 验收场景和不变量

| 场景 | 核心验收 |
| --- | --- |
| 原始玩家样例 | 运动、镜头、导航重置、QB/AB、射击动画与 HUD 保持基线；不改变数值平衡 |
| 两台同类机体 | 传感器身份独立；玩家 A 的锁定不改 B；销毁 B 不解除 A 的注册 |
| 八武器槽机体 | 无第 5 槽起失效或默认映射左手；武器组、射界、弹药和通道分别正确 |
| 武器拆换与毁伤 | 能力目录更新；取消失效动作，释放资源；AI 不继续选择已拆除设备 |
| 玩家和 AI 同命令 | 都经过许可和部署时序；事件一次；没有 AI 专用无条件发射捷径 |
| 友军防空 | 可保护自己或指定队友；无精确航迹时拒绝不可行拦截并说明原因 |
| 装甲命中 | 受击区域与方向生效，单元只消耗一次；不相关区域不触发 |
| 传感器对抗 | 辐射/干扰/遮挡影响量测，进而影响航迹与开火；不直接写锁定布尔值 |
| 动态编队 | 友军退出、敌方新接触出现、弹药耗尽后重分配；信息受链路时效约束 |
| 断链与发射机毁伤 | 中段依记忆/失效规则处理，独立末制导可继续；过期任务和报文不复活 |
| 热源一致性 | 开火、推力、燃尽改变共同状态，渲染与探测各自换算但不独立维护事实 |

纯算法与契约使用 EditMode 测试；组件生命周期、动画事件、实例装配使用 PlayMode 测试；手感和视觉用基线试玩。确定性断言限于相同输入与种子的纯仿真部分，Unity 物理和画面比较采用基线测得并记录的容差。CPU、GC、活动设备/航迹/弹体数量随场景记录；分配器和搜索按预算分频，容量超限必须可观测而非静默丢失。

建议压力阶梯为 2、8、16 台平台逐步增加武器和导弹，具体通过门槛由 P0 的目标硬件与帧预算确定，不预先承诺规模。每阶段追踪漏掉的注册、悬空句柄、重复发射、过期任务、分配抖动和仿真超时。

## 十一 完成标准

新增兼容槽位、同机制武器、普通机体变体或角色配置，不修改玩家控制、AI 主流程和现有武器的分支判断。新增真正机制只在对应能力模块、数据与表现适配中实现，并补针对性验证。

正式场景不依赖 Showcase 创建运行组件；雷达不管理导弹全部生命周期；玩家控制不管理装备状态机；显示不生成作战状态；编队不直接读取敌方真值。扩展性通过上述实际变体和多机场景证明，不能以类数量或接口数量代替验收。

第一批实施范围限定为 P0 和 P1：建立可靠基线、抽取公共装配、统一实体身份、隔离每台机体感知上下文。武器、插槽和 AI 的大规模迁移在这个地基通过验证后开始。
