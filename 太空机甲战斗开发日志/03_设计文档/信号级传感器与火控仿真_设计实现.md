## 1. 设计目标与拟真边界

### 1.1 目标

建立一套火控与感知完全基于模拟接收数据工作的传感器系统：

- 雷达按驻留（dwell）为单位发射与接收，扫描具有真实时序。
- 回波受距离、姿态 RCS、遮挡、噪声与干扰影响，测量误差随信噪比变化。
- 接收器产生检测点，跟踪器建立航迹，火控只消费航迹。
- 光电、告警、电子战、数据链共用同一套观测/航迹数据通路。
- 火控、AI、UI 在编译层面无法访问目标真实状态。
- 全链路确定性可重放。

### 1.2 拟真边界（明确声明的近似）

| 项目 | 决策 | 理由 |
| --- | --- | --- |
| 电磁场求解 | 不做 | 波长量级网格在实时下不可行 |
| 逐脉冲仿真 | 不做，合并为驻留 | 脉冲重复频率级更新无玩法收益 |
| 距离-速度单元/CFAR（旧文档层级二） | **永久不做** | 同分辨单元遮盖用测量空间贪心合并做玩法等效的工程近似（见 10.6 及其声明边界）；雷达显示颗粒感是表现层 shader 职责 |
| 多普勒盲区（notching） | **不做** | 太空无地杂波，脉冲多普勒无理由设盲区。防守对抗权重转移到 RCS 姿态、遮蔽物、干扰、诱饵 |
| 红外物理一致性 | 偏离物理 | 3K 深空背景下 300K 机体物理上无法隐身。"冷目标探测距离"是玩法数值，设定解释为传感器视场内结构热源/恒星造成的对比度限制。调参时禁止用黑体辐射公式"修正"该数值 |
| 多径 | 一次反射，仅大型结构附近，后期阶段 | 收益低于成本 |

## 2. 总体架构

三个彼此隔离的世界，依赖单向：

```text
┌─ 真实模拟世界（双精度，唯一运动权威）──────────────┐
│  SimKinematics 积分器 / 签名状态 / 发射事件 / 遮挡几何   │
│  只有仿真层（测量生成器）可读                          │
└────────────────┬──────────────────────────┘
                 │ 驻留任务 → 测量结构体流（纯数据）
                 ▼
┌─ 感知世界 ────────────────────────────────┐
│  检测点 / 本机航迹 / 共享航迹 / 告警 / 火控解算          │
│  AI、火控、武器、UI 只能读这一层                       │
└────────────────┬──────────────────────────┘
                 ▼
┌─ 表现世界 ────────────────────────────────┐
│  GameObject / 渲染 / 特效 / HUD / 浮动原点            │
│  只消费，不产生任何模拟输入                            │
└───────────────────────────────────────────┘
```

真值防火墙的执行方式：目标真实状态只在测量生成阶段被读取（该阶段扮演"物理定律"角色），产出的 `Measurement`/`Track` 结构体中不允许出现 `SimEntityId`、GameObject、阵营等真值字段，由 asmdef 依赖方向（见第 5 节）在编译层面强制。

## 3. 运动与坐标权威（本文档最高优先级决策）

### 3.1 决策

**机体运动权威 = 双精度自定义积分器，PhysX 不参与飞行。**

理由：交战包线 50–100 km、交会速度 km/s 级。PhysX 为 float，浮动原点以玩家为中心时远端实体坐标精度约毫米~厘米级且积分不确定；而本游戏为真空环境，运动方程只有推力+扭矩，半隐式欧拉即为完整解。自定义积分器同时获得：双精度、跨平台 bit 级确定性（PhysX 无法提供）、与传感器/火控共用同一坐标系。

### 3.2 SimKinematics

```text
状态：positionWorld double3（米）
      velocityWorld double3（米/秒）
      rotation      quaternion（双精度或高精度归一化 float）
      angularVelocity float3
积分：半隐式欧拉，固定 100 Hz
      v += (F/m) * dt;  p += v * dt
      ω += (τ·I⁻¹) * dt; q = normalize(q + 0.5·ω⊗q·dt)
输入：推进系统提交合力/合扭矩（受能源与热量系统仲裁后的实际值）
```

- 所有传感器、航迹、火控、导弹数学在双精度世界系进行。
- 质量随推进剂/弹药消耗实时变化（读机体运行状态值）。

### 3.3 PhysX 的保留职责

| 职责 | 范围 |
| --- | --- |
| 结构碰撞事件检测 | 玩家气泡内的 kinematic 镜像碰撞体，每物理帧由积分器单向写入 |
| 近距武器射线/触碰体积 | 气泡内 |
| 近距精细遮挡 | `RaycastCommand`，仅气泡内复杂几何 |

PhysX 碰撞体永远是 kinematic 的、由积分器驱动的镜像；禁止任何系统向 Rigidbody 施力。碰撞响应（撞毁、弹开）作为事件回传给积分器处理。

### 3.4 浮动原点与坐标服务

- 浮动原点只属于表现世界。`FloatingOriginService` 维护 `originWorld double3` 与 `revision` 计数。
- 唯一转换入口：`RenderLocal = (float3)(positionWorld - originWorld)`。禁止任何模拟代码存储 float 局部坐标。
- 原点切换发生在 Tick 边界：暂停一轮 PhysX 射线提交，双精度世界不受影响。

### 3.5 关联修订

`飞行与机动设计.md` 中"使用 Unity Rigidbody 作为物理基础"一条按本节修订：Rigidbody 降级为碰撞感知外设。辅助飞控的输入输出对象改为 SimKinematics。

## 4. 时间与调度

### 4.1 时钟

统一时间类型 `double simTimeSeconds`。

| 时钟 | 频率 | 内容 |
| --- | --- | --- |
| 运动 Tick | 100 Hz | SimKinematics 积分、热量/能源结算 |
| 传感器 Tick | 25 Hz | 驻留消费、检测生成（内部各传感器再按驻留时刻细分） |
| 融合 Tick | 25 Hz | 航迹关联、滤波、数据链消费（滞后时钟，见 15.2） |
| 表现 | 渲染帧 | 航迹外推显示、HUD、雷达画面 |

驱动方式：场景级 `SimulationDriver` 在 `FixedUpdate` 累加真实时间，`while (accumulator >= step)` 执行 Tick；每帧设最大补算数，超出记性能告警，不静默降频。

### 4.2 驻留调度（雷达扫描的时序语义）

扫描不是"每 Tick 把视场全算一遍"，而是**离散驻留序列**：

```text
扫描任务 = 波束位置序列 [b0, b1, ... bn]，每个驻留占 dwellTime 秒
传感器状态机维护：当前扫描图样、当前波束索引、下一驻留到期时刻
传感器 Tick：消费 simTime 已到期的驻留（一个 Tick 可能消费 0~k 个）
每个驻留：只处理该波束锥内候选 → 生成检测点，时间戳 = 驻留时刻
```

由此免费获得：

- RWR 的离散扫掠告警（spike）时序正确——波束扫过接收机的那个驻留才产生发射事件命中。
- 雷达显示的扫描线逐格刷新。
- 检测点时间戳精确到驻留时刻，滤波 Δt 正确。

计算总量与批量模型相同（相同的候选对/秒），只是摊开在时间轴上。

驻留到期队列按优先级处理，超预算时低优先级驻留顺延（航迹年龄如实增加，不伪造刷新）：

```text
导弹末制导 > 单目标跟踪 > 导弹中段支援 > 告警确认 > 跟踪扫描 > 广域搜索
```

### 4.3 工作模式与驻留图样

| 模式 | 图样 | 驻留特征 |
| --- | --- | --- |
| 静默 | 无 | 无发射事件 |
| 广域搜索 | 光栅扫描覆盖方位×俯仰 | 短驻留、低精度 |
| 定向搜索 | 提示区域小光栅 | 中驻留 |
| 跟踪扫描（TWS） | 光栅 + 对已有航迹插入跟踪驻留 | 搜索/跟踪驻留混排 |
| 单目标跟踪（STT） | 波束持续压在预测方向 | 长驻留、高刷新、高暴露 |
| 导弹支援 | STT + 数据链上行驻留 | 占用制导通道 |

模式切换即更换驻留图样生成器，功耗/产热/暴露随驻留密度自然变化。

## 5. Assembly 与目录

```text
ACunicombat.Simulation.Core      // 数学、Handle、时钟、内存。不引用 UnityEngine 场景对象
ACunicombat.Sensing.Contracts    // 纯数据契约：Measurement、TrackSnapshot、EW 注入缓冲、告警观测。
                                 // 只引用 Core；不含任何场景引用，结构体中禁止出现 SimEntityId
ACunicombat.Simulation.Kinematics// 双精度积分器（运动权威）
ACunicombat.Simulation.World     // 实体注册表、快照、空间索引、遮挡几何、签名状态
ACunicombat.Sensors              // 驻留调度、传播、接收、检测生成（唯一可读 World 真值的消费层）
ACunicombat.ElectronicWarfare    // 干扰注入、发射事件、诱饵
ACunicombat.Tracking             // 关联、滤波、融合。纯 C# 数学
ACunicombat.FireControl          // 解算、武器接口
ACunicombat.Presentation         // HUD、雷达显示、浮动原点
ACunicombat.Editor               // RCS 烘焙、配置校验、调试工具
ACunicombat.Tests.EditMode / PlayMode
```

asmdef 引用关系（箭头 = "引用"，非数据流；数据经运行时缓冲传递，由顶层 SimulationDriver 装配）：

```text
Sensing.Contracts   → Core
Kinematics          → Core
World               → Kinematics, Core
Sensors             → World, Sensing.Contracts, Core
ElectronicWarfare   → Sensors, Sensing.Contracts, Core     // 单向引用 Sensors，无环
Tracking            → Sensing.Contracts, Core               // 不引用 World/Sensors —— 防火墙
FireControl         → Tracking, Sensing.Contracts, Core
Presentation        → Tracking, FireControl（只读快照）
```

规则红线：

- `Tracking` 与 `FireControl` 不引用 `World`、`Sensors`——真值防火墙由此成为编译错误。Sensors 产出 `Measurement`（定义在 Contracts），Tracking 只从运行时缓冲消费，两者无编译依赖。
- EW 对接收链的影响通过 Contracts 中的注入缓冲（干扰功率场、合成检测点队列）传递：EW 写、Sensors 读，引用方向单一。
- `Measurement`、`TrackSnapshot` 等契约结构体物理上无法包含 `SimEntityId`（Contracts 不引用 World，类型不可见）。标识符类型的定义程序集见 6.1 的归属表——该表是本条声明成立的前提。
- 编译防火墙防不了语义走私：Core 中的通用 `Handle` 机制对 Contracts 可见，实现者技术上可以塞一个裸 Handle 字段偷渡实体身份。这一层靠 code review 纪律与 22.1 真值对照面板的审计守住，文档明确承认此边界。
- 调试真值对照走 `Editor`/`Presentation` 专用通道，发布构建剔除。

## 6. 核心数据模型

### 6.1 标识符

全部为 `Handle = Index(24bit) + Generation(8bit)`，注销递增 Generation。定义程序集归属（强制，asmdef 防火墙依赖此表）：

| 类型 | 定义程序集 | 理由 |
| --- | --- | --- |
| `SimEntityId` | **World** | 真值标识，对 Contracts/Tracking/FireControl 类型不可见 |
| `SensorId`、`EmitterId` | Contracts | Measurement 与发射事件缓冲需要 |
| `PlatformId`、`TrackId`、`NetworkTrackId` | Contracts | TrackSnapshot 与数据链消息需要 |
| 通用 `Handle` 基础设施 | Core | 各具体类型为独立 struct 包装，互不隐式转换 |

`TrackId` 与 `SimEntityId` 无任何映射关系暴露给感知层。

### 6.2 热路径结构体（blittable，NativeArray 存储）

禁止：string、托管数组、接口、委托、UnityEngine.Object、嵌套 Native 容器。

**Measurement（检测点）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| sensorId | SensorId | 来源 |
| timestamp | double | 驻留时刻 |
| range | float | 米；光电为 NaN |
| direction | float3 | 世界系单位向量 |
| radialVelocity | float | 米/秒；无多普勒能力时 NaN |
| losRate | float3 | 视线角速率向量 Ω（世界系，rad/s）；光电跟踪与导引头的原生测量量（见 11、17.2），无此能力时 NaN |
| rangeVar / angleVar / velocityVar / losRateVar | float | 测量方差 |
| snrDb | float | 信噪比 |
| flags | uint | 饱和/疑似杂波/受干扰/被动 等可测状态 |

不含真实目标 ID、阵营、"是诱饵"等真值标签。

**Track（航迹）**

| 字段 | 类型 |
| --- | --- |
| trackId / ownerPlatformId | Handle |
| state | double3 位置 + double3 速度 |
| covariance | 6×6 对称阵（存上三角 21 个 double） |
| confidence / classification / identityConfidence | float |
| lastUpdateTime / lastPredictTime | double |
| coastCount / hitCount | int |
| sourceMask | uint（雷达/光电/ESM/数据链位） |
| consistencyScore / interferenceScore | float |
| lifecycle | enum：Tentative / Confirmed / Coasting / Degraded / Dropped |

## 7. 世界快照与双缓冲

- 每运动 Tick 结束，积分器状态写入**写缓冲**；传感器 Tick 开始时交换读写缓冲。
- Jobs 只读快照缓冲，主线程只写写缓冲，无锁。
- 快照携带 `snapshotTime`，所有由该快照生成的测量时间戳 = 驻留时刻（由 snapshotTime 与驻留偏移推得），滤波器据此推进——**测量因果时间以生成快照为准，不以消费帧为准**。

## 8. 空间索引与遮挡

### 8.1 索引

双层：

- 全域稀疏哈希网格：双精度坐标，单元 10 km，实体注册 1~2 格；波束查询 = 波束锥包围体遍历相交单元 → 距离筛 → 波束点积筛。
- 大型结构局部：进入表现气泡后的复杂几何交给 PhysX broadphase。

### 8.2 遮挡

| 距离 | 方法 |
| --- | --- |
| 全域 | 双精度解析几何：球（小行星）、胶囊（站体）、OBB（舰体）。每候选对做线段-几何求交 |
| 气泡内 | `RaycastCommand.ScheduleBatch`，专用 `SensorOccluder` 层，取最近命中 |

遮挡缓存：键 `SensorId+TargetEntityId+OccluderRevision`，任一方位移超阈值失效；导弹级速度不缓存。

碎片云不做实体遮挡：作为区域体积记录密度/平均 RCS/温度分布，候选对穿越时按路径长度增加杂波功率与随机假检测率（见 10.4）。

## 9. 签名系统

### 9.1 方向性 RCS（与装配管线对接）

- **烘焙时机：`MechAssembler` 装配完成时**，对装配结果整机烘焙，不按预制机体。
- 方法：低模深度渲染 16 方位 × 8 俯仰，投影面积 × 材质权重 → 128 样本球面表（float 数组）。烘焙耗时目标 < 100 ms，装配界面异步执行。
- 运行时：雷达→目标视线转目标本地系，双线性插值；乘性修正：损伤 × 武器/散热器展开 × 波段。
- 表存入装配结果资产；武器挂载变化触发重烘焙。

### 9.2 热区

第一版两个热区：推进（主推+姿态）、全机（发电/武器/电子战归并）。

```text
热能变化 MJ = (产热 MW − 散热 MW) × dt
温度 = 基准 + 热能 / 等效热容量
红外辐射强度 = f(温度, 可见面积, 朝向) —— f 为玩法标定曲线，非黑体公式
```

热区间固定热导连接图（装配时生成），散热器展开状态与朝向作为散热乘性修正。扩展到四热区（+散热器、+武器）时结构不变。

### 9.3 发射特征

所有主动发射（雷达驻留、干扰、数据链、导引头、激光）写入**发射事件环形缓冲**：

| 字段 | 说明 |
| --- | --- |
| emitterId / ownerEntityId | 来源 |
| startTime / endTime | 驻留或连续区间 |
| origin / direction / beamWidth | 双精度几何 |
| frequencyBand / waveformId / emissionType | 识别与欺骗匹配用 |
| mainlobePowerDb / **sidelobeLevelDb** | 主瓣有效功率与旁瓣电平（主瓣 −30 dB 量级，装备数值） |

旁瓣电平是显式装备参数：告警接收机在主瓣外仍可能以旁瓣功率收到信号（近距离才够门槛）。"RWR 只听主瓣还是含旁瓣"由数值决定，不焊死在代码里。

## 10. 雷达管线

### 10.1 单驻留处理流程

```text
驻留到期 → 波束锥候选筛选（索引 + 点积）
        → 遮挡判定（解析 + 气泡内射线）
        → 逐候选：RCS 查表 → 对数域雷达方程 → SNR
        → 干扰/杂波功率注入（读取 EW 已写入的注入缓冲，见 13；无回调）
        → 检测判决 + 测量生成
        → 分辨率合并（10.6）
        → 检测点入环形缓冲，登记发射事件
```

### 10.2 对数域雷达方程

信号动态范围跨十几个数量级，内部一律 dB：

```text
接收功率dB = 发射功率dB + 2×天线增益dB + 20·log10(λ) + RCSdB
           − 40·log10(r) − 系统损耗dB + 积累增益dB(驻留时间)
SNRdB = 接收功率dB − 10·log10(噪声 + 杂波 + 干扰)   // 分母先线性求和再转 dB
```

多信号叠加必须在线性域求和或用 Log-Sum-Exp，禁止直接加 dB 值。第一版用归一化标定（参考探测距离反推常数项），变量关系保持完整。

### 10.3 检测判决

```text
Pd = smoothstep(门限低dB, 门限高dB, SNRdB)   // S 曲线，无硬边界；参数序为 (edge0, edge1, x)
掷骰：确定性 RNG（见 21），Pd 比较决定是否出检测点
```

### 10.4 测量误差模型

| 量 | 误差公式 |
| --- | --- |
| 距离 σr | 距离分辨率 / √(2·SNR线性) ，下限 = 分辨率/10 |
| 角度 σθ | 波束宽度 / (1.6·√(2·SNR线性))（单脉冲近似） |
| 径向速度 σv | 速度分辨率 / √(2·SNR线性) |

虚警：每驻留按泊松小概率生成假检测点（均匀分布于该波束的距离/速度范围）；碎片云内虚警率按穿越路径长度提升。

### 10.5 无多普勒盲区声明

不实现任何径向速度门限丢弃。横向机动的对抗价值来自：RCS 姿态面（侧面小截面）、脱离旧预测区域、配合遮蔽物断照射。实现者不得从空战惯例引入 notch。

### 10.6 分辨率合并（取代旧文档层级二）

同驻留内检测点在**测量空间**合并：

```text
判据：|Δr| < 距离分辨率 ∧ |Δθ| < 角分辨率 ∧ |Δṙ| < 速度分辨率
      —— 仅在本传感器具备的测量维度上评估（见下方字段有效性规则）
合并：r、ṙ、losRate 按 SNR 线性加权；direction 加权求和后归一化；
      SNR 线性相加；方差按混合方差公式合成（见下）；flags 并集
次序：检测点先按 SNR 降序排序，贪心聚类（高信噪比者为簇核）——
      消除两两合并的次序依赖，且结果确定
```

**字段有效性规则（强制）**：NaN 参与比较恒为 false，若不处理，无多普勒雷达将永远无法合并。

- 合并判据只在**该传感器能力掩码**声明的维度上评估：无多普勒能力则 |Δṙ| 项不参与判据（视为满足），依此类推。同一驻留内真实检测点的有效维度由传感器能力唯一决定，彼此一致。
- EW 合成假目标（13 节）在注入时**必须按被注入传感器的能力掩码生成字段**：能力外的字段填 NaN，能力内的字段必须有效；不满足者在注入口拒收并计数。由此合并阶段永远不会遇到维度不一致的检测点。
- 加权合成只对有效字段进行；无效字段在合并结果中保持 NaN，方差字段同样。

**混合方差公式（强制）**：设簇内第 i 个检测点某标量维度的均值为 μᵢ、方差为 σᵢ²，权 wᵢ = SNRᵢ(线性)/ΣSNR，则合并后：

```text
μ̄  = Σ wᵢ·μᵢ
σ² = Σ wᵢ·(σᵢ² + μᵢ²) − μ̄²      // 含簇内均值离差项
```

禁止实现为方差的简单加权平均：两个相距半个分辨单元的目标合并后会得到"位置居中、方差很小"的过自信测量，直接导致 22.2 的 NEES 验收超上界。均值离差项使合并测量的不确定度如实覆盖簇的展布。

n < 100 时 O(n²) 可忽略。密集编队互相遮盖、诱饵贴目标、箔条云并团由此涌现。

**声明边界**：这是本项目选择的工程近似，只在玩法层面替代单元级模拟——它不复现噪声底抬升、单元跨越损失和 CFAR 边缘行为，贪心聚类的传递性（A~B、B~C 而 A≁C）也与真实分辨单元不同。接受此差异是第 1.2 节"永久不做层级二"决策的一部分。雷达显示的单元颗粒感由表现层 shader 用检测点 + 噪声纹理绘制，逻辑层无单元格。

## 11. 光电管线

- 被动，无发射事件；驻留图样同雷达（广角搜索/窄角跟踪）。
- 测量 = 方向 + 角速率，`range = NaN`；信号强度 = f(热区温度, 可见面积, 距离², 背景)。
- 识别：距离 < 识别距离且驻留稳定 → 提升航迹 classification 置信度。
- 距离获取途径：视差机动、多机三角（15.3）、激光测距（产生发射事件触发对方激光告警）。

## 12. ESM / 告警

告警接收机每传感器 Tick 查询发射事件缓冲：

```text
候选事件：时间窗内 ∧ 频段兼容
接收功率 = 主瓣内 ? mainlobePowerDb : sidelobeLevelDb 修正
         − 20·log10(r) − 遮挡衰减
超灵敏度门槛 → 告警观测：方向(±测向误差) + 信号类别 + 波形识别置信度
```

- 驻留级时序使 spike 感自然成立：搜索雷达扫过 = 周期性短告警；STT = 连续告警。
- 告警等级推断（搜索/疑似跟踪/照射/导引头）基于收到的驻留节奏与波形，**不读对方模式变量**。
- 干扰源测向：强噪声干扰持续时间越长，方向扇区收敛越快；单机无距离，多机交叉定位走数据链。

## 13. 电子战注入点

EW 不修改"是否锁定"，只在信号链注入：

| 类型 | 注入位置 |
| --- | --- |
| 噪声干扰 | 10.2 分母干扰功率项（按频段/方向/波束旁瓣耦合） |
| 距离/速度/角度欺骗 | 测量生成后偏移对应量（需波形匹配成功） |
| 虚假目标 | 检测判决前注入合成检测点（正常格式，无真值标签） |
| 射频/红外诱饵 | 真实模拟世界中的独立签名实体 |

欺骗成功度 = f(干扰品质, 截获波形匹配, 目标雷达电子防护)。烧穿自然涌现：距离缩短后真实回波 40·log10 增速压过干扰。

所有注入留下功率/方向/时间痕迹供 ESM 反制。

## 14. 航迹系统

### 14.1 滤波器：CMKF（转换测量卡尔曼滤波）

状态 6 维（位置+速度），常速度模型。测量为球坐标 (r, az, el)，转笛卡尔伪测量后进**线性**卡尔曼滤波：

```text
z_cart = p_sensor + r · direction
R_cart = J·diag(σr², r²σθ², r²σθ²)·Jᵀ + 去偏修正项   // J 为球→笛卡尔雅可比
```

去偏修正采用标准 CMKF 去偏公式（大角度误差时均值偏移补偿）。径向速度作为第二阶段标量更新（H = 视线方向投影）。

**数值纪律（强制）**：

- 更新用 Joseph 形式：`P = (I−KH)P(I−KH)ᵀ + KRKᵀ`
- 每次更新后对称化 `P = (P+Pᵀ)/2`，对角线断言 > 下限
- 预测步过程噪声 Q 按机动档位取值（见 14.3）

### 14.2 纯方位航迹（光电专用通道）

角度-only 测量不可观测距离，禁止进入主 CMKF。独立通道二选一（首版取 a）：

- (a) 距离参数化：4~6 个假设距离子滤波器并行，视差/三角/激光出现后坍缩为单一航迹转入主通道;
- (b) 修正球坐标（MSC）EKF。

光电航迹与雷达航迹的合并发生在融合层（15.3），合并前各自独立生存。

### 14.3 机动检测

维护滑动窗 NIS（归一化新息平方）。超卡方门限 → 过程噪声升档（3 档：巡航/机动/极限），连续正常后降档。第一版不做 IMM。

### 14.4 关联

- 航迹预测到测量时间戳 → 马氏距离门控 → 门内最近邻分配。
- 未关联测量 → 候选航迹（Tentative），M/N 确认（如 3/5 驻留命中）转 Confirmed。
- 航迹交错互换（track swap）是接受的真实现象，不做全局最优分配，除非实测虚假目标密度使最近邻失效。

### 14.5 生命周期

```text
Tentative →(M/N)→ Confirmed →(连续丢失)→ Coasting →(协方差超限)→ Degraded → Dropped
```

- Coasting 只预测不更新，协方差自然膨胀，HUD 显示误差圈扩大。
- Dropped 后保留墓碑（TrackId + 末状态，~5 s）：新 Tentative 落入墓碑门内时继承旧编号，防 UI 目标编号跳变。
- 物理一致性评分：加速度超推力包线、遮挡区内持续回波、雷达/光电矛盾 → interferenceScore 上升，UI 标"疑似欺骗"，不自动删除。

## 15. 数据链与融合

### 15.1 消息模型

离散消息队列：不可变消息 → 带宽调度 → 传播+处理延迟 → 干扰丢包 → 接收队列。首版调度器为占位实现（每链路每 Tick N 条，按优先级），字节级带宽预算推迟到多机阶段。消息只含观测/航迹摘要 + 时间戳 + 协方差 + 来源，无真实坐标。

### 15.2 乱序测量（OOSM）：滞后融合时钟

数据链延迟使观测时间戳可能早于航迹最后更新——直接入滤波器数学错误。解法：

```text
融合器输入 = 按 timestamp 排序的小顶堆
只处理 timestamp ≤ simTime − Δmax 的测量（Δmax ≈ 200 ms，可配置）
→ 入滤波器的观测严格时序递增，无回溯
HUD/火控显示：航迹状态前推 Δmax + 渲染插值补偿
```

本机传感器观测同样过此堆（延迟极小，顺序天然正确）。Δmax 本身即"火控系统处理延迟"，是拟真的一部分。超过 Δmax 迟到的数据链消息丢弃并计数。

### 15.3 融合策略

- 本机多传感器：观测级融合，同一航迹按各自 R 更新（雷达给全维、光电给角度、ESM 给方向扇区）。
- 数据链航迹摘要：**协方差交叉（CI）**融合——远端与本机误差相关性未知，CI 是不做独立性假设的保守正确解：

```text
P⁻¹ = ω·P₁⁻¹ + (1−ω)·P₂⁻¹ ，ω 取迹最小化，首版可固定 0.5
```

- 三角测量前置检查基线质量：两条方位线夹角 < 门限时拒绝生成距离（防平行线伪高精度）。
- 航迹网络传播：每条融合航迹记录贡献来源链，来源矛盾时膨胀协方差而非二选一。

输出：FireSolution {

## 17. 导弹

### 17.1 架构

导弹 = 完整平台：自己的 SimKinematics、导引头（复用传感器管线，窄视场高刷新配置）、本地航迹（容量 1~2）、独立能源/热限制。母机航迹与导弹本地航迹靠关联交接，**发射后无任何真值引用**。

### 17.2 制导律

- 中段：惯性 + 数据链修正（走 15.1 消息，占制导通道）飞向预测拦截篮。
- 末段：**真比例导引（PN）直接消费导引头 LOS 率测量**。三维完整形式：

```text
R  = 目标估计位置 − 导弹位置（视线向量）
V  = 目标估计速度 − 导弹速度（相对速度）
Ω  = (R × V) / (R·R)                 // 视线角速率向量，导引头的原生测量量（Measurement.losRate）
V_c = −(R·V) / |R|                   // 接近速度：雷达导引头由多普勒直测，红外由 Ω、角尺寸变化率估计
a_cmd = N · V_c · (Ω × R̂)            // N ≈ 3~4；R̂ = R/|R|；a_cmd 恒垂直于视线
限幅：|a_cmd| ≤ 结构过载上限；R̂ 与导引头轴夹角 > 框架角上限 → 脱锁
```

LOS 率是导引头直接测量的量，不经过位置滤波器——链路最短且拟真（红外导弹本就如此工作）。侧向加速度受结构限幅，燃料/过载不足 = 自然脱靶。

### 17.3 末段结算：解析 CPA（强制）

km/s 级交会下 50 Hz 步进每步 20~80 m，禁止依赖 PhysX 碰撞。每末段 Tick：

```text
两平台视为 tick 内匀加速段：Δp(t) = Δp₀ + Δv·t + A·t²，A = ½Δa

d|Δp|²/dt = 2·Δp(t)·(Δv + 2A·t) 展开为三次多项式：
  c₃·t³ + c₂·t² + c₁·t + c₀ = 0
  c₃ = 2(A·A)
  c₂ = 3(Δv·A)
  c₁ = Δv·Δv + 2(Δp₀·A)
  c₀ = Δp₀·Δv

求根算法（最终决策：极值点隔离 + 固定次数二分。确定性、无超越函数、覆盖全部区间实根）：
  1. |Δa|² < ε → 退化为线性交会：t* = −c₀ / c₁（c₁ < ε 时取端点）
  2. 否则求导数二次方程 3c₃t² + 2c₂t + c₁ = 0 的实根（判别式 ≤ 0 则无内部极值），
     用其与 {0, dt} 把 [0, dt] 切成至多 3 个单调子区间
  3. 每个子区间端点函数值异号 → 固定 32 次二分求根（dt=0.02 s 时定位精度
     ~5 ns，km/s 级交会下距离误差微米级）；同号 → 该子区间无根
  4. 候选集 = 上述全部实根 ∪ {0, dt}，逐一求 |Δp(t)|，取最小者为 (t_cpa, d_cpa)

不采用 Cardano（判别式近零的数值调理复杂，且 cbrt/acos 依赖 libm，与 21 节
确定性分级冲突）；不采用单起点 Newton（无法保证找到区间内全部实根，与第 4 步
候选集定义矛盾）。二分固定 32 次不早退，保证同输入同步数同结果。

d_cpa < 近炸半径 → 在精确 t_cpa 时刻结算引信（破片锥几何 + 相对速度）
d_cpa < 直击半径 → 直击
```

双精度计算，与浮动原点无关，交战点在 50 km 外同样精确。

## 18. 能源与热量接口契约

传感器/EW 与机体资源系统的交互协议（每运动 Tick）：

```text
设备 → EnergyManager：提交本 Tick 功率需求（由驻留图样密度推得）
EnergyManager → 设备：按优先级分配 powerFraction ∈ [0,1]
设备执行：发射功率 × powerFraction → 探测距离按 (powerFraction)^(1/4) 自然缩水
设备 → ThermalSystem：提交实际产热 = f(实际发射功率)
过热 → ThermalSystem 强制降 powerFraction 或停机（设备各自过热门槛）
```

供电不足表现为具体设备降档（雷达刷新变慢、干扰通道减少），禁止统一性能百分比。

| 候选对 | 2048/Tick | 按预估 SNR 截断，计数 |
| 检测点环形 | 4096 | 保高 SNR，计数 |
| 本机航迹 | 64/平台 | 降级最低优先级 |
| 发射事件环形 | 1024 | 覆盖最旧 |
| 数据链队列 | 256/链路 | 按优先级丢弃 |

禁止自动扩容。

## 21. 确定性与重放

- 随机数：`squirrel3/wyhash` 类哈希 RNG，禁用 `UnityEngine.Random`。种子构成一律用**逐字段哈希链**，禁止异或组合（⊕ 可交换且可抵消：不同的 (SensorId, targetId) 对可碰撞出相同种子，低位密集的句柄值会产生相关噪声流）：
  - 目标相关掷骰（探测判决、测量噪声）：`hash(hash(hash(SessionSeed, sensorId), dwellSequence), targetEntityId)`——用稳定实体句柄（Index+Generation）而非候选枚举序号，保证波束内增删无关目标不改变已有目标的噪声序列（传感器仿真层有权读 SimEntityId，见第 2 节防火墙定义）；
  - 与目标无关的流（虚警生成）：`hash(hash(hash(SessionSeed, sensorId), dwellSequence), 驻留内虚警序号)`；
  - EW 合成假目标（13 节注入的检测点）：`hash(hash(hash(hash(SessionSeed, jammerEmitterId), victimSensorId), dwellSequence), 注入点序号)`——键由干扰机侧句柄 + 受害传感器 + 驻留序号构成，与候选枚举顺序无关，重放稳定。
- 确定性承诺分两级：
  - **同平台同构建：bit 级确定（硬保证）**——自定义积分器 + 哈希 RNG + 稳定遍历顺序 + 固定步数求根即可达成，是重放与调参的基础；
  - 跨平台 bit 级确定：**可选目标，不默认承诺**。double 在 Burst 下受 FMA 收缩与指令重排影响，超越函数（sin/cos/exp）各平台 libm 实现不同；如确需跨平台一致，需 `FloatMode.Strict` + 自实现多项式超越函数（lockstep 引擎级专项工程），届时单独立项。
- PhysX 射线参与的气泡内遮挡仅同平台确定，重放文件记录其结果以支持跨平台回放。
- 捕获内容：初始世界 + 输入流（玩家指令、模式切换）+ 配置哈希；可只重放传感器层。

## 22. 调试与验证

### 22.1 真值对照面板（先于一切实现）

Editor/开发构建专用通道：叠加显示真实位置 vs 航迹估计、协方差椭球、扫描锥、驻留波束、遮挡线、ESM 扇区。发布构建编译剔除。

### 22.2 滤波器一致性检验（客观判据，非目测）

- **NEES**（状态误差，需真值，重放场景下）：ē = (x−x̂)ᵀP⁻¹(x−x̂)，N 次蒙特卡洛均值应落在卡方 95% 区间。超上界 = 滤波器过自信（P 太小），超下界 = 过保守。
- **NIS**（新息，运行时可测）：在线监控，同时兼作机动检测输入。

### 22.3 统计验收

- 蒙特卡洛探测曲线：固定 RCS 目标径向接近 ×500 次，Pd-距离曲线对照解析雷达方程，偏差 < 5%。防止调参破坏物理关系。
- 雷达方程 r⁴、RCS 插值、CPA 解、CI 融合、坐标转换：EditMode 单测。
- PlayMode：驻留时序（RWR spike 间隔 = 扫描周期）、遮挡断照、烧穿距离随功率比移动、OOSM 堆时序严格递增、浮动原点切换航迹连续。

### 22.4 Profiler 标记

`Sim.Integrate / Sensor.Snapshot / Sensor.Dwell / Sensor.Occlusion / Sensor.Echo / Sensor.Merge / Track.Associate / Track.Filter / Fusion.DataLink / FC.Solution` 每阶段独立标记 + 计数器（候选数/检测数/丢弃数/堆深度/缓冲峰值）。

## 23. 性能预算

场景包线以设计文档实际规模为准：**8 平台 × 每平台 2 传感器 × 4 导弹在飞 + 100 环境实体**。压力测试 ×5（40 平台），不为 ×50 包线做架构妥协。

| 项 | 预算 |
| --- | --- |
| 运动积分 100 Hz | < 0.1 ms/Tick |
| 传感器 Tick 主线程 | < 0.5 ms |
| 传感器 Worker 合计 | < 1.5 ms |
| 融合 Tick | < 0.5 ms |
| 峰值单帧（含补算） | < 4 ms |
| GC | 0 B/frame |
| 遮挡查询 | < 3000/s |

估算（完整场景）：

- 母机传感器：8 平台 × 2 传感器 × 25 Hz × 平均 3 驻留/Tick × 平均 8 候选/驻留 ≈ **9600 候选对/秒**
- 在飞导弹导引头（17.1 配置：窄视场高刷新）：4 枚 × 50 Hz × 1 驻留/Tick × ≤2 候选/驻留 ≈ **400 候选对/秒**
- 合计 ≈ 10000 候选对/秒；压力测试 ×5 后 5 万/秒，仍远低于 Burst 化上限。性能不是本方案的风险项；调参劳动才是。

## 24. 分阶段实现

### 阶段 0：运动权威迁移（前置，独立交付）

SimKinematics 积分器 + PhysX kinematic 镜像 + 浮动原点服务；辅助飞控迁移。验收：现有飞行手感无回退，50 km 外两实体相对运动无抖动，重放 bit 一致。

### 阶段 1：最小雷达闭环（首个垂直切片）

一部雷达（广域+STT 两种驻留图样）、一个目标、解析遮挡、CMKF 航迹、火控解算、真值对照面板。

完成标准：

- 火控/Tracking asmdef 无 World 引用（编译即证明）。
- 目标离开波束 → Coasting → 误差圈膨胀 → 丢失。
- 遮挡断照射立即停止新检测。
- RWR 桩：能按驻留时序收到离散 spike。
- NEES 通过卡方区间；蒙特卡洛 Pd 曲线符合 r⁴。
- 相同种子重放 bit 一致；0 GC。

### 阶段 2：扫描体系与多目标

TWS 混排驻留、多目标、分辨率合并、关联门控、墓碑、驻留优先级调度。

### 阶段 3：光电与告警

热区两分区、光电方位航迹（距离参数化）、ESM 完整告警等级、激光测距。

### 阶段 4：电子战

噪声/欺骗注入、虚假检测点、烧穿、干扰源测向、射频/红外诱饵、物理一致性评分。

### 阶段 5：导弹全链路

导引头复用管线、中段数据链、PN 末段、解析 CPA 结算、搜索篮交接。

### 阶段 6：多机数据链

OOSM 滞后堆、CI 融合、交叉定位、三角测距、接力制导、带宽调度转正式。

## 25. 不采用的方案

- 完整电磁场求解、逐波长网格、雷达波 GameObject/粒子/碰撞体。
- 真实 PRF 逐脉冲射线。
- 距离-速度单元与 CFAR（含"以后再加"——由 10.6 永久替代）。
- 多普勒盲区/notch 机制。
- PhysX Rigidbody 动力学作为飞行权威。
- PhysX 碰撞作为导弹命中判定。
- 直接把 GameObject/Transform 交给火控、导弹或 AI。
- 运行时逐三角形电磁散射、无限次多径。
- 固定概率判定诱饵成功、干扰=解锁按钮、告警读取敌方锁定变量。
