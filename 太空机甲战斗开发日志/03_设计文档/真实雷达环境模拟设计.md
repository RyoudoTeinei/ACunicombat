# 真实雷达环境模拟设计

> 设计状态：技术与玩法方案。本文描述如何在 Unity 中构建信号级雷达环境，尚未进入代码实现。

## 目的

建立一套不直接读取真实目标对象的传感器系统，使雷达、光电、告警、电子战、航迹和火控都基于模拟接收数据工作。

目标效果：

- 雷达按照扫描方向和工作模式发射逻辑脉冲。
- 信号受到距离、遮挡、目标姿态、雷达截面积、噪声和干扰影响。
- 接收器先产生检测点，再由跟踪器建立航迹。
- 光电系统根据温度、热辐射、方向和遮挡发现目标。
- 告警设备只能接收实际存在的雷达、干扰和数据链辐射。
- 火控系统只能使用带误差和时间戳的航迹。
- 系统保持可实时运行，不进行完整电磁场数值求解。

## 当前结论

- Unity 可以实现高拟真度的信号级雷达环境。
- 不模拟空间中每个电磁波波峰，而模拟发射、传播、回波和接收结果。
- 不使用雷达波 GameObject、粒子碰撞或逐脉冲物理射线。
- 雷达和光电使用独立的传感器更新频率，不跟随渲染帧率。
- 雷达系统的最终输出是检测点和航迹，不是场景中的目标引用。
- 第一版使用目标级回波计算；后续再增加距离-速度单元和有限多径。

## 拟真层级

### 层级一：目标级传感器模拟

每次扫描直接计算候选目标产生的回波强度、距离、径向速度和测量误差。

包含：

- 扫描视场。
- 距离衰减。
- 方向性雷达截面积。
- 目标遮挡。
- 接收器噪声。
- 噪声干扰和欺骗干扰。
- 检测概率和测量误差。
- 航迹建立与丢失。

优点：性能好，适合第一版玩法验证。

### 层级二：合成接收信号

将目标回波、噪声和干扰累积到距离、速度和角度单元中，再从单元中提取检测点。

增加：

- 距离单元。
- 多普勒速度单元。
- 波束或角度单元。
- 目标回波互相遮盖。
- 干扰抬高局部噪声底。
- 恒虚警率检测。
- 更真实的虚假目标和诱饵。

优点：能够生成接近真实雷达的显示和信号处理过程。

### 层级三：完整电磁场求解

在三维空间中按波长建立网格，求解电磁场传播、绕射和多次反射。

结论：不用于实时游戏。

例如 `10 GHz` 雷达波长约为 `3 cm`。若使用约 `3 mm` 网格模拟一个 `1 km` 立方体，需要约：

```text
1000 m / 0.003 m ≈ 333,333 个单轴网格
333,333³ ≈ 3.7 × 10¹⁶ 个三维网格
```

这还没有计算每个网格需要保存的电场、磁场、材料和时间状态，远超实时游戏硬件能力。

## 总体信号链

```text
世界真实状态
→ 发射器生成照射任务
→ 传播、延迟与遮挡
→ 目标反射或主动辐射
→ 接收器叠加噪声和干扰
→ 生成距离、速度和方向测量
→ 检测点提取
→ 航迹关联与滤波
→ 目标分类和识别
→ 火控解算
→ 武器中段与末段制导
```

渲染系统只负责显示，不参与决定雷达是否发现目标。

## 世界真实状态

传感器模拟需要维护一份独立于玩家界面的世界状态。

每个可探测对象至少记录：

- 双精度位置和速度。
- 机体姿态与角速度。
- 质量和可用推力。
- 雷达截面积模型。
- 热区温度和热辐射模型。
- 当前主动电磁发射源。
- 可见光或激光反射特征。
- 大型遮挡体和简化碰撞体。
- 阵营和识别信息，但传感器不得直接读取阵营结果。

世界真实状态只供模拟系统计算。雷达、光电、告警、火控和玩家界面只能读取各自生成的观测与航迹。

## 雷达发射模型

### 发射器参数

每套雷达至少记录：

| 参数 | 单位 | 用途 |
| --- | --- | --- |
| 载波频率 | `Hz` 或波段 | 决定波长、多普勒比例和设备兼容性 |
| 波长 | `m` | 可由光速除以频率得到 |
| 平均发射功率 | `kW` | 决定持续信号能力、耗电和产热 |
| 峰值发射功率 | `kW` | 决定脉冲峰值和告警可探测性 |
| 天线增益 | 倍率或 `dB` | 决定主波束方向的有效辐射功率 |
| 天线有效孔径 | `m²` | 影响增益、接收能力和角分辨率 |
| 波束宽度 | 度 | 决定照射范围和测角能力 |
| 搜索方位角 | 度 | 水平扫描范围 |
| 搜索俯仰角 | 度 | 垂直扫描范围 |
| 驻留时间 | 秒 | 波束在一个方向积累信号的时间 |
| 扫描刷新率 | `Hz` | 完成观测更新的频率 |
| 工作模式 | 枚举 | 静默、搜索、跟踪、单目标和导弹支援 |

### 逻辑脉冲

逻辑脉冲是数据记录，不是 GameObject。它包含：

- 发射时间。
- 发射位置和姿态。
- 波束方向和宽度。
- 频率或波段。
- 有效发射功率。
- 脉冲或波形标识。
- 当前雷达模式。

第一版不需要按照真实脉冲重复频率逐脉冲更新。多个物理脉冲可以合并成一次扫描驻留任务，并在一个传感器更新周期内计算综合效果。

## 信号传播

### 传播延迟

单程传播时间：

```text
单程延迟 = 距离 / 光速
```

单基地雷达回波往返时间：

```text
往返延迟 = 2 × 距离 / 光速
```

在几十千米交战距离内，延迟通常小于一帧，但数据结构仍应保留发射和接收时间，便于以后支持超远距离探测和多机时间差定位。

### 自由空间衰减

主动发射信号到达目标时近似按距离平方衰减；目标反射回雷达后再次按距离平方衰减，所以单基地雷达回波总体近似按距离四次方衰减。

简化雷达回波：

```text
接收功率 ∝ 发射功率
         × 发射天线增益
         × 接收天线增益
         × 波长²
         × 目标雷达截面积
         / 距离⁴
         / 系统损耗
```

第一版可以使用归一化雷达方程，不必立即使用绝对瓦特和分贝标定，但变量关系应保持一致。

### 遮挡

大型实体可以阻断直接传播路径：

- 小行星。
- 空间站。
- 大型舰船。
- 具有足够尺寸的残骸。

遮挡检测使用简化碰撞体或双精度解析几何，不使用高精度渲染网格。

小型碎片不逐个射线检测，而作为碎片区域的统计杂波处理。

## 目标反射模型

### 雷达截面积

雷达截面积不是固定隐身等级，应随观察方向和机体状态变化。

影响因素：

- 观察方位和俯仰角。
- 机体正面、侧面和背面形状。
- 武器和散热器是否展开。
- 外挂装备。
- 损伤和碎片。
- 材料和表面处理。
- 雷达工作波段。

### 推荐实现

第一版为每种机体准备方向性雷达截面积采样表：

```text
正面 RCS
侧面 RCS
背面 RCS
顶部 RCS
底部 RCS
```

运行时根据雷达相对方向插值。

后续可以离线从低精度模型生成更细的球面采样表，但不在运行时逐三角形计算电磁散射。

### 相对运动与多普勒

径向速度：

```text
径向速度 = 相对速度在雷达视线方向上的投影
```

单基地雷达多普勒频移：

```text
多普勒频移 = 2 × 径向速度 / 波长
```

雷达直接测量的是径向速度，不是目标完整三维速度。完整速度需要连续观测、多角度观测或数据链融合。

## 接收器模型

接收器在一次驻留中合成：

- 目标真实回波。
- 背景热噪声。
- 接收器内部噪声。
- 大型物体和碎片区域杂波。
- 噪声干扰。
- 欺骗干扰。
- 诱饵回波。
- 其他雷达和友军电子战造成的干扰。

### 接收器参数

| 参数 | 作用 |
| --- | --- |
| 接收灵敏度 | 决定弱信号发现门槛 |
| 噪声系数 | 决定接收器自身增加的噪声 |
| 动态范围 | 决定强干扰下是否还能分辨较弱目标 |
| 距离分辨率 | 区分距离接近目标的能力 |
| 速度分辨率 | 区分径向速度接近目标的能力 |
| 角分辨率 | 区分方向接近目标的能力 |
| 积累效率 | 驻留时间增加后提高信噪比的能力 |
| 抗干扰品质 | 波形、频率和信号处理综合能力 |

### 信噪比

```text
信噪比 = 目标回波功率 / [背景噪声 + 干扰功率 + 杂波功率]
```

信噪比影响：

- 是否生成检测点。
- 距离误差。
- 角度误差。
- 径向速度误差。
- 检测点置信度。
- 航迹维持概率。

探测不使用固定距离边界。距离增加时，检测概率逐渐下降，误差逐渐扩大。

## 距离、速度和角度单元

层级二模拟把接收结果累积到离散单元：

```text
距离单元 × 径向速度单元 × 角度单元
```

每个单元保存：

- 总接收能量。
- 估计噪声底。
- 干扰标志。
- 来源波束和扫描时间。

目标、诱饵和欺骗干扰可以落入相同或相邻单元，使检测器难以分离。

第一版不必生成完整三维数据立方体，可只为当前波束创建一维距离单元或二维距离-速度图。

## 检测点

检测点是单次扫描输出，不等于稳定目标。

每个检测点包含：

- 测量距离。
- 测量方向。
- 测量径向速度。
- 测量误差。
- 信噪比或置信度。
- 观测时间。
- 传感器和工作模式。
- 干扰和杂波标志。

检测点可能来自：

- 真实目标。
- 诱饵。
- 欺骗干扰。
- 碎片或大型物体杂波。
- 噪声随机峰值。

## 航迹建立与跟踪

跟踪器负责把不同扫描周期的检测点关联为航迹。

流程：

```text
检测点
→ 与现有航迹预测区域匹配
→ 更新位置和速度估计
→ 缩小或扩大误差
→ 提高或降低置信度
→ 建立、维持、外推或删除航迹
```

航迹至少记录：

- 估计位置和速度。
- 位置与速度误差。
- 航迹置信度。
- 最后更新时间。
- 连续未观测次数。
- 观测来源。
- 分类和身份置信度。
- 物理一致性评分。
- 是否疑似受干扰或欺骗。

第一版可使用 Alpha-Beta 滤波；需要更稳定误差估计时使用卡尔曼滤波。

## 虚假目标与物理一致性

欺骗干扰直接生成符合接收器格式的检测点，不创建特殊的假目标标签。

虚假航迹可以表现为：

- 错误距离。
- 错误径向速度。
- 航迹逐渐偏离真实目标。
- 一个航迹分裂成多个航迹。
- 多个低置信度目标群。

跟踪器检查：

- 位置和速度是否连续。
- 加速度是否符合目标推力能力。
- 加速方向是否对应发动机热源和姿态。
- 雷达航迹是否有光电、热源或友军观测支持。
- 多机观察是否指向相同空间位置。
- 目标经过遮挡物时，信号变化是否合理。

高级欺骗干扰可以生成物理上合理的假航迹，但需要更多计算、功率、持续发射时间和干扰通道。

## 光电与温度模拟

### 热区模型

每个机体划分少量热区：

- 主推进器。
- 姿态推进器。
- 发电机和核心。
- 散热器。
- 武器。
- 外部装甲。

每个热区记录：

- 当前温度。
- 热容量。
- 当前产热。
- 当前散热。
- 表面积。
- 发射率。
- 朝向和遮挡。

### 温度更新

```text
温度变化 ∝ [产热 - 散热] × 时间 / 热容量
```

第一版可以使用抽象温度和热容量；后续再使用绝对温度和斯特藩-玻尔兹曼关系计算辐射功率。

### 红外接收信号

红外信号至少考虑：

- 热区温度。
- 有效可见面积。
- 发射率。
- 观察方向。
- 距离平方衰减。
- 大型物体遮挡。
- 背景天体和局部高热源。

光电单次观测主要得到方向。距离来自：

- 目标角尺寸估计。
- 连续运动产生的视差。
- 多机三角测量。
- 主动激光测距。

## 主动电磁辐射与告警

所有主动发射设备向辐射系统登记发射事件：

- 主动雷达。
- 噪声和欺骗干扰机。
- 全向或定向数据链。
- 导弹主动导引头。
- 激光测距或指示器。

接收机根据以下条件得到告警：

- 是否位于发射波束内。
- 接收功率是否超过灵敏度。
- 频段是否兼容。
- 波形能否识别。
- 接收机是否被遮挡或压制。

告警输出：

- 辐射源方向和方向误差。
- 信号类别。
- 搜索、疑似跟踪、武器照射或导引头接近状态。
- 识别置信度。
- 最后接收时间。

告警系统不读取敌方内部的锁定变量。

## 电子干扰

### 噪声干扰

噪声干扰向指定频段和方向增加接收功率：

```text
受干扰信噪比 = 目标回波 / [接收器噪声 + 杂波 + 干扰功率]
```

效果：

- 降低发现概率。
- 增大测量误差。
- 使航迹更新不稳定。
- 缩短有效探测距离。

代价：

- 耗电。
- 产热。
- 占用干扰通道。
- 暴露干扰源方向。

### 欺骗干扰

欺骗干扰根据截获的雷达波形产生合成回波，可以修改距离、速度或角度测量。

效果不直接作用于命中率，而是生成真实格式的错误检测点。

### 烧穿

随着双方距离缩短，真实回波按距离四次方迅速增强。达到一定信干比后，雷达能够重新建立稳定检测，形成烧穿。

烧穿距离不是固定装备数值，由雷达功率、目标截面积、干扰功率、波束方向和接收器性能共同决定。

### 干扰源测向

- 单机接收强干扰后获得方向扇区。
- 干扰越强、持续越久，测向误差收敛越快。
- 信号强度不能单独提供可靠距离。
- 多机共享方向扇区后，可以交叉定位干扰源。
- 向干扰源归航武器可以利用方向信息攻击辐射源。

## 多机数据链

数据链传输观测包和航迹包，不传输真实目标状态。

数据包包含：

- 来源平台。
- 来源传感器。
- 观测时间。
- 估计位置和速度。
- 误差和置信度。
- 航迹编号和关联信息。

协同能力：

- 被动交叉定位雷达和干扰源。
- 光电三角测距。
- 一机主动搜索、其他友机保持静默。
- 多视角验证虚假目标。
- 接力跟踪。
- 友军接替导弹中段更新。

限制：

- 通信延迟。
- 带宽和更新率。
- 数据链干扰。
- 航迹关联错误。
- 虚假航迹在编队中传播。
- 中继节点损失。
- 全向发射造成电磁暴露。

## 反射、杂波与多径

### 直接回波

所有目标首先计算雷达到目标再返回雷达的直接路径。

### 大型物体杂波

空间站、大型舰船和小行星使用独立强回波模型。它们可能：

- 遮挡目标。
- 在相邻距离和角度单元产生强杂波。
- 降低附近小目标的检测能力。

### 碎片区域

碎片区域不逐个模拟小碎片，而记录：

- 密度。
- 平均雷达截面积。
- 速度分布。
- 温度分布。
- 区域范围。

雷达穿过该区域时，按统计模型增加杂波和随机检测点。

### 有限多径

第一版不做多径。

后续只在空间站、小行星或大型舰体附近计算一次额外反射路径：

```text
雷达 → 大型反射体 → 目标 → 雷达
```

不计算无限次数反射。

## Unity 性能架构

### 更新频率分离

| 系统 | 建议初始频率 |
| --- | --- |
| 世界动力学 | `50-100 Hz` |
| 广域雷达搜索 | `1-5 Hz` |
| 跟踪扫描 | `5-10 Hz` |
| 单目标跟踪 | `10-20 Hz` |
| 光电搜索 | `5-10 Hz` |
| 导弹导引头 | `20-50 Hz` |
| 航迹融合 | `10-20 Hz` |
| 界面刷新 | `10-30 Hz` |

具体频率由玩法和性能测试调整。传感器不必每个渲染帧全部更新。

### 候选目标筛选

每次扫描先根据以下条件筛选：

- 最大作用距离。
- 波束方向和视场。
- 空间分区。
- 只排除传感器所属实体和明确不可探测的系统对象，不按阵营过滤。友军也必须经过探测和识别流程。

只有候选目标进入回波和遮挡计算。

### 并行计算

适合放入 Jobs 与 Burst 的任务：

- 距离和相对速度。
- 视场筛选。
- 雷达方程。
- 方向性雷达截面积插值。
- 热信号计算。
- 噪声和干扰累积。
- 航迹预测。

遮挡射线可以使用 `RaycastCommand.ScheduleBatch` 批量异步执行。

### GPU 计算

当使用大量距离-速度单元时，可以用 Compute Shader：

- 清空雷达数据缓冲区。
- 将目标、噪声和干扰累积到单元。
- 计算局部噪声底。
- 生成雷达显示纹理。

第一版目标级雷达不需要 Compute Shader。

### 内存与垃圾回收

- 使用预分配数组和 NativeArray。
- 不在每次扫描时创建大量托管对象。
- 不为检测点、脉冲或波束创建 GameObject。
- 使用对象池保存航迹和检测结果。
- 避免高频使用会分配内存的物理查询。

## 性能风险

### 可控做法

- 每个传感器只处理视场内候选目标。
- 以传感器刷新率而非真实脉冲频率更新。
- 使用简化碰撞体。
- 使用方向性 RCS 查找表。
- 对碎片云使用统计模型。
- 批量并行处理射线和信号计算。

### 严重风险

- 按真实数千至数万赫兹脉冲重复频率逐脉冲执行物理查询。
- 将雷达波实现为粒子、刚体、碰撞体或 GameObject。
- 每帧让所有传感器计算所有目标。
- 实时遍历渲染网格三角形计算反射。
- 建立覆盖整个战场的三维电磁体素网格。
- 无限制计算二次和更多反射。
- 为每个小碎片建立完整雷达与热模型。

## 太空坐标精度

Unity Transform 使用单精度坐标，大范围太空场景会出现抖动和距离误差。

建议：

- 世界真实状态使用双精度位置和速度。
- 传感器、轨道和火控计算使用双精度相对坐标。
- Unity Transform 只保存玩家附近局部空间的位置。
- 使用浮动原点或局部坐标气泡移动渲染世界。
- 远距离遮挡优先使用双精度球体、包围盒等解析几何。
- 进入局部复杂区域后再调用 Unity Physics 查询。

## 引擎分层

系统分为三个彼此隔离的世界。

### 真实模拟世界

保存物体真实状态：

- 双精度位置和速度。
- 姿态、角速度和加速度。
- 雷达、热和电磁特征。
- 遮挡体和区域环境。
- 传感器与发射器工作状态。

只有底层模拟可以读取这一层。

### 感知世界

保存传感器输出：

- 单次观测。
- 检测点。
- 本机航迹。
- 友军共享航迹。
- 融合航迹。
- 告警和来源可信度。

AI、玩家界面、火控和武器只能读取这一层。

### 表现世界

由 Unity GameObject、Transform、Renderer、粒子和 UI 构成，只负责：

- 显示机体和环境。
- 播放动画和特效。
- 显示雷达、航迹和告警。
- 将玩家操作转换为系统命令。

表现世界不能决定探测结果，也不能把 Renderer 是否可见当作传感器是否可见。


```text

    ↓

    ↓

    ↓             ↓

    ↓

    ↓
```

规则：

- `Simulation.Core` 不引用场景对象、UI、Renderer 或编辑器 API。

- `Editor` 只包含烘焙、可视化和资产检查工具。

## 标识符与引用规则

运行时核心不保存 `GameObject`、`Transform` 或其他 `UnityEngine.Object` 引用。

建议标识符：

| 标识符 | 用途 |
| --- | --- |
| `SimEntityId` | 世界中可被探测物体 |
| `SensorId` | 雷达、光电或告警接收器 |
| `EmitterId` | 雷达、数据链、干扰机和导引头 |
| `PlatformId` | 机体、舰船或传感器平台 |
| `TrackId` | 某个平台内部的一条航迹 |
| `NetworkTrackId` | 数据链融合后的共享航迹 |
| `FactionId` | 世界真实归属，只供伤害和任务规则使用；传感器路径不得直接读取 |

标识符使用整数和代数版本：

```text
Handle = Index + Generation
```

对象注销后递增 `Generation`，避免旧航迹或延迟数据包错误引用新对象。

`TrackId` 永远不等于 `SimEntityId`。即使一条航迹来自真实目标，感知系统也不能通过编号反查真实对象。

## 创作组件与运行时数据

### 创作组件

场景中的 MonoBehaviour 只负责配置和注册：

- `SimEntityAuthoring`
- `RadarSignatureAuthoring`
- `ThermalSignatureAuthoring`
- `RadarSensorAuthoring`
- `ElectroOpticalSensorAuthoring`
- `EmitterAuthoring`
- `JammerAuthoring`
- `OccluderAuthoring`
- `DebrisFieldAuthoring`

生命周期：

```text
OnEnable  → 注册并获得 Handle
中央 SimulationDriver → 批量读取已注册对象并提交可变状态
OnDisable → 注销并使 Handle 失效
```

创作组件本身不各自运行高频 `Update`。中央驱动器遍历注册表并批量同步，避免大量 MonoBehaviour 回调。

### 配置资产

不经常变化的参数存入 ScriptableObject：

- 雷达发射和接收参数。
- 扫描模式。
- RCS 方向查找表。
- 热区定义。
- 干扰机模式。
- 接收器噪声参数。
- 跟踪器门限。

配置资产视为不可变数据。进入运行时后烘焙成连续 Native 数据，Jobs 不直接访问 ScriptableObject。

### 运行时状态

频繁变化的数据保存在预分配 Native 容器中：

- 位置和速度。
- 当前姿态。
- 当前发射模式。
- 当前温度和热功率。
- 当前扫描任务。
- 检测点和航迹。

- `string`

- 委托

## 内存所有权

每个 Native 容器必须有唯一所有者。

| 数据 | 所有者 | 生命周期 |
| --- | --- | --- |
| 世界状态缓冲 | `SimulationWorld` | 场景运行期 |
| 空间索引 | `SpatialIndexSystem` | 场景运行期，每 Tick 重建或增量更新 |
| 到期传感器列表 | `SensorScheduler` | 每个传感器 Tick |
| 候选目标对 | `SensorQueryPipeline` | 一次扫描批次 |
| 遮挡命令与结果 | `OcclusionSystem` | 一次扫描批次 |
| 回波贡献 | `ReceiverPipeline` | 一次扫描批次 |
| 检测点 | `DetectionSystem` | 固定容量环形缓冲 |
| 本地航迹 | 每个平台 `TrackManager` | 平台存活期 |
| 数据链消息 | `DataLinkNetwork` | 投递或超时前 |

分配规则：

- 长生命周期缓冲使用 `Allocator.Persistent`。
- 跨帧临时批次使用 `Allocator.Persistent` 或可控池，不反复创建销毁。
- 单帧短任务可使用 `Allocator.TempJob`，必须在规定时间内释放。
- 所有 `Dispose` 集中在系统生命周期，不散落在业务回调中。

## 双缓冲快照

Jobs 读取的世界状态在一个 Tick 内保持不变。

使用双缓冲：

```text
写缓冲：主线程同步最新物理状态
读缓冲：Jobs 读取上一轮完成的稳定快照
Tick 边界：交换读写缓冲
```

优点：

- 避免 Jobs 与 Transform 同时读写。
- 同一扫描中的所有传感器使用一致时间点。
- 便于录制和重放。
- 允许一帧传感器延迟换取并行处理。

## 模拟时钟

传感器系统使用自己的固定步长模拟时钟，不直接依赖 `Time.deltaTime`。

建议时钟：

| 时钟 | 用途 |
| --- | --- |
| 物理时钟 | Rigidbody、推进和碰撞 |
| 传感器时钟 | 扫描、光电和告警采样 |
| 跟踪时钟 | 航迹预测和融合 |
| 表现时钟 | UI 插值和动画 |

统一时间类型使用 `double simulationTimeSeconds`。

调度器按累计时间处理：

```text
accumulator += frameDelta
while accumulator >= fixedStep:
    RunSimulationTick(fixedStep)
    accumulator -= fixedStep
```

为防止帧卡顿后无限追赶，每帧设置最大补算 Tick 数；超出部分记录性能告警，不能静默改变扫描频率。

## PlayerLoop 接入

第一版使用一个场景级 `SensorSimulationDriver`：

- `FixedUpdate` 后同步 Rigidbody 和 Transform 状态。
- 在主线程创建本轮扫描任务和 RaycastCommand。
- 调度 Jobs，不立即 `Complete`。
- 在后续 PlayerLoop 阶段或下一 Tick 完成结果。
- 完成检测、航迹和火控只读快照交换。
- `LateUpdate` 只消费结果更新 UI 和调试显示。

等系统稳定后再考虑自定义 PlayerLoop。第一版避免过早修改全局 PlayerLoop，降低调试复杂度。

## 单次 Tick 执行管线

```text
1. 完成上一批尚未完成的 Job
2. 应用上一批检测结果到航迹管理器
3. 更新航迹预测、分类和生命周期
4. 同步世界写缓冲
5. 交换世界读写快照
6. 更新空间索引
7. 找出本 Tick 到期的传感器
8. 为每个传感器生成扫描任务
9. 批量筛选候选目标
10. 生成远距离解析遮挡和本地 Physics 射线任务
11. 调度 RaycastCommand 批次
12. 计算传播、RCS、回波、噪声和干扰
13. 生成检测点
14. 将 JobHandle 保存到下一消费点
15. 更新只读告警和性能计数器
```

核心原则：不要在 `Schedule` 后立即 `Complete`，否则多线程管线退化为主线程同步等待。

```text
TrackUpdateJob 或主线程 TrackManager
```

第一版航迹数量较少时，关联和滤波可以留在主线程；候选筛选、回波和噪声计算优先进入 Jobs。航迹规模扩大后再并行化。

## 传感器调度器

每个传感器维护：

- 下一次到期时间。
- 当前模式刷新间隔。
- 扫描优先级。
- 单 Tick 最大候选数量。
- 是否允许延后一 Tick。

到期队列按以下优先级处理：

```text
导弹末制导
> 单目标火控跟踪
> 导弹中段更新
> 来袭告警
> 跟踪扫描
> 广域搜索
> 后台低优先级扫描
```

超过预算时允许低优先级扫描延迟，但必须：

- 增加航迹年龄。
- 在调试界面显示调度延迟。
- 不伪造正常刷新时间。

## 空间索引

太空场景稀疏，推荐双层索引。

### 远距离稀疏哈希网格

- 使用双精度世界坐标。
- 网格尺寸按典型探测距离设置，例如 `5-20 km`。
- 每个实体注册到一个或少量单元格。
- 雷达用波束包围球或包围锥查询相交单元格。
- 结果再做精确距离和夹角筛选。

### 局部复杂区域索引

空间站、残骸区和大型舰队附近使用局部 BVH、八叉树或 Unity Physics broadphase。

第一版优先使用：

```text
哈希网格粗筛
→ 距离筛选
→ 波束点积筛选
→ 遮挡检测
```

不直接调用 `FindObjectsOfType`、`OverlapSphere` 获取所有传感器目标。

## 遮挡子系统

### 远距离解析遮挡

使用双精度几何体：

- 球体：小行星和行星。
- 胶囊或圆柱：大型空间站主体。
- 有向包围盒：大型舰体和人工结构。

对每个候选目标计算传感器到目标线段是否与几何体相交。

### 近距离精细遮挡

只有进入局部坐标气泡的复杂对象才使用 `RaycastCommand`：

- 将双精度端点转换为当前浮动原点下的 float 坐标。
- 使用专用 `SensorOccluder` LayerMask。
- 禁止命中触发器和无关碰撞层。
- 每个候选目标默认只取最近命中。
- 批量调度，不逐条同步 Raycast。

### 遮挡缓存

静态或缓慢变化几何可以缓存短时间遮挡结果：

- 缓存键：`SensorId + TargetEntityId + OccluderRevision`。
- 传感器、目标或遮挡体移动超过阈值后失效。
- 高速导弹不使用长时间缓存。

## 雷达计算管线

### 候选对结构

每个候选对保存：

- 传感器索引。
- 目标实体索引。
- 发射时相对位置。
- 接收时预测相对位置。
- 距离和视线方向。
- 径向速度。
- 遮挡结果。
- RCS 查找方向。

目标实体索引只允许存在于回波计算阶段。转换为检测点时必须丢弃，不能沿数据链进入航迹和火控。

### 对数域计算

信号动态范围很大，推荐内部使用分贝或对数功率，避免 float 下溢和数值跨度过大。

```text
功率 dB = 10 × log10(功率线性值)
```

雷达方程在对数域转换为加减法：

```text
接收功率 dB = 发射功率
              + 发射增益
              + 接收增益
              + 波长项
              + RCS
              - 距离损耗
              - 系统损耗
```

最终需要叠加多个独立信号时，使用稳定的线性功率求和或 Log-Sum-Exp 类方法，不能直接把 dB 数值相加。

### 方向性 RCS 资产

推荐使用球面采样表：

- 第一版：前、后、左、右、上、下六方向。
- 第二版：方位 `16` 格 × 俯仰 `8` 格，共 `128` 个样本。
- 每个波段可以保存独立采样表。
- 运行时使用双线性或球面邻近插值。

RCS 资产由编辑器工具烘焙，运行时只读取连续 float 数组。

### 噪声生成

随机噪声必须可重现。

随机种子由以下数据组合：

```text
SessionSeed
+ SensorId
+ ScanSequence
+ RangeBin/TargetIndex
```

不能使用全局 `UnityEngine.Random`，否则帧顺序和其他特效会改变雷达结果。

高斯测量误差可由确定性均匀随机数转换生成。相同输入、相同种子和相同 Tick 必须得到相同检测结果。

### 检测门限

第一版：

- 根据 SNR 使用平滑检测概率曲线。
- 根据 SNR 调整测量方差。
- 使用确定性随机数决定弱信号是否形成检测点。

第二版：

- 建立距离或距离-速度单元。
- 估计邻近单元噪声底。
- 使用 CFAR 类门限生成检测点。

## GPU 与 CPU 边界

### CPU 负责

- 世界状态与空间索引。
- 候选目标筛选。
- 遮挡。
- 目标级雷达方程。
- 检测点和航迹。
- 火控和导弹制导。
- 决定性游戏逻辑。

### GPU 负责

- 大规模距离-速度图累积。
- 雷达噪声纹理。
- 原始雷达显示。
- 可视化热图和调试图。
- 非决定性的高密度杂波显示。

### AsyncGPUReadback 风险

若 GPU 生成检测点再回读 CPU，会引入：

- 一帧或更多延迟。
- 平台相关时序。
- GPU/CPU 同步风险。
- 测试和决定性重放困难。

因此第一版核心检测和航迹留在 CPU。GPU 先用于显示；只有确认 CPU 单元计算成为瓶颈后，再把接收积分迁移到 GPU。

## 热模拟底层

每个热区保存热能，而不是只保存一个热特征值。

```text
热能变化 MJ = [产热 MW - 散热 MW] × dt 秒
温度变化 = 热能变化 / 等效热容量
```

### 热区更新顺序

```text
设备提交产热
→ 热区吸收热能
→ 相邻热区交换热量
→ 散热器向空间辐射
→ 更新温度
→ 计算各方向红外辐射
```

第一版只计算核心、主推进器、散热器和武器四类热区，不做逐顶点温度。

热区之间的传导使用固定连接图，每条连接记录等效热导。连接图由机体装配时生成，运行时使用连续数组。

## 电磁发射事件系统

不为每个物理脉冲创建事件。发射分为：

- **连续发射区间**：噪声干扰、持续数据链、连续照射。
- **扫描驻留事件**：雷达波束在一个方向上的一组脉冲。
- **瞬时事件**：导引头开机、激光测距、强短脉冲。

### 发射记录

| 字段 | 说明 |
| --- | --- |
| `emitterId` | 发射器 |
| `ownerEntityId` | 所属平台 |
| `startTime/endTime` | 发射时间区间 |
| `origin/direction` | 发射位置与方向 |
| `beamWidth` | 波束覆盖 |
| `frequencyBand` | 工作波段 |
| `effectivePower` | 有效辐射功率 |
| `waveformId` | 波形识别和欺骗匹配 |
| `emissionType` | 雷达、干扰、数据链、激光等 |

发射记录存入时间有序环形缓冲。告警接收器只查询传播时间窗口内、频段兼容且几何上可接收的记录。

## 电子战注入点

电子战不直接修改目标是否锁定，而在信号链不同阶段注入效果。

| 电子战类型 | 注入位置 |
| --- | --- |
| 噪声干扰 | 接收器噪声功率累积 |
| 距离欺骗 | 距离单元或目标测量生成 |
| 速度欺骗 | 多普勒单元或径向速度测量 |
| 角度欺骗 | 波束测角结果 |
| 虚假目标 | 检测点生成前的合成回波 |
| 射频诱饵 | 真实世界中的独立信号实体 |
| 数据链干扰 | 包投递率、延迟和带宽调度 |
| 光学干扰 | 光电接收器噪声与饱和 |

所有效果都必须留下来源、功率和时间信息，供告警、测向和电子防护使用。

## 数据链运行时模型

数据链使用离散消息队列，不直接共享对象引用。

### 消息生命周期

```text
发送方生成不可变消息
→ 带宽调度器排队
→ 计算传播和处理延迟
→ 应用干扰、丢包和损坏
→ 到达接收方队列
→ 接收方验证来源和时间戳
→ 航迹融合器消费
```

### 消息类型

- 原始方位观测。
- 本地航迹摘要。
- 辐射源测向。
- 身份和分类更新。
- 导弹中段更新。
- 网络时间同步。
- 节点健康和中继状态。

### 带宽调度

每个链路维护字节或抽象带宽预算。优先级：

```text
导弹更新
> 来袭威胁
> 当前攻击目标
> 辐射源定位
> 普通态势航迹
> 低优先级背景数据
```

低优先级包延迟或丢弃后，接收方看到的是航迹老化，而不是链路仍然正常。

## 航迹关联

### 第一版

使用门控最近邻：

1. 将每条现有航迹预测到检测时间。
2. 计算检测点与预测的距离、角度和速度残差。
3. 超出门限的检测点不允许匹配。
4. 在门限内选择代价最低的匹配。
5. 未匹配检测点进入候选新航迹。
6. 连续多次确认后正式建立航迹。

### 关联代价

```text
代价 = 位置残差权重
     + 速度残差权重
     + 角度残差权重
     + 来源一致性权重
     + 分类一致性权重
```

具备协方差后使用马氏距离门控，避免用固定世界距离处理所有误差状态。

### 后续升级

- 全局最近邻分配。
- 联合概率数据关联。
- 多假设跟踪。

只有虚假目标密度确实使最近邻失效后才升级，不在第一版引入高复杂度算法。

## 航迹滤波

### 第一版 Alpha-Beta

- 状态：位置和速度。
- 优点：简单、稳定、容易调试。
- 缺点：误差协方差表达有限。

### 第二版卡尔曼滤波

- 状态向量：三维位置和三维速度。
- 维护 `6×6` 协方差矩阵。
- 不同传感器使用不同测量矩阵和噪声。
- 光电只有角度时不能伪造距离测量。
- 数据链更新保留远端观测时间。

### 机动目标

高机动目标可以：

- 增大过程噪声。
- 检测到加速度后切换模型。
- 后续升级为多模型滤波。

第一版不实现复杂目标意图预测。

## 航迹生命周期

```text
Tentative：候选航迹
Confirmed：确认航迹
Coasting：失去观测，正在外推
Degraded：误差过大，不满足火控
Dropped：删除
```

状态转换由以下条件决定：

- 连续命中次数。
- 连续未观测次数。
- 航迹置信度。
- 协方差大小。
- 物理一致性。
- 来源数量和可信度。

航迹删除后保留短时间墓碑记录，防止同一目标立即以新编号重复建立并造成 UI 跳动。

## 多传感器融合

融合采用“观测级优先、航迹级兼容”的策略。

- 本机可访问原始观测时，直接把不同传感器观测更新到同一航迹。
- 远端数据链只传航迹摘要时，执行航迹级融合。
- 不能假设两个远端航迹误差独立；来源重叠时降低融合增益。
- 每条融合航迹保存贡献来源列表和最后贡献时间。
- 来源出现矛盾时增加不确定度，不立即选择其中一个为真。

多机三角测量需要：

- 同一目标关联。
- 精确平台位置。
- 统一时间基准。
- 观测时间差补偿。
- 几何基线质量检查。

两条近乎平行的方位线不应产生虚假的高精度距离。

## 火控数据契约

火控请求只接受航迹 Handle：

```text
输入：TrackId + WeaponDefinition + ShooterState + RequestTime
输出：FireSolution
```

`FireSolution` 至少包含：

- 预测拦截位置。
- 预测拦截时间。
- 目标状态误差。
- 导弹预计剩余速度增量。
- 末制导搜索区域。
- 推荐导引头开机时间。
- 是否需要中段更新。
- 当前所需制导通道。
- 解算质量和失败原因。

火控不得接收目标 `Transform` 或 Rigidbody。调试模式可以显示真实误差，但不能把真实值反馈给武器。

## 导弹传感器架构

导弹使用与母机相同的底层传感器管线，但配置不同：

- 更窄视场。
- 更短探测距离。
- 更高刷新率。
- 更少航迹容量。
- 独立导引头噪声和抗干扰参数。
- 独立热、电磁和功率限制。

制导阶段：

```text
惯性中段
→ 数据链修正
→ 末段搜索
→ 导引头建立本地航迹
→ 导弹火控追踪本地航迹
```

导弹不能在导引头开机后自动获得母机真实目标引用。母机航迹与导弹本地航迹需要执行关联和交接。

## 线程边界

### 主线程职责

- 注册和注销场景组件。
- 读取 Transform 与 Rigidbody。
- 创建 `RaycastCommand`。
- 提交和完成 JobHandle。
- 写入 GameObject 表现。
- 更新 UI。

### Worker Jobs 职责

- 数学和空间筛选。
- 雷达方程和热信号。
- 解析遮挡。
- 噪声与干扰计算。
- 批量航迹预测。
- 可并行的检测点生成。

### 禁止事项

- Job 中访问 MonoBehaviour。
- Job 中修改 Transform。
- Job 中调用大多数 UnityEngine API。
- 多个 Job 无同步写同一航迹。
- 主线程在 Job 未完成时读取其 NativeArray。

## 容量与溢出策略

所有高频缓冲必须有容量上限和明确溢出行为。

| 缓冲 | 溢出策略 |
| --- | --- |
| 候选目标 | 按预计信号强度或威胁优先级截断 |
| 检测点 | 保留高 SNR，记录丢弃数量 |
| 本地航迹 | 降级或删除最低优先级航迹 |
| 告警源 | 保留最高威胁和最新辐射源 |
| 数据链队列 | 按消息优先级丢弃 |
| 虚假目标 | 受干扰机通道和接收器容量限制 |

禁止缓冲溢出后自动扩容，因为这会在高负载战斗中造成不可预测分配和卡顿。

## 决定性与重放

为了调试复杂传感器问题，支持确定性捕获：

- 固定模拟 Tick。
- 固定随机种子。
- 稳定实体遍历顺序。
- 所有观测保存时间戳。
- 记录玩家模式切换和发射命令。
- 记录配置资产版本和哈希。

调试捕获文件至少保存：

- 一段时间内世界快照。
- 发射事件。
- 传感器配置。
- 检测点。
- 航迹状态转换。
- 数据链消息。

可以只重放传感器层，不必重放渲染和动画。

## 配置版本与迁移

每个传感器 ScriptableObject 保存：

- `schemaVersion`
- 稳定资产 ID。

- 热区连接索引有效。

- 雷达模式切换。
- 干扰与烧穿。
- 数据链延迟和丢包。
- 导弹航迹交接。
- 浮动原点后航迹连续。

### 性能测试

固定场景分别测试：

- `20` 传感器、`200` 目标。
- `100` 传感器、`1000` 目标的压力场景。
- 大型空间站遮挡场景。
- 高密度碎片区域。
- 虚假目标饱和场景。
- 多机数据链拥塞场景。

每次测试保存平均、P95 和最大 Tick 时间，不只看平均帧率。

## 性能预算

以 `60 FPS` 为初始目标，单帧总预算约 `16.67 ms`。建议传感器系统预算：

| 项目 | 初始预算 |
| --- | --- |
| 平均传感器 CPU 主线程 | `< 1 ms` |
| 平均传感器 Worker 时间 | `< 2 ms` |
| 主线程 Job 等待 | `< 0.3 ms` |
| 单帧传感器峰值 | `< 4 ms` |
| 运行时 GC 分配 | `0 B/frame` |
| 普通战斗遮挡射线 | `< 5,000 次/秒` |
| 活跃航迹 | 首版 `< 512` |
| 检测点环形缓冲 | 首版 `< 4,096` |

以上是工程目标，不是已验证结果。Profiler 测试后再调整。

## 复杂度控制

| 阶段 | 期望复杂度 |
| --- | --- |
| 空间粗筛 | 接近 `O(实体数 + 查询到的单元内容)` |
| 候选回波 | `O(实际候选对数量)` |
| 遮挡 | `O(需要精查的候选对数量)` |
| 最近邻关联 | 最坏 `O(航迹 × 检测点)` |
| 数据链投递 | `O(到期消息数量)` |

若航迹关联成为瓶颈，先使用空间门控减少候选匹配，不立即使用更复杂算法。

## 故障与降级策略

- Job 超时：保留上一批航迹并增加航迹年龄，不生成完美补偿数据。
- 缓冲溢出：按优先级丢弃并记录计数器。
- 配置无效：禁用该传感器并输出一次明确错误。
- 数据链断开：继续使用本地航迹和最后收到的远端航迹外推。
- 浮动原点切换：暂停一轮场景射线提交，双精度世界状态继续运行。
- 设备损伤：降低功率、刷新率、精度或视场，不直接删除全部航迹。
- 传感器销毁：旧检测点仍可进入外推，但不能继续产生新观测。

## 首个工程切片

第一项实现不直接做完整雷达，而做一条可验证的垂直切片：

```text
双精度世界状态
→ 一个搜索波束
→ 哈希网格候选筛选
→ 一条批量遮挡查询
→ 归一化雷达回波
→ 带确定性噪声的检测点
→ Alpha-Beta 航迹
→ 火控只读航迹快照
→ 调试显示真实误差
```

完成标准：

- 火控代码中没有目标 Transform 引用。
- 目标离开波束后航迹进入外推。
- 遮挡后不再生成直接回波。
- 相同重放输入得到相同检测点。
- 运行时无每帧 GC 分配。
- Profiler 可以分别看到每个管线阶段。

## 分阶段实现

### 阶段一：最小雷达闭环

- 一套雷达。
- 一个目标。
- 波束视场和距离衰减。
- 一条遮挡射线。
- 带误差的距离、方向和径向速度检测点。
- 检测点建立航迹。
- 火控读取航迹，不读取目标 Transform。

- 多目标候选筛选。
- 航迹容量和优先级。
- 航迹外推和丢失。

### 阶段三：热与电磁环境

- 机体热区。
- 光电和红外检测。

- 雷达、激光和导弹告警。
- 电磁静默模式。

### 阶段四：电子对抗

- 噪声干扰。
- 欺骗干扰和虚假检测点。
- 烧穿。
- 干扰源测向。
- 射频和红外诱饵。
- 物理一致性识别。

### 阶段五：多机与数据链

- 观测包和航迹包。
- 多机交叉定位。

- 数据链延迟、带宽和干扰。

### 阶段六：信号级显示

- 距离单元。

## 第一版性能目标

建议首轮测试规模：

- `20` 个主动传感器。
- `200` 个可探测目标或大型碎片目标。
- 雷达平均更新 `10 Hz`。
- 每次扫描只对视场和距离内对象计算回波。
- 每个候选目标最多执行一条直接遮挡射线。
- 不启用多径和完整距离-速度图。

理论最坏目标配对数量：

```text
20 × 200 × 10 = 40,000 次目标配对/秒
```

经过视场和空间筛选后，实际进入完整信号计算的数量应明显更低。该目标只是初始预算，最终必须通过 Unity Profiler 在目标平台上验证。

## 验收标准

### 雷达

- 目标进入波束后才可能产生检测点。
- 距离增加时回波减弱、误差扩大。
- 目标姿态变化会改变探测质量。
- 大型物体可以遮挡直接回波。
- 雷达不能读取真实目标阵营。

### 航迹

- 单次检测不立即成为稳定目标。
- 连续检测使航迹误差缩小、置信度提高。
- 失去检测后航迹继续外推并逐渐失效。
- 虚假检测点可以形成可信航迹。
- 不合理假航迹通过多次观测逐渐被怀疑，而不是立即删除。

### 光电

- 主推进器工作会提高红外发现距离。
- 停止推进后温度逐渐下降，不会立即隐身。
- 单机被动观测距离误差较大。
- 多机观测能够缩小距离误差。

### 电子战

- 噪声干扰降低信噪比并扩大航迹误差。
- 欺骗干扰生成正常格式的错误检测点。
- 强干扰使干扰源更容易被测向。
- 距离缩短后雷达能够逐渐烧穿干扰。
- 数据链干扰降低共享航迹和导弹更新率。

### 性能

- 传感器模拟不产生持续垃圾回收尖峰。
- 不因扫描任务阻塞主线程造成明显帧时间峰值。
- 关闭雷达显示界面不会停止后台传感器模拟。
- 渲染帧率变化不会改变雷达实际刷新率。

## 不采用的方案

- 完整麦克斯韦方程实时求解。
- 逐波长空间网格。
- 雷达波粒子或碰撞体。
- 真实脉冲重复频率下逐脉冲射线。
- 运行时高精度网格电磁散射。
- 无限次数多径反射。
- 直接通过距离判断锁定成功。
- 直接把目标 GameObject 传给火控和导弹。
