## 边界与职责

- 雷达跟踪层管理匿名传感器航迹；同一次驻留内已分辨的回波，以共同先验进行整批一对一关联，然后提交滤波更新。原位置、多普勒和物理可达性门限继续有效。
- MissileContactManager 管理导弹联系人身份、发射记录、终止记录、历史关联与融合状态。数据链接收端只验证并提交报告，不按终端排列顺序决定航迹归属。
- 数据链报告对雷达航迹进行整批分配。已有且仍受证据支持的关联保留连续性；整体分配存在近似等价解时保留歧义，不能靠遍历顺序选取身份。
- 本机发射通过本地注册事件建立联系人，并通过收到的报告和传感器观测更新。HUD 不再直接遍历弹体注册表另画本机标记。
- HUD、AI、告警与防御通过 CopyMissileTracks / TryGetMissileTrack 消费同一份发布结果。历史传感器航迹可以保留查询，但终止的本机联系人不能继续显示。
- 敌方目标不使用场景实体 ID 做关联；真值只存在于独立离线验收记录。

## 时间基准

观测时间、报告状态时间与发布时刻分别保存。位置、速度及协方差必须对应同一状态时刻。TrackSnapshot 提供共同的 PredictPositionCovariance / PredictPositionUncertainty，与 PredictPosition 使用相同 LastPredictTime。未来报告不能创建或认证当前联系人；同一帧中观察者移动必须使相对几何缓存失效。

用户已批准修正旧采样程序把当前预测位置和旧时刻协方差混在一起的问题。旧 sampler 源码、失败结果以及 sample-epoch-proof.json 保留；3σ、位置跳变、屏幕跳变及重复标记门限不变。

## 固定输入重放

1. 雷达操作流从管理器创建开始记录，包含配置、原始回波、执行驻留、观察者状态、数据链状态修正、激光修正和终止操作。逐操作比对航迹位置、速度、协方差、ID、生命周期和证据时刻。
2. 联系人流记录关联前证据、已认证报告、已有绑定、本机发射记录、终止记录和预期发布结果。重放既核对原始顺序，也核对反向观测排列。
3. JSON 用于人工检查；无损载荷保留浮点位模式，避免 JSON 往返的末位变化制造重放误差。输入文件不提供可任意加载的类型名。
4. Run-PlayableCombat.ps1 在完整实战结束后执行两种独立重放，任一失败则整轮仍失败。完整实战仍覆盖真实 AI、正常调度、多机齐射、玩家机动、关雷达及断链恢复。

## 2026-10-19 完整实战继续排查

time-contract-combat：30 Hz 完整 120 秒、77 枚导弹，通过连续性、编队和两种输入重放。60 Hz 完整 120 秒、80 枚导弹，失败：1131 个重复标记帧、92 次屏幕修正超限、1 次原始航迹目标变化。该失败记录完整保留，不能用 30 Hz 或局部通过代替。

第一处根因是重新关联：旧来袭航迹断续约 0.92 秒后，低精度方位回波允许速度从朝内约 1.6 km/s 变成朝外约 1.2 km/s，接管本机新发导弹。发射时刻身份保护正确拒绝合并，因此旧雷达航迹与本机联系人同时显示。修复保留连续多普勒的独立信息，按旧运动状态、观察者运动、视线旋转、协方差和既有 1500 m/s² 可达加速度计算新的径向速度支持区间；新回波的低精度方位不能抹去旧多普勒。真实掠过可以改变径向速度符号。

第二处根因是运动证据时刻：已认证数据链对同一雷达滤波器持续进行遥测修正，但融合层仍把运动信息时间设置为最后雷达回波时间。关闭本机雷达超过一秒后，关联错误认为滤波器已过期，从而停止遥测修正。现在运动证据时间包含已接受的遥测时间，雷达命中时间及命中次数保持独立，不伪造雷达命中。
