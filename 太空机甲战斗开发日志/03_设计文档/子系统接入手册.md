# 子系统接入手册

代码核对日期：2026-10-19。适用项目：`E:/UnityDev/ACunicombat`。本文供开发编队、AI、IFF、数据链、武器、防御及 UI 子功能的 agent 使用。

本文描述当前工作区接口，不代表稳定版本 SDK 或全项目验收通过。优先级为：用户当前要求 → 实际代码与契约 → 本手册 → 历史实现记录。发现差异时先说明并更新接口说明，不能根据旧文档自行重建平行系统。

## 1. 开始开发前

1. 确定子功能负责的输入、输出、状态持有者和文件范围，先检查 `git status --short`。工作区已有大量未提交改动，不能清掉、回退或整体覆盖。
2. UI/策略模块通过本机公开适配器读取观测，形成请求；传输、资源仲裁和执行反馈由现有系统处理。
3. 新增业务代码尽量放独立文件。共享契约、雷达/导弹底层、IFF 或地图文件需要先明确协作边界。
4. 不因历史报告写着“通过”而认为当前版本已全部验收。查看对应运行目录的原始结果、源码清单和未完成说明。

### 当前并行工作边界

- M 地图与 IFF 问询应答此前由另一侧开发。接手这些文件前先确认当前负责人，不能自行推断它们已无人维护。
- 导弹联系人、雷达关联、时间基准和实战连续性仍在迭代；不要在子功能内另建航迹融合、导弹身份或显示去重系统。
- 用户最新允许合理的低精度位置收敛；这不等于允许身份串换、重复标记，也不表示测试判据已修改完成。
- 本手册只增加文档，不宣布上述工作完成，不授权修改其他 agent 的功能。

## 2. 总体链路与职责

```text
传感器观测 / 本机发射事件 / 实际收到的数据链报文
                 ↓
雷达跟踪、机体报告关联、导弹联系人管理
                 ↓
MechRadarController：本机统一态势快照
                 ↓
MechIdentityController：平台身份、证据与交战许可
                 ↓
UI / AI / 编队策略 → 命令或动作请求
                 ↓
数据链传输 / 本机动作仲裁 → 装备执行 → 实际反馈
```

这是职责图，不是可随意重排的 Unity 回调执行顺序。现有组件拥有自己的 Update/固定步进；外接模块不要再主动 Tick 同一个仲裁器、协议或数据链实例。

## 3. 身份、句柄与时间约定

| 标识 | 用途 | 不可替代为 |
| --- | --- | --- |
| `ObserverTrackRef` | `ObserverScope + TrackId`，明确哪一观察者的航迹 | 全局实体、另一机体的火控目标 |
| `TrackId` | 本地航迹句柄，包含世代 | 裸索引、对象名、永久目标 ID |
| `MemberId / Fleet / Leader` | 任务配置的成员与指挥关系 GUID | 实时位置、同队即有指挥权限 |
| `FleetPacket.Operation / Revision` | 操作关联及版本控制 | 每帧重发的新操作编号 |
| `FleetPacket.Contact` | 报告方对目标的业务关联键 | 所有观察者共享的真实实体 ID |
| `Weapon / InstanceId` | 当前装备实例 GUID | 零件型号、武器角色、固定槽号 |
| `LinkTerminalId` | 数据链终端句柄 | IFF 认证身份或本机航迹 |
| IFF `Subject` | 认证主体 GUID | 已经唯一定位的目标航迹 |

世界位置单位为米、速度为米/秒，时间为秒。Contracts 常使用 `double3`，Unity 表现层常使用 `Vector3`。角度单位看字段名：例如 IFF `BeamWidthDegrees` 为度，测量 `AngleVar` 为弧度平方。

### 时间不能只看一个字段

- `TrackSnapshot.LastPredictTime` 是当前状态时刻；`LastUpdateTime` 在原始雷达路径中是雷达观测更新时间。`SourceEvidence` 分别保存雷达、数据链等证据时刻。
- `MissileTrackSnapshot.LastUpdateTime` 是发布状态的时刻，`KinematicUpdateTime` / `LastEvidenceTime` 不等于查询时间。查询或预测不能把旧证据变新。
- 使用 `PredictPosition(now)`，不要对已经预测到 now 的位置再次做同一段外推；误差也必须预测到相同时刻。
- 编队当前使用 `radar.SimTimeSeconds`；`MechIdentityController` 的任务证据入口、部分动作执行当前使用 `Time.timeAsDouble`。它们在渲染与固定步进间可能存在差值，不能把它们描述成完全同一个时钟。
- 给身份适配器提交证据时按其当前时间域填写；跨边界应明确源状态时间和接收时间。不得用 UTC、墙钟或“收到的这一帧”覆盖观测时间。
- 保留未来时间拒绝、报文有效期和世代检查。不要任意添加大容差掩盖时间混用。

## 4. 统一态势读取

| 当前接口 | 调用含义 |
| --- | --- |
| `radar.CopyTracks(TrackSnapshot[] destination)` | 拷贝本机平台态势；只消费返回数量范围内的元素 |
| `radar.Reference(TrackId track)` | 创建带本机 ObserverScope 的引用 |
| `radar.TryGetTrack(in ObserverTrackRef reference, out TrackSnapshot snapshot)` | 校验观察者范围并查询本机航迹 |
| `radar.TryGetTrack(TrackId trackId, out TrackSnapshot snapshot)` | 已确定为本机 ID 时使用 |
| `radar.CopyMissileTracks(MissileTrackSnapshot[] destination)` / `TryGetMissileTrack(...)` | 导弹统一发布结果，不能另外遍历弹体对象补画 |
| `radar.CopyThreats(ThreatSnapshot[] destination)` | 本机收到的告警信息，不能等同于有精确三维位置的导弹 |
| `radar.TryAssignFireControlTrack(...)` | 请求本机火控指定；返回失败应保留原因/状态，不强写锁定 |

复制得到的是快照，修改它不会更新系统。数组可能截断结果，应结合各入口容量与任务规模选择缓冲区；不得只遍历旧数组长度。消费阶段仍需检查存在性、生命周期、信息年龄和本机交战许可。

`MechCooperativeTelemetry.CopyReports(List<Report>)` 是旧兼容入口，当前清空列表并返回 0。不要据此判断没有数据链，也不要恢复旧 UI 分流。调试原始收报用 `CopyReceivedReports`，业务态势仍用统一雷达适配器。

## 5. 编队命令接入

### 初始化与权限

任务装配阶段调用：

```csharp
Configure(Guid fleet, Guid leader, bool player, bool isLeader,
          int index = 0, FleetAttackMode initialMode = FleetAttackMode.Confirmed)
```

`Configure` 对已配置实例再次调用会抛异常。使用现有 `MechFleetMissionBootstrap` 作为任务组建参考，不要在 UI 每次打开时重配成员关系。

- 玩家所属编队由玩家担任长机；独立 AI 编队包含 AI 长机和 AI 僚机。AI 不向玩家下令。
- `CanCommand(Guid recipient)` 是 UI/调用方预检查；接收侧还会独立验证权限。
- 任务明确授予跨编队权限时，长机调用 `GrantSubordinateLeader(otherLeader)`；不要靠同队关系自动授予。
- 静态 `Roster` 只提供任务名单、长机关系和队位编号。它不是实时战场数据库，不得向其添加他机位置/弹药/血量供 AI 直接读取。

### 业务入口

```csharp
Guid Issue(Guid recipient, FleetOrderKind kind,
           TrackSnapshot target = default, Guid weapon = default,
           FleetAttackMode mode = FleetAttackMode.Confirmed);
bool CancelOrder(Guid operation);
void SetFormationMode(FleetAttackMode mode);
Guid RequestMove(Guid recipient, double3 destination);
Guid RequestRoute(Guid recipient, Unity.Collections.FixedList512Bytes<double3> route);
bool SetOwnRadarControl(FleetRadarControl mode);
Guid RequestRadarControl(Guid recipient, FleetRadarControl mode);
FleetPacket GetOwnStatus();
```

`Issue` 返回 `Guid.Empty` 表示本地权限检查未通过。非空只说明创建了待发送操作，**不保证报文送达、接收方接受或实际开火**。通过 `Results.TryGetValue(operation, out FleetPacket feedback)` 读取反馈；展示 `Phase` 和 `Reason`。等待期间使用“待回执”，不要显示“攻击成功”。当前回执是轮询字典，不存在通用的公开 `OrderCompleted` 事件。

| 命令 | 当前语义 |
| --- | --- |
| `Attack` | 受命方根据自身观测、装备和攻击模式选择手段 |
| `AttackWithWeapon` | 指定接收机的装备实例；该次任务允许指定武器，当前以一次实际开火提交/批次触发返航流程 |
| `SetAttackMode` | 修改确认/自由攻击规则；用 `SetFormationMode` 可通知本编队 |
| `Return` | 进入归队流程，不是瞬移到长机 |
| `SetRadarControl` | 雷达辐射管制（关闭）或主动许可（开启）；智能模式尚未实现并明确拒绝 |
| `Move` | 接收有限世界坐标路径点，经现有飞行控制执行；空路径或非有限坐标仍拒绝。长机转发整队，单机单独执行 |

指定接收机装备时，从本机收到的 `State.Capabilities` 读取 `Weapon` GUID，并校验 `Sender`、`Available`、`State.Fresh(packet, now)`；不能把长机自己的装备实例 ID 当成僚机的装备。能力报告可能过期，执行器仍会复核实际装备。

向 AI 长机下令会由其分发给下属；指定单独僚机会脱队执行再归队。指定武器委托到下级编队时，当前按已报告武器角色寻找各机装备，不是跨机复用同一个实例 GUID。缺失能力会拒绝委托，不能宣称已实现完整的多级编队成功结果聚合。

### 最小命令示例

以下方法片段可放入已有 UI/业务类；调用前机体组件应完成初始化。`selectedTarget` 必须来自长机自己的 `CopyTracks`，`recipient` 来自任务名单及权限过滤。

```csharp
using System;
using ACunicombat.Mechs;
using ACunicombat.Sensing.Contracts;

static Guid RequestAttack(MechFleetController leader, Guid recipient,
                          TrackSnapshot selectedTarget)
{
    if (leader == null || !leader.Configured ||
        !leader.CanCommand(recipient) || !selectedTarget.TrackId.IsValid)
        return Guid.Empty;
    return leader.Issue(recipient, FleetOrderKind.Attack, selectedTarget);
}

static string ReadOrderStatus(MechFleetController leader, Guid operation)
{
    if (operation == Guid.Empty) return "未创建命令";
    return leader.Results.TryGetValue(operation, out var feedback)
        ? $"{feedback.Phase}: {feedback.Reason}" : "等待回执";
}
```

接收机通过 `TryGetOrderedTrack(out TrackSnapshot)` / `MechFleetContactMatcher` 关联本机航迹。不能把 `FleetPacket.Target.TrackId` 直接交给接收机火控。

## 6. AI、装备与协同防御

- 确认攻击允许规避、主动/被动防御、射程内枪炮攻击；禁止自主发射进攻导弹。自由攻击额外允许自主进攻导弹。明确指定武器任务是该次授权例外。
- `TryNavigation(out Vector3 direction, out MechPlayerInputFrame frame)` 提供编队导航建议；接入现有 AI 输入合成，不要在外部再次直接移动 Transform，也不要覆盖避弹输入。
- 通过 `CopyEquipmentWeaponSnapshots(List<MechEquipmentWeaponSnapshot>)` 遍历实际装备实例。六槽或更多槽位依赖 SlotId/InstanceId，不应写死四个武器枚举。
- 本机装备请求使用 `MechTestWeaponSystem.CommandFireSlot(string slotId, MechActionSource source, ObserverTrackRef target = default)`、`CommandReloadSlot(...)`、`CancelEquipmentAction(...)`。`CommandFireSlot` 返回 bool 不是命中/击毁证明。
- 现有 `Actions` 是本机共享 `MechActionArbiter`，不要新建第二个仲裁器争抢同一装备。需要按动作追踪时，通过 `Actions.TryGetPending(instanceId, out actionId)` 和 `Actions.TryGetFeedback(actionId, out feedback)` 查询；请求若已失败，不保证仍存在 pending。
- `MechActionPhase.Succeeded` 是动作执行成功，不是目标被摧毁。冷却、连射、编队任务完成以执行反馈为依据，不能按入队时刻计成功。
- 新装备执行类型应接入已有 `IMechActionExecutor` 路径，复核弹药、能量、制导资源、展开、身份与火控条件。不要直接扣弹药并 Instantiate 弹体绕过它。

协同防御由 `.Defense.cs` 管理：`IsFleetThreat`、`MayDefend(in MissileTrackSnapshot, out string reason, bool preparationOnly=false)`、`TryDefenseLook` 等是现有策略接口。实际装备可用性和物理解算仍由执行器判断。

预约报文有 `DefenseClaim / DefenseCommitted / DefenseRelease`，绑定发送者、联系人和租约。发现威胁、准备拦截、实际发射、命中摧毁是不同事件。业务插件不能自行调用 `NotifyShot` 或 `NotifyApsDefense` 来伪造成功；这些由真实执行链路回报。预约不是保证断链下绝无重复出弹，紧急自卫有独立优先规则。

## 7. IFF 与身份证据

### 读取结果

优先读取统一航迹的 `Identity`（`ContactIdentitySnapshot`），必要时调用本机 `MechIdentityController.TryGetIdentity(TrackId, out ...)` 或 `CanAttackPlatform(TrackSnapshot)`。

| 字段 | 含义 |
| --- | --- |
| `Relation` | Unknown / Friendly / Neutral / SuspectedHostile / Hostile |
| `Party` | Unknown / OwnAlliance / ThirdParty，独立于关系 |
| `Iff` | 认证事务结果，包括 AuthenticatedUnassociated、NoResponse 等 |
| `Conflict / UnderAttack` | 证据冲突与受攻击情况 |
| `CanAttackPlatform / CanInterceptThreat` | 不同交战许可，不可互相替代 |
| `Reason / EvidenceTime / ValidUntil / Confidence` | 解释、时间与可信度 |

`TrackAffiliation` 只有三态，不能表达全部中立/第三方/疑似关系。UI 不得另按颜色计算敌我。合法认证但未唯一关联不等于已经找到友机；IFF 不回应不等于敌人；友方身份与可靠攻击行为冲突也不能由 UI 丢弃一边证据。

### 任务证据入口

```csharp
bool SubmitMissionEvidence(ObserverTrackRef track, IdentityEvidence evidence);
bool CorrectHostility(ObserverTrackRef track);
void RevokeCertifiedIdentity(Guid subject);
```

这些是可信任务/证据生产者入口，不是任意 AI 给目标改阵营的便捷函数。调用方必须具备任务授权，不能让普通 UI 或未认证外部报文直接获得“可靠任务情报”资格。

证据必须保留 `OriginalId`、`Source`、`Kind`、`Quality`、`Association`、`ObservedAt`、`ExpiresAt`。质量和关联质量均为 0–1；重复转发保留原始 ID，不按转发次数制造更多独立证据。未来时间、过期、非法数值会拒收。

示例仅适用于确有可信任务情报的生产者；不是从敌机 TeamId 自动生成证据：

```csharp
using UnityEngine;
// radar、identity 是同一机体已初始化组件；localTrack 是本机已存在航迹。
double observedAt = Time.timeAsDouble; // 当前身份适配器的时间域
var evidence = new IdentityEvidence {
    OriginalId = "mission/briefing-17/contact-3", Source = "mission-intelligence",
    Kind = IdentityEvidenceKind.MissionHostile,
    Quality = 1f, Association = 1f,
    ObservedAt = observedAt, ExpiresAt = observedAt + 20
};
bool accepted = identity.SubmitMissionEvidence(radar.Reference(localTrack.TrackId), evidence);
// accepted 只代表证据被接受，不应直接把 UI 颜色或武器许可写成敌对。
```

`CorrectHostility` 清除相关敌对证据/记忆，不等于强制设为友方。`RevokeCertifiedIdentity` 撤销指定认证资格，不抹除独立数据链证据。`OpticalIdentity` 和 `WaveformIdentity` 当前明确拒收，不能假装完整识别已实现。

### 配置与低层边界

当前组件可配置 `InterrogatorEnabled`、`ResponderEnabled`、`ReplyPolicy`、认证域及各域列表、射频参数、`InterferenceDb`、`AllowUnknownPlatformAttack`。授权应答域不等于友方域。训练默认允许未知平台攻击必须显式说明；严格任务不能默默继承这个设置。

当前身份适配器自动轮询问询，并新增 `RequestInterrogation(ObserverTrackRef reference, out string reason)` 手动业务入口。仍经过本机范围检查、现有事务容量、冷却和射频传输；返回 true 只代表问询已调度，不代表认证成功。UI 不直接构造签名或调用 `ReceiveQuery/ReceiveReply`。

`MechIffProtocol` 管事务、认证和超时；`MechIffRadio` 是传播边界。独立 IFF 与数据链可以共同提供证据，但不能把它们合成一个无条件“同队即友方”开关。认证密钥不能进入日志或 UI。

## 8. 数据链接入与禁止捷径

编队业务通过 `Issue/Send` 入本机发件队列，由现有物理无线桥投递。`CopyOutboundFor`、`MarkTransportSent`、`Receive` 属于传输适配边界，普通业务禁止对远机直接调用 `Receive` 来实现瞬时通信。

底层 `DataLinkSystem` 提供 `RegisterTerminal`、`UnregisterTerminal`、`Send(in LinkMessage)`、`Tick(double)`、`CopyInbox`。新增报文类型时，应同时核对 Contracts、报文大小与优先级、排队合并策略、接收者、延迟、认证/来源验证、过期和重复处理；遵循 `MechCooperativeTelemetry` 的现有桥接实现，不在每个插件里创建自己的无限带宽总线。

业务代码不能：

- 遍历敌方 Transform、TeamId、装备/弹药读取真实世界状态，再包装成“观测”。
- 把别机的本地 TrackId 当成全球统一目标编号。
- 通过直接写 `State.Members / Capabilities / Claims` 绕过报文验证。当前它们虽公开可变，业务接入应只读并检查时效。
- 让 HUD、AI、地图分别维护另一套身份；或者在 UI 隐藏相邻图标来替代关联修复。
- 把发射记录、告警存在、跟踪确认、火控可用、认证成功和攻击许可混成一个布尔值。

### 2026-10-21 双机层级与编队编辑器

- 基础编组：1带2，3带4并服从1；奇数最后一架直接归1。Roster.FormationRoot 表示整个编队根，Leader 表示直属指挥者，FormationIndex 从0开始。IsLeader 对根长机和有僚机的双机组长机均成立；独立单位Leader/FormationRoot均为自身。旧的单层“全部跟随唯一长机”语义由此替代。
- Configure 仍仅用于任务初始配置；运行中重组使用 RequestFormationLayout，经 ConfigureFormation 报文、现有物理数据链、授权检查、重试和结果回执逐机生效。Roster只增加编制、职责和相对队位配置，不添加他机实时位置/弹药真值。编辑器显示待回执及部分失败，配置批次不是原子事务，失败后需重试。
- RequestFormationLayout 的成员顺序决定职责与根长机，根改变后保留有权发起编辑的玩家管理权限。权限不足的单位不可重组；未收到编制的对象不能凭传感器识别信息直接加入指挥链。
- FleetTaskGroup：Strike（打击）允许原有自主交战协调；Support（支援）取消自主寻敌攻击、保持编队并复用协同拦截防御；Reconnaissance（侦察）允许观察未知/中立等非友方接触，扩大既有交战距离为观察间隔、不自主开火。明确攻击任务仍可覆盖默认模式，武器/雷达管制保持独立；没有实现自动任务资源优化或高级侦察航路规划。
- 队形：Automatic、EchelonLeft/Right、LineAbreast、Trail、Wedge、FingerFour、Diamond、Custom。Auto四机用指尖，其他规模用楔形；自定义保存相对长机的三维偏移，发送时归一到首机原点。队形几何不改变双机指挥结构；跟随时使用收到的直属长机状态与两机队位之差。

### 2026-10-22 任务组目标与区域指派

### 2026-10-22 指定目标、导弹就绪与被动/数据链发射

红框/红字读取 `MechRadarController.CandidateTrackId`，表示玩家准星指定；不是可发射状态，也不是敌我身份。`MechMissileLaunchSource.Label` 提供搜索/跟踪/数据链/被动中文标签，只有实际装备满足发射条件时加“·锁定”。
