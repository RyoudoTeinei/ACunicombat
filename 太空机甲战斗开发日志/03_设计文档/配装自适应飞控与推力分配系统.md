# 配装自适应飞控与推力分配系统

## 目的

建立一套不依赖固定机体构型、不把按键硬编码到某类发动机、能够适应部件换装和喷口损坏的六自由度飞控系统。

玩家或 AI 只提出期望的平移加速度、姿态或角速度。飞控读取当前装配后全部喷口的真实能力，自动决定每个固定喷口的节流和每个矢量喷口的偏转角。

本文只记录清点与设计，不代表相关运行时代码已经实现。

## 当前配装

当前玩家测试配装为 `Melander 1010`：

- 核心：`AC6_SKIN_BD_M_1010`
- 手臂：`AC6_SKIN_AM_M_1010`
- 腿部：`AC6_SKIN_LG_M_1010`
- 背部推进器：`AC6_NATIVE_BS_A_1010`，在核心左右两个挂点各实例化一套

### 喷口清点

| 部位 | 数据或模型中的喷口 | 数量 | 当前状态 |
| --- | --- | ---: | --- |
| 核心 | 正面排气喷口 2 个、向上排气喷口 4 个 | 6 | 有数值和局部位置，没有确认对应模型挂点 |
| 双臂 | 每侧横向喷口 1 个、前向 RCS 1 个、后向 RCS 1 个 | 6 | 单侧模板镜像生成，有数值和局部位置，没有确认对应模型挂点 |
| 双腿 | 每侧主喷口 2 个、横向喷口 1 个、前后 RCS 各 1 个 | 10 | 单侧模板镜像生成，有数值和局部位置，没有确认对应模型挂点 |
| 两套背部推进器 | 每套 `_dmy_31`、`_dmy_41`、`_dmy_51` 各 1 个 | 6 | 模型挂点明确；只有 `_dmy_31` 已接入主羽流和运行时锚点 |
| 合计 | 配置数据与明确模型标记 | **28** | 不能等同于 28 个已接入物理的喷口 |

当前数量必须分三层理解：

1. **设计/配置清单为 28 个。** 核心、手臂、腿部有 22 个数值喷口，两套背部推进器共有 6 个明确的模型喷口标记。
2. **现有运行时只有 16 个功能通道。** 它们是主推 2、反推 2、横移 2、肩部升力 2、腿部升力 2、下降 2、肩部 RCS 2、腿部 RCS 2。
3. **真正绑定模型 Transform 的只有 2 个。** 即左右背部推进器的 `_dmy_31`。其余 14 个运行时通道仍按核心或腿部包围盒估算位置。

因此，当前系统既没有逐一使用 28 个喷口，也没有让 16 个逻辑通道完整对应实体喷嘴。

## 现有系统的问题

### 按功能角色分配，而不是按硬件能力分配

现有控制器先把喷口划为 `Main`、`Reverse`、`StrafePositive`、`ShoulderLift` 等固定角色，再由 `W/S/A/D` 或自动驾驶选择角色。角色内的喷口获得同一请求方向，并按左右健康度分摊一组额定推力。

这会产生以下问题：

- 新部件必须手工规定每个喷口属于哪个按键和角色。
- 同一个矢量喷口本来可以承担多种方向，却被锁死为单一用途。
- 更换核心、手臂、腿部或推进器后，飞控不能从几何和能力自动发现新的控制方式。
- 喷口位置与质心的力臂没有进入统一分配，平移与转矩无法一起优化。
- 当前矢量推力主要是数学上旋转一组总推力，不是控制真实喷口枢轴。
- 物理推力方向与羽流读取的挂点方向可能不一致。

### 数据结构不统一

- 手臂和腿部保存 `localThrustDirection`，核心保存 `localExhaustDirection`，方向语义相反。
- 三类部件分别使用不同喷口类，缺少统一能力接口。
- 背部推进器只有整组推力，没有逐喷口定义。
- 喷口数据没有模型锚点路径、偏转枢轴、偏转轴、伺服速度、节流响应和最小脉冲。
- 运行时无法可靠判断“数据存在但模型没有绑定”的降级状态。

## 设计原则

1. **输入描述意图，不点名发动机。** `W/S/A/D` 只生成期望运动，不能直接选择主推、侧推或腿部喷口。
2. **所有发动机使用同一能力模型。** 固定发动机、矢量发动机和脉冲 RCS 的差异由参数表达。
3. **同一状态驱动物理与表现。** 推力、转矩、喷口骨骼、羽流、声音、功耗和产热都读取求解后的实际执行状态。
4. **换装后重新建立能力矩阵。** 部件、挂点、质心或健康度变化后自动重新计算，不维护机型专用按键表。
5. **允许不完美配装。** 飞控尽量实现命令；若构型能力不足，应报告残差和缺失方向，而不是生成不存在的推力。
6. **姿态稳定优先于平移精度。** 高速战斗中先保证机体可控，再满足玩家的加速方向。

## 统一喷口定义

每个装配后的实体喷口都生成一份统一定义与运行时状态。

### 静态定义

| 字段 | 含义 |
| --- | --- |
| `nozzleId` | 部件内稳定编号 |
| `sourcePartId`、`partInstanceId` | 来源部件和左右/多挂点实例 |
| `anchorPath` 或 `anchorSuffix` | 喷口出口模型锚点 |
| `gimbalPivotPath` | 可选的矢量枢轴 |
| `fallbackLocalPosition` | 锚点缺失时的降级位置 |
| `baseThrustDirection` | 统一保存推力方向，不保存排气方向 |
| `maximumContinuousThrustKn` | 连续最大推力 |
| `maximumBurstThrustKn` | 可选短时最大推力 |
| `actuatorType` | `Fixed`、`Gimballed` 或 `PulseRcs` |
| `gimbalAxes`、`gimbalLimits` | 可转轴与正负角度限制 |
| `gimbalSlewRate`、`gimbalAcceleration` | 矢量伺服动态 |
| `throttleRiseRate`、`throttleFallRate` | 推力建立与关闭速度 |
| `minimumStableThrottle`、`minimumImpulseBit` | 连续发动机或脉冲 RCS 的下限 |
| `powerCurve`、`heatCurve` | 输出对应的耗电和产热 |
| `visualProfile`、`audioProfile` | 羽流和声音配置 |

`Main`、`Reverse`、`Strafe` 等可以保留为调试标签或成本偏好，但不能决定喷口是否有资格参与某个方向。

### 运行时状态

- 当前世界位置和推力方向
- 当前/目标节流
- 当前/目标偏转角
- 可用最大推力
- 健康度、故障和禁用状态
- 当前功耗、产热和推进剂流量
- 是否成功绑定出口与枢轴
- 上一物理帧输出，用于限制突变

## 装配后的自动建模

每次配装完成后执行以下流程：

1. 遍历核心、双臂、双腿、背部与可提供推进能力的武器或扩展部件。
2. 按每个实际部件实例展开喷口模板；左右镜像和多挂点安装必须生成独立喷口，不能共享一个运行时状态。
3. 优先绑定模型锚点和矢量枢轴；绑定失败时使用局部位置回退，并在诊断界面标记为“估算”。
4. 统一转换为机体坐标系下的位置、基准推力方向和可偏转包线。
5. 根据装配质量分布计算固定质心。武器动作和蒙皮包围盒不得逐帧改变质心。
6. 生成控制能力矩阵，并检查六自由度可控性。
7. 采样各方向最大可实现力和力矩，派生配装页面显示的加速度与姿态性能。

## 六自由度控制目标

外层飞控把玩家、AI、姿态稳定器、制动器和轨道同步器的请求合成为六维目标：

```text
w_target = [Fx, Fy, Fz, Tx, Ty, Tz]
```

- `F` 是机体坐标或统一导航坐标下的期望合力。
- `T` 是姿态控制器根据目标角速度/姿态和当前状态计算的期望力矩。
- 玩家仍感受到的是前进、横移、升降和转向；喷口选择属于飞控内部行为。

对第 `i` 个喷口：

```text
force_i  = direction_i * thrust_i
torque_i = (position_i - center_of_mass) x force_i
```

该喷口对六维控制的贡献列为：

```text
b_i = [direction_i ; arm_i x direction_i]
```

所有喷口组合成能力矩阵 `B`，求解各喷口节流 `u`，使 `B * u` 尽量接近期望六维力/力矩。

## 推力分配器

### 优化目标

每个物理帧求解一个带约束的最小化问题：

```text
min ||W * (B*u - w_target)||^2
    + lambda_power  * power(u)
    + lambda_heat   * heat(u)
    + lambda_slew   * ||u - u_previous||^2
    + lambda_gimbal * ||angle - angle_previous||^2
```

约束包括：

- 节流范围、健康度和故障状态
- 固定喷口方向
- 矢量喷口偏转范围、偏转轴、转速和加速度
- 发电功率、储能余量和散热余量
- 连续发动机最低稳定节流
- RCS 最小脉冲与占空比
- AB、QB 等短时模式的允许条件和持续时间

### 任务优先级

建议使用分层优先级，而不是只靠一个平均权重：

1. 防止失控的姿态稳定和角速度限制
2. 紧急制动、避碰和结构安全限制
3. 玩家或 AI 请求的转向
4. 玩家或 AI 请求的平移
5. 轨道同步、漂移抑制和自动配平
6. 功耗、热量、喷口磨损与噪声优化

低优先级任务不能消耗掉高优先级任务所需的控制余量。

### 矢量喷口求解

矢量方向会改变矩阵 `B`，问题不是一次线性求解即可完成。首版可采用小规模迭代：

1. 从上一帧实际偏转角开始。
2. 在当前方向下求有界非负节流。
3. 计算剩余的力和力矩误差。
4. 按误差梯度调整各矢量喷口方向，并限制在偏转包线和本帧伺服行程内。
5. 重建矩阵并重复 3 至 5 次。

当前配装约 28 个喷口，这一规模适合在 Unity `FixedUpdate` 中使用预分配数组完成，不应每帧产生托管内存分配。

脉冲 RCS 的求解结果先表示平均占空比，再由脉冲调度器转换为满足最小脉冲宽度的点火序列。

## 物理与表现的一致性

- 求解器输出每个喷口的实际推力和方向。
- 物理层在喷口位置施力，或等价地累加合力和关于固定质心的合转矩。
- 矢量枢轴按伺服后的实际角度旋转，不直接跳到目标角。
- 羽流沿实际排气反方向显示，长度和亮度读取实际节流。
- 发动机、液压和伺服音效读取同一节流与角速度状态。
- 功耗、产热、推进剂和损伤都按实际输出结算。

禁止物理层使用机体逻辑正向、羽流层使用喷口 `Transform.forward` 的两套方向来源。

## 配装能力评估

配装完成后需要生成以下诊断：

- 控制矩阵秩；完整六自由度要求有效秩为 6
- 前、后、左、右、上、下最大合力与对应加速度
- 偏航、俯仰、滚转最大正负力矩和角加速度
- 在保持零附带转矩时的各向平移能力
- 在保持零净平移时的各轴转向能力
- 能力矩阵条件数或控制余量，识别“理论可控但非常脆弱”的配装
- 单个喷口失效后的剩余能力
- 功率受限和热受限时的持续能力

配装检查结果应明确区分：

- **完全可控：** 六自由度都有足够余量。
- **受限可控：** 可以控制，但某些方向很弱或会严重耦合。
- **不可完全控制：** 缺少某个平移方向或转矩轴；允许玩家实验，但必须给出警告。

配装页面上的三向加速度、单位质量姿态扭矩等数值最终应由该能力评估派生，不再由“主推力/侧推力/反推力”简单相加。

## 对操作层的影响

- `W/S/A/D/Space/Ctrl` 继续保持现有语义，只生成期望机体或导航坐标加速度。
- `X` 生成与当前速度相反的受限制动力，并要求飞控尽量保持姿态与高度。
- 轨道同步、QB 和 AB 都提交六维目标或模式约束，不直接调用指定喷口组。`F` 自由视角只属于相机层，不向本飞控提交任何目标。
- 固定发动机只能贡献其轴向推力；矢量发动机在机械范围内参与多个方向。
- 换装改变发动机布局后，按键无需重配；只有实际可达的加速度、耦合和响应发生变化。

## 分阶段实现

### 当前实验基线：固定绑定喷口直接驱动物理

- 背部左右主推进器继续使用既有独立通道和推进器零件额定主推力。
- 除主推外，不再根据 `Reverse/Strafe/ShoulderLift/LegLift/RCS` 角色生成临时喷口。只有保存到 `ThrusterNozzleLayout.json` 的条目才是运行时喷口；模型中未配置的 dummy 只是候选挂点，不产生推力和羽流。
- 每个已绑定辅助喷口暂用统一 `50 kN` 额定推力，节流范围为 `0..1`。喷口世界位置由绑定锚点和局部偏移决定，推力方向永远是编辑器保存的排气方向反向；本阶段没有矢量偏转。
- 当前分配器以固定喷口节流为未知量，联合逼近期望平移力与偏航力矩。喷口位置产生真实力臂；若布局无法同时满足零附带平移和目标转矩，残余耦合必须保留，不能由隐藏控制通道抵消。
- 羽流直接读取该喷口的实际输出向量。飞控、力矩和表现使用同一个喷口状态，禁止再由机体总控制力反推哪些喷口应该发光。
- 此基线先验证位置、方向、镜像、点火与控制可达性。单喷口独立额定值、健康度、能源、热量、脉冲调度和矢量机构在数据可信后再加入。

### 第一阶段：统一数据，不替换物理

- 新增统一喷口定义，保留现有核心、手臂和腿部数组作为迁移来源。
- 给背部推进器增加逐喷口定义，但 `_dmy_41`、`_dmy_51` 的用途和数值必须先验证。
- 逐个确认核心、手臂和腿部 GLB 中的 dummy 语义，填写出口与枢轴绑定。
- 建立导入校验，报告重复 ID、零方向、缺失锚点和无效偏转轴。

### 第二阶段：运行时清单与诊断

- 装配后生成统一喷口运行时列表。
- 显示 28 个候选喷口中哪些已绑定、哪些使用估算位置、哪些被禁用。
- 可视化每个喷口的基准方向、偏转包线、力臂和健康度。
- 暂时继续使用旧飞行物理，避免同时改数据与手感。

### 第三阶段：影子求解

- 新分配器只计算，不施加物理。
- 记录目标六维力/力矩、可实现结果、残差、饱和喷口和每帧耗时。
- 与旧角色通道输出对比，先解决方向、符号、镜像和质心错误。

### 第四阶段：切换实际物理

- 由逐喷口实际状态统一施加力和转矩。
- 羽流、枢轴、音效、能源和热量改读统一状态。
- 旧 `Main/Reverse/Strafe` 分配器仅保留为调试回退，稳定后删除。

### 第五阶段：换装与损伤闭环

- 配装页面改用能力评估结果。
- 喷口损坏后即时重分配，并在 HUD 提示丢失的控制方向。
- 接入发电机、储能器、散热器和推进剂约束。

## 验收条件

- 任意删除、增加、镜像或换装推进部件后，不修改输入代码即可飞行。
- 固定喷口不会产生其轴线之外的推力。
- 矢量喷口不超过机械角度和伺服速度。
- 单个喷口失效后，系统自动使用剩余喷口，并正确表现附带耦合或能力不足。
- 纯平移请求在能力允许时不产生明显旋转；纯转向请求在能力允许时不产生明显漂移。
- 目标与实际六维力/力矩、功耗、产热和表现使用同一份执行状态。
- 30 个左右喷口、每物理帧 3 至 5 次迭代时不产生 GC，求解耗时满足目标平台预算。
- 测试帧率变化时，节流、偏转和脉冲输出不抖动、不跳帧。
