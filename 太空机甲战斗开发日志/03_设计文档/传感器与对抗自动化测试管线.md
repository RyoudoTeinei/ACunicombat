## 二 管线总体结构

执行顺序：能力预检 → 加载场景与固定种子 → 生成世界真值 → 运行正式传感器/通信/融合 → 运行正式识别与决策 → 双通道记录 → 离线对齐评测 → 多次统计 → 门槛判定 → 生成报告与可重放用例。

两条记录通道必须隔离：

- TruthRecorder：仅测试设施读取真实实体位置、姿态、速度、实际身份、信号源、导弹目标和物理命中结果，用于离线裁判。
- ObserverRecorder：在 AI 实际读取边界记录其量测、航迹、证据、收到的消息、能力、候选行为和最终命令。记录“传感器产生过什么”和“AI 当时真正拿到什么”两个时间点。

离线 Evaluator 才能同时读取二者。禁止把真实 EntityId、真阵营、是否诱饵、导弹真实目标添加到生产 Measurement 或 AI 视图中。真值只用于评测，不用于让被测系统跟踪更准确。

日志钩子不得影响随机数序列、传感器预算或执行顺序；缓冲溢出计数并使相关结果无效，不能静默截断。测试用真值追踪放在专用程序集/构建条件中，生产 AI 不引用它。

| Artifacts/SensorBench/<run-id>/ | 原始记录、指标、图表、复现配置；默认不提交 Git |

每个 ScenarioSpec 至少含 schemaVersion、scenarioId、模式、必需能力、场景资产、设备与配装、世界/任务参数、观测条件、干扰配置、识别资料库版本、AI 策略、种子清单、固定步长、预热和测量时长、采样频率、容量与运行超时、预期约束、对应门槛版本。

每次输出 manifest.json、capabilities.json、truth.jsonl、observations.jsonl、tracks.jsonl、messages.jsonl、decisions.jsonl、events.jsonl、metrics.json、summary.csv、report.html、test-results.xml 和 Unity 日志。按需保存光电帧与失败窗口录像，常规成功运行不保存全程高分辨率视频。

运行清单记录 Git 提交与工作区差异摘要、Unity/包版本、场景与配置哈希、种子、模型与资料库版本、平台/GPU/渲染设置、开始结束时间和是否使用兼容模式。同一 scenarioId 的参数改变必须形成新的配置哈希，不能覆盖旧基线。

建议执行模式：Smoke、Regression、Sweep、Replay。当前入口已支持 Mode、Scenario、ReplayFrom 和 OutputPath，种子来自 Scenario；单独 Seed、Sweep 与审定 Baseline 参数尚未实现，不能假定已有这些调用选项。

## 四 时间 坐标与目标关联

所有误差先对齐坐标和时间。记录采样时刻、传感器产生时刻、接收时刻、融合时刻与决策时刻。量测误差对其采样时刻真值计算；AI 当下误差对决策时刻真值计算，包含信息陈旧和外推误差。不得用未来位置评判旧量测后把延迟误记成传感器噪声。

位置统一到明确的世界/任务参考系；发生导航参考重置、浮动原点或坐标转换时记录变换及版本。雷达距离、方向、多普勒按同一时刻观测者位置和速度计算真值。角误差用夹角或局部切平面残差，避免跨正负 180 度出现假大误差。

匿名量测与真目标的评测关联仅在裁判侧进行。单目标场景直接校验；多目标使用固定、公开的时空门限和一对一全局匹配，标出未匹配真目标、未匹配观测和歧义。不能每帧选择最有利的最近目标后隐藏航迹身份切换。

测试专用旁路可记录量测生成来源和回波合并的多源关系，用于解释错误，但不得回流生产系统。分辨率内合并回波单独统计“不可分辨目标组”；不可强迫它映射为一个完美单目标。欺骗合成点与真实实体目标分别计数，其来源只供裁判可见。

同时输出匹配目标上的条件误差和全体目标的漏检/误关联/虚假航迹指标。仅在有输出时算出的小误差，不能掩盖系统已丢失大多数目标。

## 五 核心指标

| 层次 | 必须输出的指标 | 用途 |
| --- | --- | --- |
| 原始雷达 | 有效覆盖驻留次数、检测率、距离/角度/径向速度偏差与 RMSE、P50/P90/P95/P99、SnrDb | 判断何时看得见、测得准 |
| 光电 | 视场覆盖、可见像素/遮挡、检测率、角误差、型号候选准确率、未知拒识率、误判率 | 判断看到轮廓、型号、标识的能力边界 |
| 航迹 | 位置/速度误差、确认延迟、连续可用率、最长中断、丢轨/再捕获时间、碎片化、身份切换 | 判断信息能否持续支撑行动 |
| 不确定性 | 误差与协方差的一致性、位置置信区域覆盖率、过度自信比例 | 防止实际偏差很大但火控误以为精确 |
| 干扰 | 检测与可用率变化、虚假航迹率、误关联、假身份/假目标接受率、失锁时间、干扰停止后的恢复 | 判断干扰改变了什么，而不只看 Jammed 标记 |
| 通信 | 每方向消息到达率、时延/抖动、陈旧度、会话成功率、重复包、身份回复关联错误 | 区分拒绝回复和根本没收到 |
| 身份 | 平台类别/型号/阵营各自混淆矩阵、误判敌军/误判民用/误判友军、未知比例、确认耗时、证据来源 | 分离分类能力和敌我判断 |
| 决策 | 信息到行动延迟、触发依据、拒绝理由、资源冲突、越权、打断/取消、开关机/换目标抖动 | 解释 AI 的反应是否符合可知信息和策略 |
| 交战 | 错误许可与漏掉有效窗口、火控点误差、交接成功、拦截/命中率、近失距离、耗弹、保护目标损失 | 直接验证信息是否足够战斗 |
| 辐射管制 | 主动发射时长、可被截获时段、暴露估计与对手实际知识的差异、信息获取收益 | 评估隐蔽与信息交换的代价 |

位置 RMSE 为所有有效对应时刻的距离误差平方均值再开方，同时报告有多少时刻无航迹。速度与量测各维分别计算，不能把角度和米混成一个分数。

雷达检测率分母为实际覆盖且满足该场景定义的探测机会；另报整个任务时间内的发现率/覆盖率，避免通过少扫描提高表面检测率。无目标场景按单位扫描时间或搜索体积报告虚警；当前未建模的噪声虚警不能记为已验证零虚警。

仅有方位的光电/被动接触不计算虚构的三维位置误差，应测方向误差、未知距离表示和由此产生的正确拒绝。若使用测距或多源融合，分别标注新增的信息来源。

位置协方差正定且模型条件适用时，可计算 eᵀP⁻¹e 并检查置信区域覆盖；奇异矩阵、强非高斯和混合航迹单列诊断，不用强行求逆获得漂亮分数。分类概率只有在输出定义为概率时才评估校准；普通效用分数不当概率。

## 七 光电和热像场景矩阵

| 编号 | 场景 | 变量及重点 |
| --- | --- | --- |
| EO01 | 可见轮廓与角测量 | 目标像素尺寸、视场、分辨率、距离、方向和部分遮挡 |
| EO02 | 型号与标识识别 | 正侧背视、装备变化、相似型号、涂装/标识、遮挡；逐级检测/分类/识别 |
| EO03 | 对比度与光照 | 明暗背景、背光、眩光、曝光、运动模糊；输出失败原因 |
| EO04 | 热通道 | 温差、推力、开火、燃尽、冷却、热诱饵；对比统一热源与观测 |
| EO05 | 资料库 | 有模板、无模板、错误/过期资料、第三方同型号与伪装民用 |
| EO06 | 边界与泄露 | 目标被遮挡但存在、换 prefab 名不换外观、隐藏阵营改变但观测不变 |

区分两类实现与报告：AnalyticEO 以明确光学/可见性参数生成抽象观测；RenderedEO 用实际渲染图像验证可见性和识别。分析模型通过不等于像素识别通过。若生产识别仍是解析模型，报告必须直说，不把真值标签加噪包装成光电视觉能力。

真实图像测试需要固定相机、图形后端和渲染配置，并保存代表性帧。无图形设备的 BatchMode 不能替代该测试；可选渲染阶段在不支持的机器上标为 UnsupportedEnvironment，发布要求必测时阻止通过。带 renderer 的热像组件只有在其输出实际进入 AI 观测链后才计入 AI 感知成绩。

识别资料库与评测场景分开版本化，保留未用于调参的姿态、装备组合和未知型号。验证已知模型与未知拒识，不仅反复测试模板原图。

## 八 干扰与多机对抗矩阵

分为 ReceiverInjection 和 EndToEndEmitter 两种模式。前者在接收端注入已知强度以测算法；后者必须从发射机位置、方向、频段、功率和工作时序经传播与接收生成贡献，才用于回答游戏中的干扰机实际能做到什么程度。

| 编号 | 场景 | 测量重点 |
| --- | --- | --- |
| EW01 | 噪声功率扫描 | 无干扰与接收端 J/S 为 -20/-10/0/10/20 dB 的探索点；转折处加密 |
| EW02 | 几何与频段 | 同/异频段、主瓣/旁瓣、距离、方向、遮挡、间歇发射；缺失耦合不得算通过 |
| EW03 | 多源干扰 | 多干扰源叠加、容量限制、目标与干扰共同变化 |
| EW04 | 欺骗量测 | 距离/速度/角度偏移、假点、渐进变化；测错误建轨、换轨、火控许可 |
| EW05 | 干扰开关与适应 | 开启前、开启中、停止后完整时间线；失锁、保持外推和恢复 |
| EW06 | 雷达互扰 | 多台友敌雷达的时频重叠和扫描几何；不能把普通多机测试当互扰测试 |
| EW07 | 通信与呼叫 | 呼叫到达/回复丢失、呼叫丢失、延迟重试、应答拒绝；真假原因隔离 |
| EW08 | 跨传感器 | 雷达受扰但光电可用、光电受遮挡但被动告警可用、共同失效 |

J/S 指同一接收机、同一时刻和带宽约定下的干扰与目标信号功率比；记录信号、噪声、杂波与干扰各自功率和单位。不能将发射功率直接当 J/S，不能直接相加 dB。无目标信号时 J/S 未定义，另报接收干扰功率；多目标时按目标分别计算。

使用相同场景、种子和预定轨迹做成对对照，先隔离信号影响。之后再开启 AI 自适应测试，允许雷达改模式、转向或切光电；单独报告其资源/暴露成本。闭环结果非单调不自动判 bug，因为 AI 可改变行为；固定算法固定几何的功率响应才适合检验预期趋势。

以连续曲线输出检测率、误差、稳定航迹比例、错误识别率和交战窗口随 J/S/距离/角度的变化；不能只给“干扰成功”一个布尔值。区分压制、诱骗、破坏身份判断和切断通信等效果，标注机制和代价。

## 九 信息足够性的判定

不设全游戏统一的“航迹质量超过某值就能做一切”。为动作定义 InformationRequirementProfile：必需观测维度、最大数据年龄、可接受不确定性、身份/授权要求、预测时域、连续支持与可用资源。

| 用途 | 所需信息 | 验证方式 |
| --- | --- | --- |
| 察觉和提高警戒 | 有可信接触或告警，不一定有距离 | 不应生成精准火控或确定身份 |
| 转向搜索与呼叫 | 可用方向/区域和许可 | 能将传感器或询问指向合理范围 |
| 型号/阵营识别 | 匹配证据、资料库和任务情报 | 分别评估分类与身份，未知保留正确 |
| 枪炮射击 | 位置、速度、时效、火控误差满足该武器条件 | 实际近失距离、命中率与误许可 |
| 导弹发射和接管 | 初始指示、交接范围、支持链路和导引头能力 | 错误接管、有效窗口、末段捕获与结果 |
| 防空拦截 | 威胁轨迹与时限、受保护对象、拦截能力 | 拦截是否来得及，是否保护成功，误耗弹 |

报告比较“AI 判断可执行”和“实际执行结果”，保留误许可、过度保守和正确拒绝。不得将不满足已设门槛等同于真实不可能；测试专用理想信息对照可估计机会损失，但必须标注 OracleControl、与生产 AI 彻底隔离，也不作为唯一成功标准。

导弹目标意图、身份和暴露评估除准确性外还需测不确定性是否诚实。保留未知比凭低质量信息给出高置信错误更符合索敌玩法。不同任务的误击、漏防和隐蔽损失代价在配置中明确，不用一个平均分掩盖。

## 十 行为与信息隔离测试

场景覆盖静默编队、预警机代询、民用/第三方/敌方混杂、未知型号、来袭弹目标不明、友军失联、干扰下回复丢失、武器损毁、资源竞争和紧急自保。

不是每个场景规定唯一动作，而是定义必须满足的约束、允许动作集合与效果范围。例如无测距能力不能凭空精确拦截；紧急自保可按授权开机；拒绝呼叫不能自动确认敌方；同 Tick 资源冲突不能双重执行。对允许多种合理战术的场景再比较结果与代价。

加入观测回放测试：固定给 AI 相同的快照、消息、策略、时钟和随机种子，只修改其不可见的真阵营/弹体目标字段，检查决策是否一致。此测试隔离 AI 输入，不让隐藏字段通过后续物理变化间接改变观测；正常闭环中，真实行为变化产生新观测后允许决策不同。

还需检查：相同报告重复转发不增信；未知距离维度保持未知；波束没覆盖不算漏检；过期回复不能认证新会话；假点来源标签不可被 AI 读取；同一接触换评测标签不改变生产判断；动作注册顺序不影响同输入裁决。

## 十一 重复试验与通过标准

探索建议每个参数点先运行 30 个独立种子，临界区域或高方差场景增加到 100 个以上；具体样本上限与置信区间精度由 Suite 配置确定。这是起始预算，不保证足以证明罕见误击风险。预热和测量时长按扫描周期、确认时间及任务窗口配置，预热不应掩盖首次发现指标。

同一运行的帧不是独立样本。统计区间按独立种子/运行分组，均值和分位数可用按运行重采样的 bootstrap；成功率给出相应置信区间。零次误击只能报告观测次数和风险上界，不能宣称误击概率为零。

区分两套门槛：ContractGate 验证强不变量，如不读真值、不可重复发射；CapabilityGate 验证具体玩法性能，如指定场景的发现率、误差、误判率和拦截率。后者必须绑定武器/传感器配置及目标任务，先测基线，再设定并版本化；不随失败结果自动放宽。

回归门槛同时使用明确的绝对要求、相对基线退化幅度、最小实际影响及统计不确定性。若区间不足以判断，记 Inconclusive 并按预算补测，不能反复重跑直到通过。探索 Sweep 与正式验证种子分开，避免用同一批随机样本调参和宣布达标。

结果状态：Passed、Failed、NotImplemented、UnsupportedEnvironment、InfrastructureFailed、Inconclusive。可选缺失项可形成部分报告；声明为 required 的能力只要不是 Passed，整套验收就不得显示绿色。禁止将“未运行”“未探测到任何目标”“日志全空”包装成零误差通过。

## 十二 CI 和本地运行阶段

| 阶段 | 触发方式与范围 | 输出/门禁 |
| --- | --- | --- |
| Preflight | 每次运行，校验项目版本、资产、必需能力、编辑器锁、许可证和输出目录 | 缺条件明确终止或标记，不能改用不等价运行时 |
| Smoke | 代码变更时，固定小种子集的契约、单目标雷达和已接通干扰注入 | 快速定位确定性错误 |
| Regression | 相关模块变更或合并前，代表性多目标、融合、生命周期、交战与行为回放 | 产出基线比较与失败复现包 |
| Sweep | 人工或未来 CI 定时触发，多种子、距离/角度/J/S 等扫描 | 能力曲线和边界，不逐次自动覆盖审定门槛 |
| Graphics | 有图形设备的运行节点，光电/热像及 Unity 场景集成 | 保存图像证据，独立环境门禁 |
| Report | 汇总上述实际执行结果 | 不同模式和缺失能力分开显示，附可重放配置 |

这是管线触发设计，本文件不创建定时自动化。Unity Tests 使用工程记录的编辑器版本，独立工作副本或确保工程未被另一个编辑器占用；不得强制关闭用户正在使用的编辑器。许可证/工程锁失败属于基础设施失败，不能记为算法失败或测试通过。

退出状态应区分通过、断言失败、基础设施失败和必需能力缺失/结果不充分，并由包装脚本映射为 CI 明确状态。产物缺失、JSON 模式不符、运行被超时终止均不可继续生成伪成功摘要。

## 十三 报告必须回答的问题

报告首页先显示各能力实际执行覆盖、必需缺口和通过状态，再呈现每种传感器/配置的能力边界：在什么距离、遮挡、目标类型与干扰条件下，能察觉、定位、识别、攻击或拦截。

必须提供五种图：真值轨迹与本机估计/不确定区叠图；距离/J/S 对检测与航迹可用率曲线；误差随时间及干扰开关标记；型号与阵营识别混淆矩阵；量测到达、身份变化、AI 决策和执行结果的统一时间线。仅有方位时画视线或不确定区域，不画伪精确目标点。

失败用例输出最小复现资产/参数、固定种子、前后事件窗口和相同命令可重放入口。报告明确是哪一层先退化：没有扫描、信号不足、量测错误、关联失败、信息过期、识别冲突、策略拒绝、资源不足或武器执行失败。不能把所有未命中都归罪于雷达，也不能把渲染可见误当成 AI 已识别。

最终结论采用“该配置在这些条件下满足某项行动需求”，不写“AI 已拥有足够信息”这样的全局结论。

## 十四 首批实现任务与交付验收

1. 建立 ScenarioSpec、能力清单、双通道记录格式和测试专用程序集边界；加入时间/坐标/缺失记录校验。
2. 扩展现有 RadarSensorSystemTests 与跟踪测试：单目标距离/速度/角度、多种子、扫描机会分母，输出条件误差与漏检。
3. 接入 ReceiverInjection 噪声和假点测试；添加无干扰成对对照，测建轨、串轨、许可和恢复。明确暂不覆盖真实干扰发射机效果。
4. 完成离线对齐/匹配、汇总、基础图表、CI 状态与 Replay；交付一份实际运行的雷达能力报告，保留现有失败而非自动修阈值。
5. 随重构 P1/P3 接入每机态势与行动日志，测多机隔离、火控信息要求、共同执行和真值泄露。
6. 随 P4 接通完整干扰传播和通信干扰；接入光电观测契约后，分别增加 AnalyticEO 与 Graphics 测试；先前缺失项转为可执行测试。
7. 随 P5/P6 增加身份、辐射决策、防空与编队闭环评价，再扩大到代表性压力场景。

第一批合格交付至少能重放一个无干扰/有干扰的雷达对照，给出误差、漏检、航迹可用率、火控许可变化与统计样本数；所有未实现光电/完整 EW 项在首页可见。只有后续能力实际接入并运行，才可声称已验证其识别或交战效果。
