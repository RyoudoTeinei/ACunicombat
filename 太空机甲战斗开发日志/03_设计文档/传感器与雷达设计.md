# 传感器、告警、电子战与数据链数值设计

> 设计状态：草案。本文只记录玩法和数值结构，尚未写入游戏代码。

## 设计目标

- 玩家操作的是传感器和火控系统，而不是直接读取场景中的真实目标。
- 主动雷达、光电、告警接收机和友军数据链提供不同质量的观测结果。
- 探测、跟踪、识别和武器解算是不同阶段，不使用一个二元“锁定”状态代替全部过程。
- 每种感知手段都必须有代价：主动雷达会暴露，光电缺少可靠距离，电子战会发热并成为辐射源，数据链会延迟或受干扰。
- 数值尽量使用有意义的物理单位；暂时无法物理化的算法能力使用 `0-100` 品质值。

## 目标自身的信号数值

每个目标至少具有以下可变特征：

| 数值 | 单位 | 作用 |
| --- | --- | --- |
| 雷达反射截面 | 平方米 | 决定主动雷达接收到的回波强度，应随观察方向变化 |
| 热辐射特征 | 相对值或瓦特 | 决定红外搜索与跟踪系统的发现距离 |
| 电磁辐射特征 | 相对值或瓦特 | 雷达、干扰机、数据链和其他发射设备工作时上升 |
| 推进器热特征 | 相对值 | 主推进和高强度姿态机动时迅速上升，停机后逐渐衰减 |
| 激光反射特征 | 相对值 | 影响激光测距和激光雷达效果 |
| 当前姿态修正 | 倍率 | 表示不同方向暴露面积、天线和发动机喷口的差异 |

这些数值不是固定“隐身等级”。同一机体在正面滑行、侧面展开武器、主推进器全开时，应呈现完全不同的信号。

| 低截获概率品质 | `0-100` | 控制波形、功率和跳频以降低敌方告警概率的综合值 |

### 距离计算原则

参考探测距离只用于标定。实际发现能力至少考虑：

```text
有效探测距离 = 参考探测距离
             × (目标当前雷达截面 / 参考目标截面)^(1/4)
             × 传感器状态修正
             × 干扰修正
             × 环境修正
```

雷达回波随距离的四次方快速衰减，因此目标截面翻倍不会让探测距离翻倍。实际系统不应该在某个距离突然由“完全不可见”变成“精确锁定”，而应通过积累观测逐渐提高航迹置信度。

### 工作模式

| 模式 | 扫描范围 | 更新速度 | 数据质量 | 电磁暴露 | 主要用途 |
| --- | --- | --- | --- | --- | --- |
| 静默 | 无 | 无 | 无主动观测 | 最低 | 依赖光电、告警和数据链 |
| 广域搜索 | 大 | 慢 | 低 | 中 | 发现未知目标 |
| 定向搜索 | 中 | 中 | 中 | 中 | 搜索已知方向或数据链提示区域 |
| 跟踪扫描 | 中 | 中到快 | 中 | 中到高 | 同时维持多条航迹 |
| 单目标跟踪 | 小 | 快 | 高 | 高 | 精确火控和武器发射 |
| 导弹支援 | 定向 | 快 | 高 | 高 | 提供中段更新或持续照射 |

雷达模式会动态改变刷新率、功耗和发热。装备面板记录的是能力上限，不是所有模式同时达到的性能。

## 光电与红外系统

光电系统包括可见光、热成像和红外搜索与跟踪。它们不主动发射电磁波，适合静默探测，但通常先得到方向，不能立即得到可靠距离。

### 建议记录的装备数值

| 数值 | 单位 | 说明 |
| --- | --- | --- |
| 参考热目标探测距离 | 千米 | 对规定热特征目标的发现距离 |
| 参考冷目标探测距离 | 千米 | 对未开主推进器目标的发现距离 |
| 识别距离 | 千米 | 能将目标从光点分类为机甲、导弹或大型载具的距离 |
| 广角视场 | 度 | 搜索模式覆盖范围 |
| 窄角视场 | 度 | 跟踪和识别模式覆盖范围 |
| 角分辨率 | 度 | 测量目标方向的精度，越小越好 |
| 搜索刷新率 | 赫兹 | 广角搜索的刷新速度 |
| 跟踪刷新率 | 赫兹 | 窄角跟踪的刷新速度 |
| 光电航迹容量 | 条 | 能同时维护的被动航迹数量 |
| 红外灵敏度 | `0-100` | 对弱热源和冷目标的综合探测能力 |
| 抗强光品质 | `0-100` | 面对恒星、爆炸、诱饵和发动机尾焰时维持目标的能力 |

### 被动测距原则

- 单次光电观测通常只有方位和俯仰，没有可信距离。
- 连续运动可通过视差和目标角尺寸逐渐估算距离，但需要时间和自身机动。
- 多机从不同位置同时观测，可以利用三角测量迅速改善距离精度。
- 主动激光测距可以直接获得距离，但会触发敌方激光告警。
- 高速接近的导弹即使容易看到，也可能因为发现过晚而没有足够拦截时间。

光电探测强度近似随距离平方衰减，并受到目标朝向、推进器状态、机体散热和背景天体影响。

## 告警系统

告警系统不等于全知提示。它只能根据接收到的辐射或光学迹象推断威胁。

### 雷达与电磁告警接收机

| 数值 | 单位 | 说明 |
| --- | --- | --- |
| 接收灵敏度 | `0-100` | 发现微弱或低截获概率雷达信号的能力 |
| 频段覆盖 | 枚举或列表 | 能监听的雷达和通信波段 |
| 测向精度 | 度 | 估算辐射源方向的误差，越小越好 |
| 更新时间 | 赫兹 | 威胁方向和状态的刷新速度 |
| 辐射源识别品质 | `0-100` | 判断搜索雷达、火控雷达、干扰机和导弹导引头类型的能力 |
| 告警航迹容量 | 条 | 可同时分析和显示的辐射源数量 |

告警等级建议分为：发现搜索信号、疑似跟踪、稳定单目标跟踪、武器照射、主动导引头接近。敌方采用跟踪扫描或低截获概率波形时，告警只能给出概率判断，不保证准确显示“已锁定”。

### 导弹与激光告警

| 数值 | 单位 | 说明 |
| --- | --- | --- |
| 导弹告警参考距离 | 千米 | 对规定发动机热特征导弹的发现距离 |
| 导弹告警覆盖角 | 度 | 机体周围可监视范围，完整覆盖上限为 `360` 度 |
| 导弹告警刷新率 | 赫兹 | 对高速小目标的更新速度 |
| 导弹分类品质 | `0-100` | 区分来袭导弹、碎片和友军弹药的能力 |
| 激光告警灵敏度 | `0-100` | 发现测距、指示和武器激光的能力 |

被动红外导弹不会因为发射动作自动触发雷达告警。玩家只能依赖光电导弹告警系统看到发动机尾焰，或通过友军、目视和战术推断发现威胁。

## 电子战系统

电子战分为电子攻击与电子防护。干扰不是让敌方雷达屏幕直接变黑，而是降低对方观测质量、制造错误航迹或迫使其改变模式。

### 建议记录的装备数值

| 数值 | 单位 | 说明 |
| --- | --- | --- |
| 干扰等效辐射功率 | 千瓦 | 决定噪声干扰在远距离上的强度 |
| 干扰覆盖角 | 度 | 定向阵列或全向天线的覆盖范围 |
| 同时干扰通道 | 个 | 可同时对付的雷达、导引头或通信链路数量 |
| 噪声干扰品质 | `0-100` | 抬高对方接收噪声、压低信噪比的能力 |
| 欺骗干扰品质 | `0-100` | 制造错误距离、速度、角度或虚假目标的能力 |
| 电子防护品质 | `0-100` | 本机雷达和数据链抵抗干扰与欺骗的能力 |
| 频段覆盖 | 枚举或列表 | 能实施干扰的雷达和通信波段 |
| 干扰启动时间 | 秒 | 从识别威胁到生成匹配波形所需时间 |

### 电子战代价与反制

- 干扰机会显著增加耗电、发热和电磁辐射特征。
- 强噪声干扰会暴露大致方向，敌方可以采用被动测向或反辐射武器攻击。
- 距离足够近时，目标雷达回波可能强到能够“烧穿”干扰。
- 雷达可通过缩小波束、提高驻留时间、改变频率、融合光电航迹来抵抗干扰。
- 欺骗干扰成功后应产生可信但逐渐异常的虚假航迹，而不是简单降低一个命中率数值。
- 诱饵、箔条、红外诱饵和拖曳式诱饵属于电子战载荷，但数量应由独立的弹药或消耗品系统记录。

## 数据链

数据链用于共享观测和火控信息。它传输的是带时间戳和误差的航迹，不是同步真实目标坐标。

### 建议记录的装备数值

| 数值 | 单位 | 说明 |
| --- | --- | --- |
| 参考通信距离 | 千米 | 无中继、无干扰、天线方向合适时的稳定通信距离 |
| 带宽 | 兆比特/秒 | 限制同时传输的航迹、图像和武器更新量 |
| 基础处理延迟 | 毫秒 | 编码、融合和排队产生的延迟 |
| 航迹更新率 | 赫兹 | 向友军发送航迹更新的最高频率 |
| 共享航迹容量 | 条 | 可同时接收或发送的目标数量 |
| 武器制导通道 | 个 | 可同时提供中段更新的导弹数量 |
| 抗干扰品质 | `0-100` | 跳频、纠错、定向传输等能力的综合值 |
| 低截获概率品质 | `0-100` | 降低通信被发现和定位概率的能力 |
| 中继容量 | 个 | 可为多少友军或导弹转发数据 |

### 数据链规则

- 航迹包必须包含来源、估计位置、估计速度、误差、置信度和观测时间。
- 接收方需要将通信延迟计入航迹年龄；旧数据不能显示成实时位置。
- 中断数据链后，本机可继续外推友军航迹，但误差会随时间增加。
- 导弹中段更新占用武器制导通道和带宽。
- 多个平台对同一目标的观测可以降低误差，但错误识别也可能通过网络扩散。
- 定向窄波束数据链更难截获和干扰，但要求双方保持天线指向。

## 航迹与传感器融合

航迹不等于真实目标。每条航迹至少包含：

- 估计位置与速度。
- 位置、速度和方向误差。
- 置信度。
- 目标分类与识别置信度。
- 最后观测时间和当前航迹年龄。
- 来源传感器及来源平台。
- 是否受到干扰或存在矛盾观测。

建议保留以下状态：

```text
疑似接触 → 已探测 → 已建立航迹 → 已分类 → 已识别 → 可生成火控解算
```

状态可以倒退。目标关闭推进器、雷达静默、脱离视场或实施欺骗干扰后，航迹应进入外推状态，误差持续扩大，最终丢失。

## 整机数值汇总原则

不同零件组合成整机时不能把所有传感器数值直接相加。

- 质量、耗电、发热、总带宽、干扰功率和独立通道数量可以累加。
- 探测距离、识别距离、刷新率、灵敏度和品质值通常取当前可用设备中的最佳值。
- 角误差、距离误差、延迟等“越低越好”的数值取最低的有效非零值。
- 覆盖角可以由不同方向的阵列组合，但总覆盖不超过 `360` 度，并应记录实际朝向，不能只相加。
- 整机有效航迹数量受传感器航迹容量、火控融合容量和数据链容量中最窄的环节限制。
- 多传感器融合提高的是置信度和抗干扰能力，不应直接把雷达探测距离相加。

## 第一版原型基准

以下仅作为首轮实验的中型机体基准，不代表最终平衡：

| 系统 | 初始基准 |
| --- | --- |
| 主动雷达 | 对 `10 平方米` 目标参考探测距离 `50 千米`；广域搜索 `1 Hz`；跟踪扫描 `4 Hz`；单目标跟踪 `20 Hz`；雷达航迹 `16` 条 |
| 光电系统 | 热目标参考探测距离 `35 千米`；冷目标 `12 千米`；识别距离 `8 千米`；光电航迹 `6` 条 |
| 雷达告警 | 测向误差 `10 度`；刷新 `4 Hz`；告警航迹 `16` 条 |
| 导弹告警 | 对工作中发动机参考距离 `15 千米`；覆盖 `360 度`；刷新 `10 Hz` |
| 电子战 | 同时干扰 `2` 个目标；噪声干扰品质 `50`；欺骗品质 `35`；电子防护品质 `40` |
| 数据链 | 参考距离 `100 千米`；带宽 `8 Mbps`；处理延迟 `50 ms`；航迹更新 `10 Hz`；共享 `32` 条航迹；制导 `4` 枚导弹 |

这些基准的意义是让系统尽快进入可测试状态。实际平衡应根据典型交战距离、机体加速度、导弹飞行时间和玩家可处理的信息量共同调整。

## 2026-07-23 雷达、航迹操作与火控原型实现状态

本节记录已经写入 Unity 工程并通过 C# 编译的原型能力。本文开头的“尚未写入游戏代码”只适用于早期草案，不再代表当前状态。

### 已实现的数据边界

- 雷达显示层只读取 `TrackSnapshot`、`RadarEchoSnapshot` 和 `RadarStatusSnapshot`。
- `TrackSnapshot` 只包含估计位置、估计速度、协方差、航迹质量、生命周期、来源与估计阵营，不携带目标 `Transform`、真实速度或真实型号。
- 场景中的 `CombatTestTarget` 只在传感器仿真入口作为真值源生成测量，HUD、火控和导弹都不能直接访问它。
- 当前分类器尚未实现，因此新建雷达航迹默认是 `Unknown`，分类和身份置信度为零。HUD 不会因为测试目标本身的阵营字段而泄漏真实身份。

### 已实现的雷达与航迹流程

```text
搜索驻留 → 测量/单次回波 → 临时航迹 → 三次命中确认
        → TWS 候选 → 玩家指示 → STT → 火控解算 → 开火许可
```

- 单次扫描不会直接生成稳定 TWS 航迹。
- 航迹支持临时、确认、滑行、降级和丢失生命周期；失去测量后先按协方差外推并降低显示亮度。
- SEARCH 覆盖区为 `100° × 60°`，由 `12°` 波束按 `13 × 8` 蛇形光栅扫描；方位/俯仰网格间距约 `9°`，相邻圆锥重叠以消除对角盲区。传感器每 `40 ms` 消费 4 个搜索驻留，完整扫掠约 `1.04 s`。
- 扫描帧开始时锁定当前瞄准方向作为扫描中心，帧内波束按固定光栅推进；HUD 扫描线读取实际驻留方向，不使用独立动画伪造扫掠。
- TWS 在背景光栅中插入现有航迹预测方向的 `8°` 重访驻留，少量航迹时基准重访间隔为 `0.24 s`。
- STT 使用目标预测方向的 `6°` 窄波束，基准驻留间隔为 `0.035 s`；同时将背景搜索降为每个传感器 Tick 2 个驻留，完整扫掠约 `2.08 s`，不完全关闭态势搜索。
- STT 获取时间按航迹质量在约 `0.22-0.45 s` 之间变化；目标离开雷达框架角、质量不足或航迹丢失时不强制建立 STT。
- 制导通道由雷达控制器统一分配、保留和释放，并通过公开状态提供给 HUD。

### HUD 与操作

- 左上角为 360° 综合战术态势图：采用航向向上和离散自适应量程，只保留放大的圆形距离图、相对方位、航迹编号、距离、垂直差、速度矢量和来源，不显示本机、航迹统计及量程摘要文字。
- 航向向上的基准必须使用摄像机/飞控逻辑航向，不能使用包含模型朝向补偿的机体根节点 `transform.forward`；三角形尖端、地图 `000` 和屏幕正前方必须一致。
- 右下角为放大的前向雷达状态图：参考现代战斗机/《战争雷霆》的扇形显示，绘制四级距离弧、方位分隔线、实际搜索波束带、俯仰光标及覆盖扇区内的航迹编号和距离。
- 右下雷达使用独立的 `5/10/20/40/80/最大量程 km` 离散显示档位，并以滞回规则自动切换；显示量程只决定画面比例，不改变传感器最大探测距离。
- 右下角以距离弧标注当前显示量程，不单独显示显示量程、探测上限及扫描几何参数文字；保留 SEARCH/TWS/STT、当前波束方位/俯仰、扫描帧进度、航迹容量、搜索刷新、目标重访、驻留负载、制导通道、STT 编号和降级标志。
- 两张图职责分离：左上回答“战场上有哪些公开航迹”，右下回答“本机雷达正在如何扫描”，不能把前向雷达扇区误当作 360° 战术态势。
- `SCAN` 表示完整搜索体积刷新率，`REVISIT` 表示当前跟踪目标重访率。现代 AESA 可在毫秒量级切换电子波束；高重访率不等于机械天线以相同速度旋转。
- `Tab` 只切换航迹操作 HUD，不关闭雷达。
- 航迹操作模式显示中央绿色虚线大圈和小准星。只有确认航迹参与鼠标指定；小准星中心必须进入目标 `54 × 54 px` 四角框并持续停留才请求 STT，离开四角框立即清空获取进度，不强制转动摄像机。
- `T` 解除当前 STT，优先退回 TWS；`G` 循环选择可用确认航迹。这些按键字段可在 Inspector 中重新绑定。
- 临时航迹、确认航迹、候选、STT 和滑行航迹分别使用闪烁框、稳定框、琥珀色单框、加粗红色单框加文字、虚线衰减表达。临时航迹只允许四角框闪烁，编号、距离、质量和来源文字不得随框闪烁。
- 世界目标标记只绘制一个主框；候选和 STT 通过颜色、线宽和文字区分，不再叠加第二层候选框。
- 显示层会把雷达分辨率内位置和速度近似一致的重复航迹合并为一个标记，优先保留 STT、候选和高质量确认航迹；原始航迹仍保留给火控和调试。
- 普通 HUD 不显示 `Q < 0.35` 的确认航迹、命中少于两次或 `Q < 0.40` 的临时航迹、`Q < 0.35` 或连续漏检超过四次的滑行航迹，也不显示降级航迹；STT 与玩家候选航迹始终可见。
- 原始单次回波只在 `Tab` 航迹操作模式中短暂显示；已被现有航迹吸收的回波不重复绘制，避免把一次目标测量表现成多个目标。
- HUD 使用暗色半透明底和高对比荧光绿色细线。集成雷达 HUD 存在时，旧的左上角机体/演示调试文字自动停用，防止覆盖战术态势图。
- 红色不是 STT 的唯一提示；STT 还必须使用更粗的四角框和 `STT` 文字。

### 航迹可靠性约束

- 搜索、TWS 和 STT 驻留可能在同一个仿真 Tick 内测量到同一目标。航迹关联器必须允许这些测量继续关联到本 Tick 已命中的航迹，不能因为“已经命中过”而新建重复航迹。
- 同一 Tick 的多次关联可以继续修正滤波器，但生命周期只计一次命中，避免驻留重叠把单帧测量伪装成多帧确认。
- 已命中的航迹在该 Tick 末尾不得再记一次 miss。未命中时，只有本 Tick 实际雷达驻留波束覆盖航迹预测位置且仍无量测，才记一次 miss。
- 以上规则优先解决“起飞后出现大量假目标”和“确认航迹反复退回临时状态”的根因；不能只在 HUD 层隐藏重复标记。

### 航迹漏检与高速目标关联约束

- 航迹融合 Tick 不等于雷达对每条航迹完成了一次有效观测。航迹漏检必须根据发射事件中的波束方向、波束宽度和有效量程判定观测机会，不能按仿真帧计数。
- 没有新量测的普通融合 Tick 只允许航迹继续预测，不得立即增加漏检计数或把确认航迹推进滑行状态。
- 新建航迹的速度先验必须覆盖当前作战包线以及本机和目标的相对速度。当前原型采用 `300 m/s` 的一倍标准差初始速度不确定度，并使用平方马氏距离 `25` 作为关联门限。
- 回归测试必须覆盖单个目标以 `100 m/s` 飞行、雷达每 `0.2 s` 重访一次、连续运行 `6 s` 的场景，并保证只维持一条确认航迹，不能形成滑行航迹拖尾。

### 火控与导弹

- 火控只读取选定航迹的 `TrackSnapshot` 并生成 `FireSolution`。
- 发射许可检查航迹生命周期、解算有效性、武器框架角、预计捕获质量和制导通道。
- 主动雷达导弹允许由高质量确认航迹发射，先使用公开航迹进行中段更新，当前原型在限定时间后切换为末段阶段。
- 半主动雷达导弹要求 STT；红外导弹不强制要求雷达 STT，但仍检查当前解算质量；指令制导占用火控制导通道。
- 导弹飞行中不持有目标 `Transform`，航迹短暂丢失时按最后公开状态外推，超出允许时间后失去制导。

### 仍未完成

- 阵营、目标类别和型号的传感器分类器尚未实现；当前航迹应正常显示为未知目标。
- 光电、ESM 和数据链尚无独立测量生产器；公开契约和 HUD 已能表达这些来源，但不能把“可显示”视为“已完成仿真”。
- 主动雷达导弹末段目前是阶段切换和航迹外推框架，尚未实现独立的弹载雷达扫描、捕获和抗干扰模型。
- 当前 HUD 是 IMGUI 原型。固定数组避免了航迹集合的逐帧分配，但字符串和 GUI 绘制仍会产生托管开销，正式版本应迁移到项目显示层并缓存格式化文本。
- 丢失航迹目前主要依靠滑行/降级阶段表现；如需航迹被删除后仍保留数帧最后预测位置，应增加专用的只读 tombstone 显示快照。
