# 雷达与友军数据链共享态势融合

2026-10-17 完成收尾；测试目录保留启动时的 20261016 名称。

## 实现

新增观察者独立的 MechCooperativeTrackFusion，将本机雷达航迹和已经收到的可信友机自身导航报告关联。输入仅来自观测/收到的报告，不读取其他机体 Transform 来决定匹配。报告产生端仍使用既有友机自身导航及物理数据链投递路径。

双方预测到同一时刻，位置与速度分别使用完整协方差计算 NIS；采用互相唯一且有足够分离度的一对一匹配。需要两次双方都更新的独立证据才能确认，不以重复包或重复查询累加确认。保留航迹完整代际，歧义、过期、未来时间和可信敌方身份冲突时不强行继承友方身份。误差过大到无法可靠关联的雷达回波也不据此确认身份。

关联后输出融合位置/速度、友方身份、已知机体类型与原始信源时间；不反写原始雷达滤波器。数据链独立报告在未关联时也进入同一个公共快照集合。报告超过三秒失效后撤销由其提供的融合，不把它刷新为新雷达观测。

## 兼容边界

地图绘制和询问应答文件未修改。MechRadarController.CopyTracks、TryGetTrack 和已有身份读取适配器使用共享结果，AI 原有读取路径随之接通。旧 CopyReports 显示分流接口保留但返回空列表，避免未改动地图再把已经进入统一输出的友机报告添加一次；原始报告诊断使用新增 CopyReceivedReports。

因此数据链独立联系人现在使用统一航迹入口的标识显示，不再由地图另造一份友机联系人。匹配成立后沿用本机雷达 TrackId。候选确认期、真正关联歧义和报告过期仍可出现独立/未知联系人，这与错误重复显示不同，不能为了凑固定数量强制合并。

同时调整导弹缓存刷新顺序，避免雷达内部使用 trackScratch 时被缓存刷新覆盖融合身份。新增回归强制刷新缓存后检查内部读取仍有相同的两名友军。

既有友机登记以同队准入为信任基础，本轮没有实现或替代询问应答认证协议；也没有新增敌方航迹共享或编队任务分配。

## 验证

首轮融合与地图原有测试 37/37。

综合 178 项中 176 通过，LogFast2020Stationary30Fps 和 LogFast2020Strafe30Fps 首次失败，日志为定位不确定度/安全引爆窗口拒绝。最终专项 41/41，包括上述两项复跑、39 项融合与地图测试。保留初次失败，不宣称单批 178/178 或永久解决 APS 间歇时序问题。

真实 Unity PlayMode 用例通过正式雷达、物理数据链和未修改地图刷新接口运行 15 秒；预热后连续核对 276 帧：4 个共享外部联系人、其中 2 个友方；地图总共 5 个联系人（包含本机），AI 的真实目标可用性判断排除两名友军。列表读取、按 ID 查询及雷达内部缓冲读取一致。

其它测试覆盖旧 150m/100m/s 门槛外的合法协方差关联、歧义交叉、代际隔离、重复报告、信息过期、敌方身份冲突、多观察者隔离、仅有数据链报告和非法时间。

当前主项目运行时代码编译通过，只有现存 API 弃用警告。测试在隔离 URP 工程执行；未运行主项目全量批处理，也未宣称玩家实际那局已人工复验。

证据：Artifacts/SensorBench/Cooperative-Fusion-20261016-regression/results.xml；Cooperative-Fusion-20261016-final/results.xml 与 verification.json。
