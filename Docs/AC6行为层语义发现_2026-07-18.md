# AC6 行为层语义发现：官方状态名与动作衔接数据

日期：2026-07-18

背景：动作库管线搭好后的疑问——解包素材里没有动作标签，衔接数据也不知在哪，是否每个动作都要人工审查。本文是调查结论。

## 1. 结论先行

1. **解包素材本身确实没有任何动作标签**。HKX 无名；TAE 的 name 字段只是 anim ID→文件映射；`chr/c0000.behbnd.dcx` 解出的 `basenormal.bhv`（1.34MB 主行为图）与 `w0xx.bhv`（按武器类别）是 FromSoft 私有二进制（magic 0x0005/0x0003），字符串区只有骨骼名，状态名一个没有。
2. **但不需要逐个人工审查**：社区仓库 [soulsmods/ac6-bhv-debug](https://github.com/soulsmods/ac6-bhv-debug) 提供了 AC6 v1.03 的 BHV 调试元数据——**官方日文状态名 + 完整转换图**。已拷贝到 `Tools/BhvDebug/c0000/`（随本提交入库）。
3. 人工审查收敛为：BHV 解析器（见第 5 节）做出来后抽查即可。

## 2. 调试元数据内容

`Tools/BhvDebug/c0000/`：

| 文件 | 内容 |
| --- | --- |
| `basenormal_dbg.json` | c0000 主行为图 **222 个状态**：`StateName`（官方日文名）+ `NextStates`（目标状态 + 触发条件，如"パッド入力 ジャンプ"） |
| `basenormal_dbg.csv` | 纯状态名列表，**行号 = 编译 BHV 内状态索引（1:1 对齐）** |
| `w010~w1000_dbg.*` | 按武器类别的行为图调试名——对应 `c0000_a2xx` anibnd bank，是"武器类别→bank 映射"遗留项的钥匙 |
| `atklist_dbg.json` | 攻击列表调试名 |

## 3. 对判定表的印证与裁决

- **着地三级**：状态 61/62/63（硬直極小/小/ドスン）与判定表 `011000/011010/011020` 轻/中/重完全对应——判定被官方语义印证。
- **制动族**：状态 68-76（ブレーキ開始/ループ/から待機 + 回り込み左右）对应 `0101x3` 制动段的结构判定。
- **QB 悬案可裁决**：QB 有独立状态族（77/78/79/80/82…共 17 个），与ブーストダッシュ/ブースト飛行分离——"QB vs 普通 boost travel"的区分在行为层是明确的两组状态，等 anim ID 连接后即可终裁。
- 注意：搜索"ホバ/浮遊"零命中——悬停待机（a000_010900）在官方词汇里可能叫别的（待機系或ブースト飛行系），同样等 anim ID 连接裁决。

## 4. 动作衔接数据的三层来源

1. **BHV 转换图**（本次获得）：官方状态→状态的转换拓扑与触发条件——衔接关系本身。
2. **TAE Blend 事件**：每条动画开头的 Blend 事件（实测 0.07~0.17 s）就是官方 blend-in 时长。可从现有 `Tools/LocalOut/c0000_tae_dump.json` 自动抽取，填动作清单的 `blendInSeconds`，不用拍脑袋。
3. **ID 结构约定**：x0 进入 / x1 过渡 / x2 稳态循环 / x3 制动退出的序列骨架（判定表 §2）。

## 5. 剩余缺口与工具项：BHV 状态表解析器

调试 JSON/CSV **不含 anim ID**。名字与动画的连接依赖："CSV 行号 = 编译 BHV 状态索引"这一 1:1 对齐，需解析 `basenormal.bhv` 二进制状态表提取每状态的动画引用。

- 直接按 u32 LE 搜已知 anim ID（10900/10100/22200…）在 bhv 里基本无命中——动画引用经过编码或索引表，需正经逆向状态表结构。
- 做出解析器后产出：**状态名 → anim ID → 转换图**的全自动标签表，动作清单的语义标注与衔接配置都从它生成；判定表三个目检项（QB 区分、四方向朝向、080xxx 语义）大概率直接裁决。
- **版本警告**：调试数据按 1.03 索引对齐；本机为 coop mod 构建，解析器完成后先用状态总数（222）与结构特征验证对齐无漂移，漂移则不能直接按索引对名。

## 6. 复现路径

```text
behbnd 解包：BND4.Read("Resources/Game/chr/c0000.behbnd.dcx")（SoulsFormats + Oodle dll，
             参考 Tools/DotNet/AC6AnimExportProbe 的依赖）
调试数据源：github.com/soulsmods/ac6-bhv-debug（已拷入 Tools/BhvDebug/）
状态名解码：JSON 为 UTF-8 BOM；CSV 为 UTF-16 LE
```
