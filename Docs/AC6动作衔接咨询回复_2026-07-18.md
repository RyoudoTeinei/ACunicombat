## 2. 问题 4.1：QB 物理动作恢复（已解决）

**证据链**（全部本机可复现）：

1. 枚举四个 `c0000_a000_XX.anibnd.dcx` 的 binder 内容共 266 条 a000 HKX：**`a000_0224xx` 不存在任何 div**；但 `a000_022300`（ジャンプ加速，BHV 状态 29 引用 TAE 22300）**存在**——说明"BHV 引用的 TAE ID 无同名 TAE 行"不阻碍物理文件存在，两层是独立的。
2. TAE 别名机制有直接先例：TAE 行 22200 的 name 指向 `a000_004220.hkt`（ID 与文件号不同）；`a000_120200` 的 TAE 行 ID 是 26700、`a000_100002` 是 100000——**name 字段是唯一权威映射，ID 与文件号同号只是巧合居多**。
3. `a000_004240-43` 四个文件：0.67 s、根骨冲量 4.9-8.5（全库最高一档）、42/43 躯干侧倾左右镜像、每条 68 个 TAE 事件且含 0.17 s 不可取消头 + 密集 Cancel 旗标——QB 的运动学与事件签名完全吻合，且数量正好四方向。
4. BHV 侧 QB 状态族（77 QB / 78 ロック時 / 79-80 BD 中 / 82 空中）引用 TAE 22400/22410/22420/122400，方向变体 x0-x3 与 004240-43 一一对应。

**对咨询三个子问题的回答**：

- 4.1.1：是。22400 系不引用同名文件，按 22200→004220 同款别名落到 `a000_0042xx`。
- 4.1.2：映射位于 **TAE 行的 name 字段**（不在 compendium/BHV action index）。本构建的 TAE 缺 223xx/224xx 行——要么 coop mod 重打包时裁剪，要么原版这些行在我们未转储的 TAE 分片里。
- 4.1.3：`c0000` 的 HKX 解包**不缺**（004240-43 就在 div 里）；缺的是 TAE 行。建议从原版（非 coop mod）`c0000.anibnd.dcx` 重转一次 TAE 对比验证别名行；但**不阻塞**——QB 素材本身现在就能导：

```powershell
powershell -File Tools/BuildAC6ActionClips.ps1 -ActionId a000_004240,a000_004241,a000_004242,a000_004243 -Force
```

标注建议：`OfficialMapped(ByAlias)`，manualNote 写明别名推断依据，与直接命中区分。

## 3. 问题 4.2：IR 设计建议

**建议两段式，不直接转译 BHV**：

1. **可审计 JSON 行为图**（`c0000_bhv_state_map.json` 已是雏形，补三样）：每状态的辅助动画槽（状态记录 +0x16 的 u16 也是动画条目索引，如 QB 的辅助槽 e14→TAE 20022、飞行系的 e3→TAE 101，疑似附加姿态/倾斜层）；转换目标的双重验证结果（我方解析器已做 222/222 转换数 + 5746/5746 目标全验证，方法可并入）；每动画的 TAE Blend 时长（见 §5）。
2. **Unity Builder 编译成 ScriptableObject 状态图**。最小 IR 字段：

```text
StateNode {
  stateId, officialName,
  primaryAction (actionId + clip 引用), auxActions[],
  blendInSeconds (来自 TAE Blend 事件), loop (来自动画时长与循环误差),
  transitions: [ { targetStateId, conditionText[], conditionInput (人工映射的输入枚举), order } ]
}
```

3. 转换裁决顺序第一版就用**转换列表的数组序**（BHV 存储序 = 调试 JSON 的 NextStates 序，先命中先走）。条件二进制段暂不转译（见 §4），`conditionInput` 由人工按调试文本映射到你们的输入系统枚举——最小子图只有十几条转换，人工映射一小时内完成且可审计。

## 4. 问题 4.3：BHV 转换条件解读（现状与建议）

**已确定**：条件的可读文本在调试 JSON 每条转换的 `Conditions` 数组里（如"パッド入力 ジャンプ"、"ターゲットロック中 固定ロック中"、"接地"系）；转换记录二进制里每条带 condListOffset/condCount，指向条件参数记录——**该记录的字段编码尚未逆向**。版本漂移问题已排除（双验证全过，coop 构建与 1.03 调试数据零漂移）。

**建议**：最小闭环不解条件二进制。按文本人工映射：パッド入力系→输入按键；ターゲット系→锁定状态布尔；接地/空中→你们运动模拟的 grounded 标志；能量系→暂时恒真。动作未播完可否跳转：以 TAE 的 Cancel 旗标窗口为准（QB 头 0.17 s 内无 Cancel 旗标=不可打断，之后逐类开放——这个数据 dump 里已有，builder 可直接抽）。

## 5. 问题 4.4：TAE Blend 事件（实测数据，替换 0.15 常量）

Blend 事件挂在动画头部，`endTime` 即官方 blend-in 时长。最小闭环全套实测：

| 动作 | TAE ID | 官方 blend-in (s) |
| --- | --- | --- |
| a000_000000 待機 | 0 | 1.0（慢融合） |
| a000_020200 地上ブースト | 20200 | 0.4 |
| a000_020210 ブーストダッシュ | 20210 | 0.533 |
| a000_120200 ブースト飛行 | 26700 | 无 Blend 事件（沿用上游或瞬时） |
| a000_004240-43 QB 四方向 | 4240-43 | 0.133 |
| a000_025000/025100 ブレーキ | 25000/25100 | 0.133 |
| a000_100002 自由落下 | 100000 | 0.4 |
| a000_004200 着地 | 4200 | 0.033（近硬切） |
| a200_030020 抬臂 | 30020 | 0.1 |
| a200_030022 保持 | 30022 | 0.1 |
| a200_030030 开火 | 30030 | **无 Blend（硬切，后坐要瞬时）** |

规律清晰：待机类慢融、移动类 0.4-0.53、QB/刹车 0.133、开火硬切。Builder 应直接从 `c0000_tae_dump.json` 抽 Blend 事件填 `blendInSeconds`，无事件者填 0（硬切）并允许状态图上游指定。blend-out 无独立事件——AC6 的退出融合由**下一个**动作的 blend-in 承担，`blendOutSeconds` 应废弃或恒 0。

## 6. 问题 4.5：武器行为图对齐（部分回答）

`Tools/ParseBhvStateTable.py` 与 BHV 格式对 `w0xx.bhv` 同样适用（w010 已验证：9 状态解析成功，状态名=待機/射撃待機/射撃開始/射撃/射撃終了等）。武器 BHV 动画条目引用的是**武器自身 TAE 的小号 ID（0-5）**，不是 a2xx——机体上半身与武器动作的联动不在武器 BHV 里，大概率由引擎按"武器类别参数→机体 a2xx bank"选择（EquipParamWeapon 侧，仍待 paramdef）。第一版按现行 a200 暂定映射走人工目检确认即可；w020（步枪类）的状态序列（待機→射撃開始→射撃→射撃終了）可作为上半身层的官方序列参照——与 030020→030022→030030 的暂定映射结构一致，佐证该映射方向正确。
