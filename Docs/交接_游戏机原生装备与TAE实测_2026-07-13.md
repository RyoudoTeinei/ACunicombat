## 5. 武器 TAE 已提取，但运行时尚未接通

`WP_L_0010` 的 `a000_040010` 成功提取 3 个特效事件：

| 时间 | FFX ID | DummyPolyID |
|---:|---:|---:|
| 0.4000 | 992011 | 300 |
| 1.0667 | 992015 | 235 |
| 2.1667 | 992012 | 300 |

本机产物：

```text
Tools/LocalOut/wp_l_0010_tae_dump.json
Tools/LocalOut/effect_timelines/a000_040010.json
```

这里发现了明确的集成差异：机体 TAE 使用带槽位前缀的 `DummyPolyID`，当前 `MechActionEffectPlayer` 可按前缀映射到头、核心、手臂、腿和四个武器槽；武器自身 TAE 的 `235/300` 是装备内部本地 dummy，没有槽位前缀。若直接交给当前机体路由器，前缀为 0，会被判定为 `MechPartSlot.None`。

因此后续必须增加装备本地特效播放模式：

1. `MechEquipmentAnimationPlayer.PlayAction` 同时启动该装备动作对应的 effect timeline。
2. 装备 timeline 直接在当前装备实例内部按 `_dmy_235`、`_dmy_300` 查找，不再走机体千位前缀路由。
3. 事件时间应与装备动画时间源同步，并处理循环和动作中断。
4. 机体悬浮动作的 4 个 FXR 已能生成真实 Unity 预制体；武器侧 `992011/992015/992012` 仍需翻译并接入装备本地播放器。
5. 将武器发射 EFFECT 行纳入 Unity 验证报告，断言生成点位于对应装备边界内且方向沿 dummy 的 `-Z`。
