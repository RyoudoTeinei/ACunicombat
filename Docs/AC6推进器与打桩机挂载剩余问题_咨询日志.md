# AC6 推进器与打桩机挂载剩余问题咨询日志

更新日期：2026-07-12

## 1. 当前工程状态

工程已经完全停用 Blender 烘焙管线。机体、武器和推进器均从 AC6 生素材经原生 FLVER/HKX 到 glTF/GLB 管线进入 Unity，保留蒙皮、骨架、dummy、材质和原始动作。

目前已经完成：

- 1010、2010、3010 以及两套混装机体的统一骨架换装与原始动作播放。
- 手持、背部武器按核心/手臂 dummy 安装，背部武器方向与核心侧支架骨动作已经基本正确。
- 武器和推进器各自保留独立原始动作播放器。
- 五套 loadout 的结构、接口骨同步和基本挂点验证能够通过。

但最新人工检查仍发现两个视觉错误：

1. `WP_L_0010` 打桩机与左手/前臂重叠。
2. 三种核心上的部分推进器模型与核心外壳分离，像悬浮在挂点附近。

自动验证过去只证明“装备根跟随目标 dummy”，不能证明安装语义和可见几何正确。

## 2. 打桩机问题

### 2.1 已确认的根因

样例代码曾把 `WP_L_0010` 错写成普通左手步枪，因此它被分配到掌心 `_dmy_23`。

重新读取原始参数后确认：

- `EquipParamWeapon` 的模型 ID `10` 是 `PILE BUNKER - PB-033M ASHMEAD`。
- 该行 `absorpParamId = 200`。
- `WepAbsorpPosParam` 行 200 的左侧挂点是 `3025`。
- `3xxx` 表示手臂部件，后三位 `025` 对应左前臂 `_dmy_25`。
- 普通枪械行 100 才使用 `3023`，即掌心 `_dmy_23`。

因此 `WP_L_0010` 必须带 `melee` 标签并由 `_dmy_25` 挂点接收，不能再走枪械挂点。

### 2.2 当前本地修复

`AC6SkinnedModularSampleBuilder.cs` 已做以下改动：

- 将 `WP_L_0010` 更名为 `Native Pile Bunker ASHMEAD 0010`。
- 将其标记为 `isMelee: true`。
- 默认动作改为原生静止动作 `a000_000000`。
- 装配时不自动播放近战攻击/展开动作。
- 验证器要求所有近战装备默认静止且禁止自动播放攻击动作。

修复后的报告已经显示它选择了 `AM_M_1010_dmy_25`，而不是 `_dmy_23`。2026-07-12 07:03 的最新重建中，五套 loadout 自动验证为 5/5；新近景里打桩机已经沿左前臂安装，不再使用掌心挂点。但仍需由原游戏参考确认其收纳姿态和局部穿模，不能仅凭挂点编号宣称完全闭环。

### 2.3 仍需确认的问题

即使目标 dummy 已改为 `_dmy_25`，仍需确认：

1. `WP_L_0010` 的模型根是否就是前臂安装原点，还是还需要武器侧握持/吸附基准。
2. `a000_000000` 首帧是否是正确收纳姿态，或应该使用另一条常驻姿态动作。
3. 打桩机在静止、蓄力和击发时，机体动作与武器动作应该如何同步触发。
4. 原游戏是否会隐藏/切换打桩机的部分 mesh，当前重叠是否包含可见性状态遗漏。

## 3. 推进器问题

### 3.1 已确认的数据

每个核心 GLB 内都有三个 `_dmy_800`：一个前胸制动喷口和两个背部主喷口。三种核心的位置不同，当前构建器已经分别保存了 1010、2010、3010 的绑定姿态金标。

推进器原始模型不是静态装饰：

- 每个 `BS_A_x010` 都有自己的 mesh、骨架和原始 HKX 动作。
- 模型内部还有 `_dmy_31`、`_dmy_41`、`_dmy_51`。
- `BoostParam` 使用 31/41/51 作为推进器效果相关 dummy。
- 当前装配会在核心的三个 `_dmy_800` 下各实例化一个推进器可见模型。

原始 FLVER 中央 dummy 31 的位置如下：

| 推进器 | `_dmy_31` 原始位置（约） |
| --- | --- |
| `BS_A_1010` | `(0, 0.014, -0.528)` |
| `BS_A_2010` | `(0, 0.012, -0.485)` |
| `BS_A_3010` | `(0, 0.082, -1.025)` |

这些点位于模型中心之外或接近喷口端，不能在没有游戏装配依据的情况下直接当作模型安装根。

### 3.2 已发现的动作状态错误

旧样例把推进器默认动作设为 `a000_000001` 并在装配时自动播放。该动作是工作/偏转动作，其首帧已经使推进器机构相对安装框架产生偏转，因此静止场景也可能看到模型错位。

当前本地修复改为：

- 默认动作使用 `a000_000000`。
- 装配时不自动播放推进/偏转动作。
- 工作动作仍保留，后续由飞行状态显式触发。

2026-07-12 07:03 的最新重建确认三个推进器实例的根节点相对各自 `_dmy_800` 都是零位移、零旋转、单位缩放，五套 loadout 自动验证全部通过。然而新生成的 `Closeup_Uniform1010/2010/3010_Boosters_t000.png` 仍能看到可见推进器组件通过细长结构悬在核心外壳上方。由此可以确定：动作误触发是一个真实问题，但不是剩余视觉错位的全部根因。

### 3.3 已排除的试验方案

曾试验把推进器内部 `_dmy_31` 强制对齐到核心 `_dmy_800`。结果会把 1010/2010/3010 推进器根分别额外移动约 0.5m、0.5m、1.0m，并在截图中把可见喷口进一步推出核心外壳。

该方案也与上一轮咨询结论“核心 `_dmy_800` 的坐标系已经编码安装朝向，模型根 identity 安装”冲突，因此已经从代码中撤销，不能作为正式解决方案。

### 3.4 当前真正卡点

目前还缺少 AC6 原游戏对 Booster 的完整装配实现或等价数据链。DSAnimStudio 对 AC6 Booster 也没有可直接照搬的完成实现。

需要确认的不是再试一个局部偏移，而是下面四层语义：

1. 核心 `_dmy_800` 是完整推进器模型安装点，还是只用于喷焰/SFX 的发射点。
2. 一个 `BS_A_x010` FLVER 应实例化三次，还是只实例化一次并用其内部 31/41/51 对应三个喷口。
3. 推进器模型根、骨架 bind pose、`a000_000000` 首帧和内部 dummy 的矩阵应按什么顺序组合。
4. 核心外壳是否已经包含固定喷口几何，Booster mesh 只表示内部活动机构；若是，应该显示哪些 mesh。

只要这四点没有从原游戏逻辑或可靠工具实现中得到证据，单纯让两个 Transform 数值重合仍可能产生“验证通过但视觉错误”。

## 4. 希望咨询方重点回答的问题

1. AC6 在装配 `BS_A_*` 时，是否把完整 FLVER 根以 identity 分别挂到每个核心 ref 800？
2. 核心的三个 ref 800 与 Booster 的 ref 31/41/51 分别是什么语义，是否存在一一映射？
3. Booster 应该实例化一次还是三次？如果三次，三个实例是否使用同一个完整 mesh？
4. `a000_000000` 是可信的常驻静止姿态吗？装配后是否必须先采样该动作才能得到正确外观？
5. Booster 是否依赖 TAE 事件控制 mesh 可见性、骨骼状态或效果挂点？
6. `WP_L_0010` 除了使用 `WepAbsorpPos 200 -> 3025` 外，是否还存在武器侧安装矩阵或收纳动作要求？
7. 能否提供原游戏或社区工具中的明确矩阵链，至少覆盖一个核心、一个推进器和 `WP_L_0010`？

## 7. 完成标准

后续修复至少需要同时满足：

1. 打桩机在静止姿态不再与手掌重叠，安装到前臂且外观符合原游戏收纳逻辑。
2. 三种核心的前胸和背部推进器都与各自外壳连接，无悬浮、无明显穿模、朝向正确。
3. 静止和动作中点都保持正确，不能只在单帧调好。
4. 武器攻击和推进器工作动作按状态显式触发，不在装配时自动播放。
5. 五套 loadout 的接口骨同步、挂点和动作验证仍全部通过。
6. 正式方案只使用原生素材管线，不恢复 Blender 烘焙资产。
