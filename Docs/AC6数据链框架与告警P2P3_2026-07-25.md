# AC6 数据链框架 + 告警 P2/P3 实现

日期：2026-07-25。三件事一起落地：**数据链正式框架**（面向无人机/僚机/导弹/
拦截系统的可扩展地基）、**告警 P2**（识别置信度、波形库数据文件、告警历史）、
**告警 P3 红外通道**（MAW）。全程未编译（本机资源占用中）。

## 1. 数据链框架（新程序集 `ACunicombat.DataLink`）

```
终端注册（LinkTerminalProfile：功率/天线/灵敏度/网络）
  → Send(LinkMessage)（Heartbeat / TrackShare / GuidanceUpdate / Command）
  → DataLinkSystem.Tick：写 EmissionEvent（可被 ESM 侦听！）
      + 物理投递：单播定向波束指向被寻址实体 / 同网组播全向
      + 单向 1/R² + 接收灵敏度判决 + 余量不足 6dB 线性丢包（确定性种子）
  → 每终端收件箱（按 Tick 清空，消费端 Sequence 去重）
```

框架特性（为无人机/僚机/拦截弹预留的正是这些）：
- **终端 = 平台上的电台**，64 槽 + Handle 世代号；`NetworkId` 分网（0=制导网，
  编队网/拦截网往后加号即可）；报文载荷是 `TrackSnapshot` 等契约——链路搬运的
  永远是感知产物而非真值，信号级纪律不破。
- **链路本身是辐射**：上行波形（band 2, waveform 10）进波形库 → 敌方 RWR 解出
  `DataLinkUplink` 类 → **早于 pitbull 的"有弹在飞"软告警**（Tracked 级钉底）。
- **断链是物理事件**：载机被击落（发射终端 owner 死亡）报文自然消失；出距离、
  余量不足丢包；干扰接入点已留 TODO（margin −= JamContribution）。
- 一 Tick 固有时延（发送入队 → 下一传感器 Tick 投递）。

### 制导链路重构（吃自己的狗粮）

导弹中段修正从"每帧直读航迹库"改为**纯报文消费**：
- 发射端：`MechRadarController.PumpGuidanceUplinks` 按 0.25s 周期把航迹快照
  经链路发往在飞导弹；**再捕获逻辑从导弹端移到发射端**（原航迹丢失时按上次
  发送快照 `TryReacquireTrack` 换弹）。
- 导弹端：`TryUpdateDatalinkTrack` 只消费 `GuidanceUpdate` 报文 + 记忆外推，
  直读后门全部拆除。pitbull 后制导通道（资源）释放但链路订阅仍在——丢锁可靠
  链路重新引导（延续上轮 CR#4 的决议）。
- Id 区段：本机终端 index 1、导弹终端 8..63；链路 EmitterId 用 32+index 区段
  与雷达发射机分开，本机 RWR 消隐雷达+链路两个自发射源（`BlankedEmitterId2`）。

## 2. 告警 P2

- **识别置信度**：接收余量 <18 dB 时 `WaveformConfidence` 线性打折；相关器
  维护 EMA，**低于 0.35 只知道"有辐射"不下波形结论**（远处微弱辐射源先显示
  Unknown，逼近后才"认出"是火控雷达——侦察玩法免费出现）。快照新增
  `IdentificationConfidence`。
- **波形库数据文件**：`StreamingAssets/EsmWaveformLibrary.json`（band/waveformId/
  className/name），代码内默认条目保底、文件逐条覆盖，加新威胁不改代码。
- **告警历史**：RWR 面板下方滚动 4 条升级事件（"12s 火控雷达→锁定"）；
  锁定/导弹级顶部闪烁对抗提示（QB 破锁 / 全力规避）。

## 3. 告警 P3：红外 MAW 通道

`MawSensorSystem`（Sensors）：全向红外告警，补 RF 的盲区（IR 弹全程静默、
ARH 中段静默）。判据：注册红外点源辐照度过阈 + **接近速度 ≥20 m/s**（自机
发射的导弹飞离被自然滤掉）。产出 `WarningObservation`（EmissionType.Infrared +
伪波形 0xFFF0）汇入同一接触环、同一相关器 → `InfraredPlume` 类 → MissileActive。

数据源：导弹注册红外点源，**燃烧段 58 dB / 燃尽滑翔段 28 dB**——滑翔段告警
中断是真实行为，远射滑翔+终端 pitbull 的战术自动成立。TODO(P4)：障碍物注册表
就绪后接 `AnalyticOcclusion` 视线判定。
