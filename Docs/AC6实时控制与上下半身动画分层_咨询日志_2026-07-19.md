# AC6 实时控制与上下半身动画分层咨询日志

日期：2026-07-19

## 1. 本次目标与提交边界

请基于工程现有的行为图、动作资产表和模块化机体动画系统，实现正式的玩家实时控制闭环。

本次需要解决的是“玩家输入 -> 物理运动/朝向 -> 行为图状态 -> 机体动作 -> 武器动作与特效”的正式链路，不是按时间播放动作的演示脚本，也不是直接把输入键硬编码到某个动画 ID。

需要实现并验证的操作如下：

- `W/S`：前进/后退。
- `A/D`：向左/向右平移，不负责左右转向。
- 鼠标水平移动：控制镜头和机体左右转向（Yaw）。
- 鼠标垂直移动：控制观察/瞄准俯仰（Pitch）。
- 不允许滚转（Roll）。
- `Space`：上升。
- 双击 `Space`：触发 Assault Boost（AB）。
- `Shift`：触发 Quick Boost（QB）。
- 鼠标左键：左手武器开火。
- 鼠标右键：右手武器开火。
- 进入场景时，镜头必须位于机体后方并朝向机体前方，不能正对机体脸部。

## 2. 现有上下半身处理方式

工程现有的 `MechBodyActionPlayer` 已经建立两层动画结构。正式控制实现必须沿用并完善这套结构。

### 2.1 第 0 层：全身基础动作层

第 0 层并不是只控制下半身，而是完整的全身基础姿态层，负责：

- 待机；
- 普通移动；
- 推进飞行；
- 上升；
- QB；
- AB；
- 着地、制动和其他全身状态。

该层使用双槽交叉淡入淡出，行为图切换状态时通过官方 TAE blend-in 时间完成过渡。

机体的实际位移和朝向必须由物理/运动控制系统负责。`Animator.applyRootMotion` 保持关闭，动画只表达姿态，不成为世界坐标运动的权威来源。

### 2.2 第 1 层：上半身遮罩动作层

第 1 层使用 `AvatarMask`，只覆盖上身、肩部、手臂以及需要参与瞄准和射击的骨骼链，负责：

- 抬臂；
- 瞄准；
- 保持瞄准；
- 左右手武器开火；
- 射击后恢复；
- 其他允许和移动同时发生的武器姿态。

上半身动作不能覆盖髋部、腿部和根节点，不能使第 0 层的移动、飞行或 QB 姿态停止。移动过程中抬臂瞄准和射击必须可见，这是正式验收条件。

非循环的上半身动作播放完毕后应自动淡出，返回基础全身动作提供的默认上身姿态；持续瞄准则应进入对应的保持状态，而不是每帧重新播放抬臂动作。

### 2.3 模块化机体同步

机体由头、核心、手臂、腿等独立部件组成，各部件保留自己的 `Animator` 和骨架。现有播放器采用同一个手动时钟推进所有部件，并在每次 PlayableGraph 求值后重新同步部件接口骨。

正式实现必须继续保证：

- 同一动作的四个机体部件使用相同时间；
- 全身层和上半身层的权重、淡入淡出时间一致；
- 换装后接口骨的位置、旋转和缩放不漂移；
- 武器自身的开火、装填或展开动画与机体上半身动作使用同一战斗事件和时间基准；
- 发射特效、弹丸生成和声音事件与武器动作的实际发射帧对齐。

## 3. 输入与运动语义

### 3.1 镜头和机体方向

鼠标控制第三人称镜头，同时给出机体期望朝向：

- 水平鼠标输入改变 Yaw，这才是机体左右转向的来源；
- 垂直鼠标输入改变 Pitch/瞄准方向；
- 任何输入组合都不能产生 Roll；
- 镜头初始位置在机体背后，镜头前方、机体视觉前方、物理推进前方和武器瞄准前方必须一致。

AC6 导出的模型局部视觉前方不一定等于 Unity 默认 `Transform.forward (+Z)`。实现时必须明确校准并分离：

- 逻辑/物理朝向；
- 模型视觉轴修正；
- 镜头朝向；
- 武器瞄准轴。

不能通过把摄像机放到机体正面来掩盖模型前向轴错误。

### 3.2 平移和推进

`W/S/A/D` 是相对机体水平朝向的平移/推进输入：

- `W` 沿机体前方推进；
- `S` 沿机体后方反推；
- `A/D` 沿机体左右轴平移；
- `A/D` 不改变 Yaw；
- `Space` 提供向上的推进输入。

运动系统应输出连续的期望推力或加速度，并保持项目既定的无空气阻力、具有惯性、转身不等于改变速度方向的太空机动原则。

### 3.3 QB 与 AB

- 按下 `Shift` 时，根据当前移动输入触发对应方向的 QB；没有方向输入时使用前向 QB。
- QB 的物理脉冲、全身动作、喷口特效和声音必须由同一次状态转换驱动。
- 双击 `Space` 触发 AB，必须使用按键边沿和明确的双击时间窗判定。
- 单击或按住 `Space` 只负责上升，不能误触发 AB。
- AB 进入后由行为图决定保持和退出条件，不应把 AB 简化成一次固定时长的平移。

## 4. 正式架构要求

请按以下职责边界实现：

1. 输入适配层只采集玩家输入，生成稳定的输入快照并填充 `MechGraphContext` 所需字段。
2. 物理/运动层消费输入快照，计算推力、速度和无滚转朝向，不直接选择动画。
3. 机体行为图解释器根据输入和机体状态选择第 0 层全身状态及动作。
4. 武器命令层或 `w0xx` 武器行为图选择第 1 层上半身动作和武器自身动作。
5. `MechBodyActionPlayer` 负责全身层与上半身层的并行播放、遮罩、混合和模块化骨架同步。
6. 武器系统负责弹药、射击事件、弹丸和特效，但不能绕过上半身/武器行为状态直接生成“看起来开火”的效果。

玩家、AI 和测试场景应共享同一个行为图入口，只由不同输入源填写上下文。不要为测试场景建立另一套按时间直接调用动作 ID 的控制逻辑。

输入到行为图条件目录的映射需要显式记录，至少包括移动方向、上升、QB、AB、左武器扳机、右武器扳机、接地状态、能量/冷却状态和武器可用状态。

## 5. 动画并行与裁决规则

默认规则是“移动和瞄准/射击并行”，而不是互斥：

- 待机 + 抬臂/瞄准/开火：允许；
- 普通移动 + 抬臂/瞄准/开火：允许；
- 推进飞行 + 抬臂/瞄准/开火：允许；
- 上升 + 抬臂/瞄准/开火：允许。

QB、AB 或硬直期间是否允许射击，应由官方行为图条件裁决。如果官方图明确禁止，才临时压制上半身武器层；不能用“正在播放全身动作”作为一刀切的禁火条件。

左右手武器应能独立响应。按下某一侧鼠标键时，只驱动对应侧武器命令；如果机体上半身动作需要双臂共同参与，则由武器类别和行为图决定，不能把左右键合并成同一个射击入口。

## 6. 必须通过的验收用例

### 6.1 镜头与朝向

- 场景启动时镜头位于机体后方，玩家看到机体背面。
- 只移动鼠标水平轴时，镜头和机体发生 Yaw 转向。
- 只按 `A/D` 时机体横移，朝向不变。
- 连续执行鼠标转向、斜向移动、上升和 QB 后，机体 Roll 仍为 0（允许极小浮点误差）。
- 按 `W` 时，机体实际位移方向与画面中的机头/胸部前方一致。

### 6.2 移动与战斗并行

- 按住 `W` 并按左键：机体继续前进，同时出现左手抬臂、瞄准和开火动作。
- 按住 `A` 或 `D` 并按右键：机体继续横移，同时出现右手武器动作。
- 飞行/上升过程中开火时，第 0 层动作保持，第 1 层上半身权重可见且对应动作 ID 正确。
- 武器模型动作、枪口特效和弹丸生成帧对齐。

### 6.3 QB 与 AB

- `W/A/S/D + Shift` 分别触发正确方向的 QB；无方向输入 `Shift` 触发前向 QB。
- QB 期间实际速度变化、机体动作和喷口特效方向一致。
- 按住 `Space` 能持续上升且不会进入 AB。
- 在双击时间窗内快速按两次 `Space` 才进入 AB。
- AB 进入、保持和退出均能在行为图转换历史中看到真实状态变化。

### 6.4 换装兼容

至少在 1010、2010、3010、Mixed A、Mixed B 五套 loadout 上重复上述关键用例，确认：

- 动作不会散架；
- 上半身遮罩骨命中数量有效；
- 接口骨同步误差接近 0；
- 武器和喷口随所属部件的挂点及动画移动；
- 换装不会改变输入语义或镜头前向。

## 7. 调试与交付要求

测试场景应显示或可查询以下真实运行状态，不能只输出预设阶段名称：

- 当前行为图状态 ID；
- 当前第 0 层全身动作 ID；
- 当前第 1 层上半身动作 ID 和层权重；
- 左右武器当前状态/动作；
- 最近行为图转换历史及触发条件；
- 当前逻辑朝向、模型轴修正和速度向量；
- 模块化接口骨的最大位置/旋转/缩放误差。

请交付：

1. 正式玩家输入适配器和运动控制器；
2. 与 `MechGraphContext`/行为图的接线；
3. 上半身武器行为图或等价的正式状态层接线；
4. 可直接打开并实时操作的 Unity 验证场景；
5. 覆盖上述验收项的自动或半自动验证报告；
6. 输入位、行为图条件、全身状态和武器状态的映射说明。
