# AC6 动作资产表与动作衔接剩余问题咨询日志

更新日期：2026-07-18

## 1. 结论先行

本轮已经建立可再生成的 AC6 动作资产表，也已将社区 `ac6-bhv-debug` 中的官方状态名与本机 `basenormal.bhv` 的状态索引、转换数量做了严格对齐。这解决了“这个动作 ID 在原版状态机中叫什么”的一部分问题，但还没有解决“游戏运行时应该如何进入、循环、打断、混合和退出这些动作”。

当前 Unity 演示中已有部分动作可以播放，但存在明显的语义选错、重复播放旧受击动作、入场/循环/退出衔接不正确、QB 与方向变体缺少物理 HKX、上半身架枪开火仍靠候选 ID 等问题。

因此当前成果的正确定位是：

- 动作资产盘点、原始文件可用性、BHV 官方语义映射已基本跑通。
- Unity 单动作预览和四部件 Clip 应用已跑通。
- 战斗动作状态机、动作序列和原版衔接规则尚未跑通。
- 当前的 `MechActionRegistry` 是 Clip 注册表，不是 AC6 行为状态机的等价实现。

## 3. 当前实际问题

### 3.1 演示并没有按语义播放 AB、QB 和开火序列

`AC6CombatShowcase` 中曾出现机体反复播放旧的受击/倒地动作，而不是应有的飞行、QB 或架枪动作。这说明“Clip 能播放”不等于“动作语义与状态衔接正确”。

![演示中错误重复旧动作](Images/ac6_action_showcase_wrong_sequence_2026-07-18.png)

资产表窗口可以把单个动作 Clip 应用到四个框架部件，这个能力仅能用于目检和标注，不能自动证明它在原版哪个状态、方向或武器类别下使用。

![动作资产表与 Unity 预览](Images/ac6_action_catalog_manual_preview_2026-07-18.png)

### 3.2 官方 QB 语义已找到，但同名物理 HKX 缺失

BHV 映射已经确认：

```text
a000_022400 = クイックブースト / Quick Boost
a000_122400 = 空中クイックブースト / 空中 Quick Boost
a000_120200 = ブースト飛行 / Boost Flight
```

`a000_120200` 有物理 HKX、Pose 和四部件 Clip，可用。

`a000_022400` 和 `a000_122400` 只有 TAE/BHV 逻辑映射，当前资源包没有同名物理 HKX，因此不能生成 Pose 和 Unity Clip。当前演示中的左右“QB”只能使用未确认候选动作，不能作为正式实现。

### 3.3 资产表没有变成运行时状态图

BHV 解析器已经可以产出：

- 状态索引。
- 官方日文状态名。
- Primary/auxiliary 动作槽及动作 ID。
- NextStates 和转换数量。

但 `AC6ActionLibraryBuilder` 当前只把通过门禁的单个 Clip 写进 `MechActionRegistry`。它没有把下列信息编译成 Unity 运行时数据：

- 状态到状态的转换拓扑。
- 转换条件和输入含义。
- 进入、循环、退出和恢复段。
- 方向、空中/地面、推进模式和武器类别参数。
- 不可打断区间、可取消窗口和动作完成条件。

因此当前程序实际上是由 `AC6CombatShowcaseController` 用定时器硬切动作 ID，而不是沿原版行为图执行。

### 3.4 混合时长仍是手写常量

`MechActionDefinition` 有 `blendInSeconds` 和 `blendOutSeconds`，但资产构建器对大多数动作仍写入 `0.15` 秒默认值，演示 Registry 则另外手写 `0.03` 到 `0.12` 秒。

TAE 中虽然存在 `Blend` 事件，但当前还没有把它的开始/结束时间、混合方向和参数转成 Registry 数据。这是动作跳变、提前恢复或长时间互相污染的直接风险。

### 3.5 上半身架枪和开火仍是候选 ID

当前演示使用：

```text
a200_030020 = 暂定“抬臂”
a200_030022 = 暂定“举枪保持”
a200_030030 = 暂定“开火/后坐”
```

这三个动作都有物理 HKX、Pose 和四部件 Clip，但资产表仍是 `NeedsReview + Heuristic`，并未通过武器行为图确认。

当前还缺少 `w010` 到 `w1000` 等武器 BHV 状态与 `a2xx/a3xx` 机体上半身动作、武器自身动作之间的确定关系。

### 3.6 运动轨迹、机体姿态和装备事件没有同一时间基准

当前演示仍会在 Controller 中程序化修改机体根节点位移和旋转，而骨骼 Clip、武器 HKX、枪口特效、导弹生成和推进特效由不同计时逻辑驱动。

尚未建立：

- 状态进入时间为零点的统一时间轴。
- 机体全身层、上半身层和武器自身动作的相位锁定。
- TAE 开火帧、后坐帧、特效帧和音效帧的统一派发。
- 不同重量、腿部类型和武器类别对动作状态的选择规则。

## 4. 需要咨询的具体问题

### 4.1 如何恢复官方 QB 的物理动作

1. `a000_022400` 和 `a000_122400` 是否实际引用另一个物理 HKX ID，而非同名文件？
2. 映射是否位于 compendium、TAE 的参数、BHV action index 或另一层动作别名表？
3. 当前 `c0000` 解包结果是否不完整，需要从哪个原版 archive/binder 重新提取？

### 4.2 如何把 BHV 状态图编译成可运行的中间表示

希望对方建议一个稳定的 IR，至少包含：

- State ID、官方名、Primary/auxiliary 动作槽。
- 进入、循环、退出动作序列。
- NextState、条件、优先级、打断规则和可取消窗口。
- 方向、地面/空中、武器类别、推进模式等参数。
- 全身、上半身和装备层的同步关系。

需要确认：是应该直接转译 BHV，还是先生成可审计的 JSON 行为图，再由 Unity Builder 编译为 ScriptableObject。

### 4.3 如何解读 BHV 转换条件

社区 debug JSON 有可读条件名，但本机原始 BHV 中的条件参数、分支优先级和引擎默认行为还没有完整转译。需要确认：

- 哪些条件只是输入，哪些是状态标志、地面检测或能量检查。
- 多个 NextState 同时满足时的裁决顺序。
- 动作未播完时是否可立即跳转。
- 不同版本（debug 元数据为 1.03，本机资源为当前/含 mod 构建）是否有状态索引漂移。

### 4.4 如何从 TAE 稳定提取衔接和事件时序

需要把现有 TAE dump 的事件参数转成以下可执行数据：

- Blend-in / blend-out 时长和曲线。
- 进入循环段和退出段的时机。
- 可打断、可转向、方向锁定和速度修改窗口。
- 枪口、弹丸、后坐、护盾、喷焰、音效和镜头事件时间。

希望对方说明 `Blend` 事件的字段含义，以及哪些事件可用于动作衔接，不要再使用统一 `0.15s` 经验值。

### 4.5 武器行为图如何和机体动作对齐

需要从 `w010` 到 `w1000` 等武器行为图中确定：

- 每类武器的待机、抬臂、矄准、开火、后坐、装填和恢复动作。
- 机体 `a2xx/a3xx` 上半身动作与装备自身 HKX 的对应关系。
- 移动中开火、空中开火、肩武器、近战和护盾是全身状态还是上半身叠加层。
- 导弹连射和自适应矄准时机如何对齐。

## 5. 不接受的权宜方案

- 不再用旧受击动作或外观相近的候选 Clip 冒充 QB、AB 或开火动作。
- 不用机体根节点平移冒充骨骼飞行姿态。
- 不为每个动作手写一组混合秒数并称为原版衔接。
- 不恢复 Blender 烘焙管线。
- 不只检查“Animator/PlayableGraph 正在播放”就判定动作正确。
- 不把 `OfficialMapped` 误解为“物理 HKX 存在且可直接播放”。

## 6. 最低验收标准

1. 资产表可重建，64 条玩家人工备注不丢失。
2. Idle -> AB 进入 -> Boost Flight 循环 -> AB 退出/制动能按已确认状态序列播放，无旧受击动作回退。
3. 地面和空中的左/右 QB 使用官方语义和真实物理 HKX，进入、主段和恢复姿态可见。
4. Idle/飞行 -> 抬臂 -> 矄准保持 -> 开火/后坐 -> 恢复按武器类别正确选择。
5. 全身移动层与上半身武器层不互相覆盖错误骨骼，换装 1010/2010/3010 四部件后仍成立。
6. 混合和打断参数来自 BHV/TAE 或有文档的映射，不是演示脚本常量。
7. 武器动作、枪口/导弹/护盾/喷焰特效与机体动作使用同一状态时间轴。
8. 自动验证需检查当前状态 ID、当前 Clip ID、关键骨姿态差、转换进度和事件时刻，不能只检查日志字符串。

## 7. 建议对方优先交付的最小闭环

不要立即转译全部 1288 个动作的所有条件。先用下列最小子图证明方法成立：

```text
Idle
  -> AB 进入
  -> Boost Flight 循环
  -> 左 QB / 右 QB
  -> 制动或恢复

Idle/Boost Flight
  -> 右手武器抬臂
  -> 矄准保持
  -> 开火/后坐
  -> 恢复
```

这个子图如果能从 BHV/TAE 数据自动生成，并在 Unity 中对 1010/2010/3010 换装都正确，再扩展到其余动作。
