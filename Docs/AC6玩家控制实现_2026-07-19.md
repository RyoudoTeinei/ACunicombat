按咨询日志 §4 的六层职责边界实现，全部编译通过。**没有任何按时间硬播动作的路径**：

## 2. 输入 → PadBits 映射（显式记录，§4 要求）

位定义与 `c0000_condition_catalog.json` 的 padBitNames 一致，常量在 `MechPadBits`：

| 输入 | PadBits |
| --- | --- |
| WASD 有输入 | bit0 移動入力 + bit5 走行 + (空中? bit4 飛行ブースト : bit1 地上ブースト) |
| WASD 无输入 | bit20 入力無し（回待机的必要条件，适配器求反算出） |
| Space 边沿 | bit6 ジャンプ |
| Space 按住 | bit17 ジャンプ押している + bit12 ↑移動；按住 ≥0.25s 追加 bit7 上昇開始ブースト |
| 双击 Space（0.3s 窗） | bit14 猛ダッシュ（AB 触发候选映射，待官方条件核对） |
| Shift 边沿 | bit2 クイックブースト発動 + bit3 ダッシュ回り込み |
| 左/右键按住 | bit13 エイム押した（+ 武器层独立处理左右） |

Context 其余：Grounded/Airborne 来自运动层；Energy/Lock/Guard 暂 false/0（接真系统时替换）。

## 3. 关键接线决策

1. **QB 三位一体**：物理脉冲挂在 `graphRunner.StateChanged` 上——进入名字含"クイックブースト"的状态才施加冲量，方向取当时移动输入（无输入=前向）。脉冲、全身动作、（特效）由同一次状态转换驱动（验收 6.3）。
2. **AB 由图裁决**：运动层的 AB 推力只在当前状态名含"ブーストダッシュ"时生效——进入/保持/退出全在转换历史里可见，不是定时平移。
3. **キャラ制御フラグ近似**：状态进入 0.15s 后视为 5 个取消窗全开（serialized）。正确数据源是当前动画的 TAE ChrActionFlag 窗口，编入 IR 后替换——已在字段 Tooltip 标注。
4. **上半身压制**：仅 QB 状态期间压制武器层（保守近似，serialized 可关）；移动/飞行/上升 + 抬臂/开火全部并行（§5 默认规则）。
5. 左手动作组 030x4x/030x5x 的具体 ID 是镜像组推断，serialized 待目检修正。


## 5. 与验收用例的对应

- 6.1 镜头/朝向：SnapBehindTarget 后置启动；Yaw 只来自鼠标；A/D 只平移（运动层不读 A/D 改 Yaw）；Roll 恒 0 是 `LogicalRotation=Euler(0,yaw,0)` 的结构性质，非数值巧合；模型轴偏差走 `modelForwardYawOffset` 显式字段。
- 6.2 移动+射击并行：武器层只调 `PlayUpperBody`，不触碰第 0 层；压制规则仅 QB。
- 6.3 QB/AB：见 §3.1/3.2；`Shift+WASD` 方向由脉冲方向实现，四方向 QB **动画**变体（004240-43 选边）待方向目检后在状态动画覆盖表里细化。
- 6.4 换装：本实现不新增任何骨骼引用，全部经 MechBodyActionPlayer——换装兼容性与现有系统等价。
- §7 调试：Rig 的 OnGUI 面板输出真实运行状态（状态 ID/动作 ID/转换历史），非预设阶段名。
